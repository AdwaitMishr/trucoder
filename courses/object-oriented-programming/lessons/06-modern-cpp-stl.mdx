      ### Smart pointers

      - **`std::unique_ptr<T>`** — *exclusive* ownership: the object is destroyed
        when the unique_ptr dies; the copy constructor is **deleted** — transfer
        ownership with `std::move`. Zero overhead vs a raw pointer.
      - **`std::shared_ptr<T>`** — *shared* ownership: a reference count; copying
        increments it, destruction decrements it, and the **last owner** destroys
        the object. Prefer `std::make_shared<T>(...)` — one allocation and
        exception-safe.
      - **`std::weak_ptr<T>`** — a *non-owning observer*: `lock()` returns a
        `shared_ptr` (or null if the object died), `expires()` checks liveness.
        It **breaks reference cycles** — two `shared_ptr`s pointing at each other
        would never free.
      - Never use `new` when a smart pointer (or `make_*`) can do the job.

      **Use case:** a factory returns `std::unique_ptr<Shape>`; a cache hands out
      `shared_ptr` to shared configs; a parent owns children via `unique_ptr` and
      children hold a `weak_ptr` back to the parent.

      ### RAII — Resource Acquisition Is Initialization

      - **Acquire the resource in the constructor, release it in the
        destructor** — the resource's lifetime equals the object's lifetime.
      - Applies to: heap memory, file handles, mutex locks, sockets, DB
        connections.
      - **Why it is exception-safe:** when an exception unwinds the stack,
        destructors of local objects run automatically — no manual
        try/catch/cleanup paths to forget.

      **Use case:** `std::lock_guard` locks the mutex at construction and unlocks
      it at destruction — even if the guarded body throws, the mutex is released.
  - type: markdown

      ### STL containers — one line each

      - **`std::vector`** — contiguous dynamic array; O(1) indexing and amortized
        push_back; cache-friendly; **the default choice**.
      - **`std::list`** — doubly-linked list; O(1) insert/erase *anywhere*,
        O(n) search; pick it only for frequent middle insertions with stable
        iterators.
      - **`std::deque`** — double-ended queue; O(1) push/pop at *both* ends, with
        indexed access.
      - **`std::map`** — sorted key→value (red-black tree); O(log n)
        lookup/insert; iteration in key order.
      - **`std::unordered_map`** — hash table; O(1) *average* lookup; keys
        unordered.
      - **`std::set`** — sorted *unique* keys; O(log n) membership tests.

      **Use case:** vector for a buffer you grow; unordered_map for a lookup
      table; set for "is this ID known?"; map when you also need sorted iteration.
  - type: markdown
    content: |
      ### STL algorithms & lambdas

      - `std::sort(begin, end)` — O(n log n); `std::find` — linear search;
        `std::binary_search` — logarithmic, but the range **must already be
        sorted**; `std::accumulate` — fold (sum, etc.).
      - **Lambda:** `[capture](params) -> ret { body }` — capture by value `[=]`
        or by reference `[&]`:

      ```cpp
      std::sort(v.begin(), v.end(),
                [](int a, int b) { return a > b; });   // descending
      ```

      **Use case:** sort a `std::vector<Employee>` by salary with a one-line
      lambda comparator instead of writing a named function.
  - type: markdown
    content: |
      ### Const correctness

      - **const member function** — `double area() const` — promises not to
        modify the object; required to call methods on const objects/references.
      - **const reference parameters** — read without copying:
        `void print(const std::string& s);`
      - **`mutable` member** — may be modified even in a const method (caches,
        counters, lock guards).
      - Pointer constness: `const int* p` (pointee is const) vs
        `int* const p` (pointer itself is const).

      **Use case:** mark every getter `const` and take parameters by `const&` —
      the compiler then enforces your non-mutation promises everywhere.

      ### Move semantics & std::move

      - `std::move(x)` is **just a cast to an rvalue reference** — it does *not*
        move anything and does *not* copy anything; it only makes `x` *eligible*
        for a move.
      - The **move constructor** then steals the resource (takes the pointer,
        nulls the source) instead of deep-copying; the source is left in a
        valid-but-unspecified state (usually empty).
      - **Why it matters:** returning / passing big objects no longer
        deep-copies — a big performance win.
      - Move-only types: `unique_ptr`, `std::thread`, `std::fstream`.

      **Use case:** `return std::move(local)`-style transfers (usually implicit
      via return value optimization) let a function hand a huge vector to its
      caller without copying it.
  - type: markdown
    content: |
      ### **Interview questions**

      :::tip
      **Interview question:** unique_ptr vs shared_ptr vs weak_ptr — when do you
      use which? — unique_ptr: exclusive ownership, movable but not copyable —
      the default choice. shared_ptr: shared ownership via a reference count —
      copies keep the object alive until the last owner dies. weak_ptr: a
      non-owning observer that `lock()`s — used to break reference cycles so
      shared_ptr graphs can actually be freed.
      :::

      :::tip
      **Interview question:** what does std::move actually do (and what does it
      NOT do)? — It performs a cast to an rvalue reference
      (`std::remove_reference_t<T>&&`); it does NOT move, copy, or delete
      anything. It merely makes the object *eligible* for a move — the actual
      resource transfer happens in the move constructor / move assignment that
      the compiler then selects.
      :::

      - `shared_ptr` costs a control block (refcount) per object — prefer
        `unique_ptr` unless ownership is genuinely shared.
      - After a move, always treat the source as empty — do not rely on its
        contents.
