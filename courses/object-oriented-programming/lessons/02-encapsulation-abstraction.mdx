      ### Encapsulation — data hiding

      - Bundle **data + the functions that operate on it** inside one class;
        keep the data `private`.
      - The outside world touches the object only through its **public
        interface** (methods, getters, setters).
      - Why it matters: **invariants**. A setter can validate, a public field
        cannot:

      ```cpp
      class Account {
      public:
          void deposit(double amt) { if (amt > 0) balance_ += amt; }
          double balance() const { return balance_; }
      private:
          double balance_ = 0.0;   // nobody can set this to -5
      };
      ```

      **Use case:** a library header exposes only the public API — the
      implementation (even the internal data layout) can change without
      breaking callers.

      ### Abstraction — hide complexity, expose the interface

      - **Encapsulation** hides *data and implementation details* behind an
        interface (the *how*).
      - **Abstraction** hides *complexity*, exposing only what the caller needs
        (the *what*).
      - **Abstract class** — has at least one **pure virtual** function
        (`virtual void draw() = 0;`); **cannot be instantiated**; derived
        classes must override the pure function to become concrete.
      - **Interface (C++)** — a class with *only* pure virtual functions and no
        data. Java's `interface` is a language keyword; in C++ it is a
        convention (an abstract class with no data members).

      **Use case:** a `Shape` interface exposing `area()` lets the rest of the
      app work with any shape without knowing which concrete class it is.
  - type: markdown
    content: |
      ### friend functions & friend classes

      - A `friend` can access the class's `private` members — a deliberate
        backdoor.
      - `friend std::ostream& operator<<(std::ostream&, const Account&);`
      - `friend class TestSuite;`
      - Justified for: `operator<<` / `operator>>`, unit tests, tightly
        coupled helper classes.
      - Friendship is **granted, not taken**: it is neither inherited nor
        transitive.

      ### struct vs class

      - In C++ the **only** difference is the default access: `struct` members
        default to `public`, `class` members to `private` (and the default
        inheritance access differs the same way).
      - Convention: `struct` for plain data holders, `class` for encapsulated
        types.

      :::tip
      **Interview question:** encapsulation vs abstraction — same thing? — No.
      Encapsulation hides *implementation details and data* behind an
      interface; abstraction hides *complexity*, exposing only the essential
      operations. Encapsulation is the mechanism (private state + public API);
      abstraction is the design goal (interface without implementation).
      :::
  - type: markdown
    content: |
      ### **Interview questions**

      :::tip
      **Interview question:** why do friend functions break encapsulation and
      when are they still used? — They reach into private state without going
      through the public API, so the class can no longer guarantee its
      invariants on every access. They are still used where the operation
      genuinely belongs outside the class: stream operators (`operator<<`) and
      test code that must inspect internals.
      :::

      - An abstract class cannot be instantiated; a concrete class can.
      - A C++ interface is just an abstract class with only pure virtual
        functions — no special keyword needed.
