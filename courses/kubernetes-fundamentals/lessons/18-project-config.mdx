  - type: markdown
    content: |
      Configuration leaves the image. For ShopAPI:

      ```yaml
      apiVersion: v1
      kind: ConfigMap
      metadata:
        name: shop-config
      data:
        APP_ENV: production
        LOG_LEVEL: info
      ```

      ```yaml
      apiVersion: v1
      kind: Secret
      metadata:
        name: shop-secrets
      type: Opaque
      data:
        REDIS_PASSWORD: c3VwZXJzZWNyZXQ=
        API_TOKEN: YWJjMTIz
      ```

      The Deployment wires both in with `envFrom`:

      ```yaml
            envFrom:
              - configMapRef:
                  name: shop-config
              - secretRef:
                  name: shop-secrets
      ```

      :::warning
      Secret values are base64 — readable by anyone with cluster access.
      The lesson here is *separation*, not encryption: the image never
      contains the secret, so a rebuild is never needed to rotate it.
      :::

      :::tip
      The order of keys in `data` is not meaningful — YAML maps are
      unordered. Sort the keys before joining so the answer is stable.
      :::

    hints:
      - "kind is at the top level; name under metadata; data keys under data."
      - "sort(data.keys()) then ','.join(...)."
      - "Only Secrets have a type field."
    solution: |
      import yaml

      def solve(manifest: str) -> list:
          d = yaml.safe_load(manifest)
          kind = d["kind"].lower()
          name = d["metadata"]["name"]
          keys = ",".join(sorted(d.get("data", {}).keys()))
          typ = d.get("type") if kind == "secret" else None
          return [kind, name, keys, typ]
