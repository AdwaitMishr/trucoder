solution: |
  def solve(selector: str, labels: str) -> bool:
      def to_map(s: str):
          return dict(pair.split("=") for pair in s.split(",") if pair)

      sel = to_map(selector)
      lab = to_map(labels)
      return all(k in lab and lab[k] == v for k, v in sel.items())

Every Pod, Deployment, and Service in Kubernetes carries **labels**: small
`key=value` pairs like `app=web` or `tier=db`. They are the address book of the
cluster — anything that needs to *find* a group of objects does it with a
**selector**.

## The rule

A selector matches an object when **every** pair in the selector exists in the
object's labels, with the same value. Extra labels on the object are fine.

```
selector:  app=web, env=prod
labels:    app=web, env=prod, tier=frontend   -> matches (subset)
labels:    app=web                             -> does NOT match (env missing)
labels:    app=api, env=prod                   -> does NOT match (value differs)
```

This is exactly why a Service can "see" the right Pods: the Service's selector
picks out the Pods whose labels contain it.

:::example
selector `app=web` against labels `app=web,tier=frontend`:
`app` exists in the labels and equals `web` → **matches**.
:::

## The algorithm

1. Split each string on `,` into pairs.
2. Split each pair on `=` into key and value.
3. For every selector pair, the labels map must contain that key **with that
   value**.

:::warning
Do not check only the key. `app=web` must not match a pod labeled
`app=api` — the value has to be equal too.
:::

:::tip
An empty selector matches everything. Kubernetes uses this for "all pods in
this namespace" — an empty `matchLabels` selects the whole set, because there
are no requirements to fail.
:::
