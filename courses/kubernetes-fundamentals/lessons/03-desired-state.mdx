A Deployment in Kubernetes declares *what you want*: `replicas: 3`. It never
tells the cluster *how* to get there. That is the controller's job.

## The loop

Every controller runs the same three-step loop, forever:

1. **Observe** — how many ready pods exist right now?
2. **Compare** — does the current state match the desired state?
3. **Act** — create or terminate pods to close the gap.

This is **reconciliation**: the cluster constantly nudges reality toward the
manifest. When a pod crashes, the loop observes `ready = 2` while `desired = 3`,
and acts — creating one replacement.

:::example
desired = 3, ready = 2 → the loop creates **1** pod.
desired = 2, ready = 3 → the loop terminates **1** pod (scale down).
desired = 5, ready = 5 → **0** changes. The world matches the manifest.
:::

## The math

The gap is always `desired − ready`:

- positive → create that many pods,
- negative → terminate that many pods,
- zero → do nothing.

:::warning
The delta is **signed**. A Deployment scaled down from 5 to 3 with 5 pods still
running needs `3 − 5 = −2`: terminate two. Returning only the absolute
difference loses the direction of the action.
:::

:::tip
This loop is why Kubernetes "heals itself". Nothing watches for failures
specifically — the controller just keeps comparing current to desired, and a
missing pod is simply a gap to close.
:::
