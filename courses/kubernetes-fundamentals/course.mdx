# How to use this course

Kubernetes sounds like a wall of acronyms: Pods, Deployments, Services, HPAs.
Strip the jargon away and it is a small set of *ideas* — and every idea is
either a command you run or a number you reason about.

Most lessons here are **reading**: the concept, the `kubectl` commands, and the
YAML that makes it real. Read them like the docs you wish existed — then run
the commands on a cluster (or `kind`/`minikube` on your laptop) to make them
stick. Two early lessons are **coding exercises**, kept only where the math is
genuinely worth practicing: resource units and HPA math.

The second half of the course is a **capstone project**: ShopAPI, a real
three-tier app. Five graded lessons make you *prove* you can read and validate
production manifests (Deployment, Service, ConfigMap/Secret, Ingress/HPA,
PVC wiring) — including catching broken ones. The final lesson runs the whole
stack for real on a `kind` cluster and gives you the interview answers that
turn the project into a resume line.

Work through the lessons **in order**:

1. Cluster architecture — who is who, and how `kubectl` talks to it.
2. Pods — the smallest unit Kubernetes schedules.
3. Resource units — what `128Mi` actually means (code).
4. Deployments — desired state, replicas, rolling updates.
5. Services — stable names, selectors, DNS.
6. Probes — readiness vs liveness, and the timing math.
7. HPA math — the autoscaler's formula (code).
8. Taints & tolerations — who is allowed on which node.
9. Namespaces — folders, budgets, and the DNS name.
10. ConfigMaps & Secrets — config that changes without a rebuild.
11. Storage — PVs, PVCs, and when state survives.
12. Beyond Deployments — Jobs, CronJobs, DaemonSets, StatefulSets.
13. Ingress — L7 routing into the cluster.
14. RBAC & security — who, how, and what can talk to what.
15. Observability & Helm — logs, metrics, and packaging.
16. **Project** — the Deployment manifest (graded).
17. **Project** — the Service (graded).
18. **Project** — ConfigMap & Secret (graded).
19. **Project** — Ingress & HPA (graded).
20. **Project** — storage and full wiring (graded).
21. **Project** — run ShopAPI on kind, for real.

By the end you will read a Deployment manifest and see *why* every number is
there — and you will have deployed a complete, production-shaped app on a
real cluster, with the vocabulary to defend it in an interview.

|---|--------|------------------------|------|
| 1 | Cluster architecture | control plane vs nodes, `kubectl` | reading |

| 10 | ConfigMaps & Secrets | config without rebuilds | reading |
| 11 | Storage | PVs, PVCs, access modes | reading |

The project uses a consistent manifest set — every lesson references the same
ShopAPI. Do the graded lessons in order; the final walkthrough assumes you
know all five manifests.
