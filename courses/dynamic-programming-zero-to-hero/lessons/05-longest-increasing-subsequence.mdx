solution: |
  def solve(nums: list[int]) -> int:
      n = len(nums)
      dp = [1] * n
      for i in range(n):
          for j in range(i):
              if nums[j] < nums[i]:
                  dp[i] = max(dp[i], dp[j] + 1)
      return max(dp) if n else 0

Here the state is not a single number but a *position*. The answer at index `i`
depends on every smaller index before it. This is the classic O(n²) DP, and the
birth of the "every previous state is a candidate" pattern.

## Define the state

Let `dp[i]` = length of the longest increasing subsequence that **ends at index
`i`**. That phrasing matters: it forces `nums[i]` to be the last element, which
lets you extend from earlier subsequences.

## The recurrence

For each `i`, look at every `j < i`. If `nums[j] < nums[i]`, you can extend the
subsequence ending at `j` with `nums[i]`, giving length `dp[j] + 1`. So:

```
dp[i] = 1 + max(dp[j])  over all j < i where nums[j] < nums[i]
```

and at least `1` (the element alone).

## Reading the answer

The longest increasing subsequence might end anywhere, so the answer is
`max(dp)`, **not** `dp[n-1]`.

:::warning
This is a classic bug: assuming the best subsequence ends at the last index. It
does not — a later, smaller element can have a short subsequence ending there
while an earlier element hosts the longest one. The answer is the max over the
whole table.
:::

## Complexity

You scan all previous `j` for each `i`, so this is O(n²) time and O(n) space.
There is a faster O(n log n) method using a patience-sorting trick, but the O(n²)
DP is the one that builds intuition — learn it first.

:::tip
Reach for the "state = ending index" idea whenever a problem is about
subsequences. Ask: *if the sequence must end here, what can the second-to-last
element be?*
:::
