solution: |
  def solve(coins: list[int], amount: int) -> int:
      INF = float('inf')
      dp = [INF] * (amount + 1)
      dp[0] = 0
      for a in range(1, amount + 1):
          for c in coins:
              if a - c >= 0:
                  dp[a] = min(dp[a], dp[a - c] + 1)
      return -1 if dp[amount] == INF else dp[amount]

This is the first problem where *greedy* feels tempting and is wrong. The DP
insight here is to define the state as the **remaining amount**, and to try every
coin as the "last coin used".

## Define the state

Let `dp[a]` = fewest coins to make amount `a`. The answer is `dp[amount]`. This
turns one big question into a chain of smaller questions indexed by the amount.

## The recurrence

To make amount `a`, your last coin is some `c` in `coins`. Before using it, you
needed to make `a - c`. So:

```
dp[a] = 1 + min(dp[a - c])  for every coin c where c <= a
```

If no coin can make `a`, leave it as "impossible".

## Greedy fails — an example

:::example
With coins `[1, 3, 4]` and amount `6`, greedy takes `4` then `1` then `1` — three
coins. But `3 + 3` is only two coins. Greedy only works for canonical coin
systems. DP explores all combinations and finds the true minimum.
:::

## Implementation details

Initialize `dp` with a large number (call it "infinity") meaning *impossible*,
and set `dp[0] = 0`. Iterate amounts from `1` to `amount`. If the final
`dp[amount]` is still the large number, return `-1`.

:::warning
Use a big-but-safe sentinel for infinity — something like `Integer.MAX_VALUE / 2`
in Java, or a large float in Python — so that adding `1` to it never overflows
and wrecks your comparisons.
:::
