## How to use this course

Work through the lessons **in order**. Each one builds on the previous. Read the
lesson, attempt the problem, and only reveal hints when you are genuinely stuck.

Two buttons matter:

- **Run** — checks your code against the *visible* examples. Use it while coding.
- **Submit** — checks the *hidden* tests too, and marks the lesson solved when
  everything passes.

Aim to solve each lesson in **Java** — it is the closest to what interview
platforms expect. JavaScript and Python are there if you want to reinforce the
idea in another language.

## The roadmap

The eight lessons form one coherent arc:

| # | Lesson | The idea it introduces |
|---|---|---|
| 1 | Fibonacci | overlapping subproblems, memoization, tabulation |
| 2 | Climbing Stairs | the same recurrence as a "ways to arrive" count |
| 3 | House Robber | the choose / skip decision |
| 4 | Coin Change | minimization with an impossible sentinel |
| 5 | Longest Increasing Subsequence | state = ending index; answer = max(dp) |
| 6 | 0/1 Knapsack | the two-dimensional state |
| 7 | Longest Common Subsequence | two-string DP |
| 8 | Edit Distance | two-string DP with a cost per operation |

By the end, you will be able to look at a problem and ask the right two
questions: *"Can I break it into smaller versions of itself?"* and *"Do those
smaller versions repeat?"* When both answers are yes, you have a DP problem.
