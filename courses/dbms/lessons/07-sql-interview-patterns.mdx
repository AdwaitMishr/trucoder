      ## Seven patterns that keep showing up

      LeetCode's SQL 50 and most interview screens reuse the same handful of
      archetypes. Learn the pattern, not the problem: recognize the shape of
      the question, reach for the matching SQL, and state the result.

      Base data used by several examples in this lesson:

      ```sql
      CREATE TABLE Employee (emp_id INT, name VARCHAR(20), dept_id INT, salary INT);
      INSERT INTO Employee VALUES
        (1, 'Alice', 10, 60000),
        (2, 'Bob',   20, 50000),
        (3, 'Carol', 10, 80000),
        (4, 'Dave',  30, 40000),
        (5, 'Eve',   20, 50000),
        (6, 'Finn',  20, 45000),
        (7, 'Gina',  10, 55000),
        (8, 'Hank',  10, 35000);
      ```

      **Use case:** every pattern below is a question you can be asked verbatim
      ("second highest salary", "customers who never ordered", "top 3 per
      department"). Knowing the pattern tells you the query in one breath.

      ## Pattern 1 — second highest value

      **Question:** "Find the second highest distinct salary."

      Two idiomatic answers; the first is the classic LeetCode 176 solution:

      ```sql
      -- Option A: sort, skip the first
      SELECT DISTINCT salary
      FROM Employee
      ORDER BY salary DESC
      LIMIT 1 OFFSET 1;
      -- distinct salaries DESC: 80000, 60000, 55000, 50000, 45000, 40000, 35000
      -- OFFSET 1 skips 80000 → 1 row: 60000

      -- Option B: strictly below the max
      SELECT MAX(salary)
      FROM Employee
      WHERE salary < (SELECT MAX(salary) FROM Employee);
      -- → 60000
      ```

      **NULL when absent:** if the table has fewer than 2 distinct values,
      Option A returns **no rows** and Option B returns **NULL** — an aggregate
      over an empty set is NULL, never 0. Interviews love this corner case;
      the coding exercise at the end simulates it with `-1`.

      ## Pattern 2 — top-N per group

      **Question:** "List the top 3 earners in each department."

      Window function + outer filter. `PARTITION BY` makes the ranking restart
      per group; `DENSE_RANK` keeps ties inside the window:

      ```sql
      SELECT dept_id, name, salary
      FROM (
        SELECT dept_id, name, salary,
               DENSE_RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rk
        FROM Employee
      ) t
      WHERE rk <= 3;
      -- dept 10: Carol 80000 (1), Alice 60000 (2), Gina 55000 (3)  → 3 rows
      --          Hank 35000 (4) is cut
      -- dept 20: Bob 50000 (1), Eve 50000 (1), Finn 45000 (2)      → 3 rows
      -- dept 30: Dave 40000 (1)                                    → 1 row
      -- → 7 rows
      ```

      Note the tie: Bob and Eve share rank 1, so Finn still lands at rank 2
      and all three make the top 3. With `RANK()` the tie would skip rank 2
      and the answer would differ — state which one you mean.

      ## Pattern 3 — consecutive rows / sequences

      **Question:** "Find numbers that appear three times in a row"
      (LeetCode 180). Two tools: self-join on adjacent ids, or `LAG`.

      ```sql
      CREATE TABLE Logs (id INT PRIMARY KEY, num INT);
      INSERT INTO Logs VALUES (1, 1), (2, 1), (3, 1), (4, 2), (5, 1), (6, 2), (7, 2);

      -- Self-join: id must be consecutive AND the value equal
      SELECT DISTINCT l1.num AS ConsecutiveNums
      FROM Logs l1
      JOIN Logs l2 ON l1.id = l2.id - 1
      JOIN Logs l3 ON l1.id = l3.id - 2
      WHERE l1.num = l2.num AND l2.num = l3.num;
      -- 1 at ids 1,2,3 qualifies → 1
      -- 2 appears at 6,7 only (two in a row) → excluded
      -- → 1 row: 1

      -- LAG version: peek the two previous rows
      SELECT DISTINCT num AS ConsecutiveNums
      FROM (
        SELECT num,
               LAG(num)   OVER (ORDER BY id) AS prev1,
               LAG(num, 2) OVER (ORDER BY id) AS prev2
        FROM Logs
      ) t
      WHERE num = prev1 AND num = prev2;
      -- same answer: 1
      ```

      Self-joins need a gap-free sequence to join on; `LAG`/`LEAD` only need
      an ordering — prefer them when ids can be sparse.

      ## Pattern 4 — anti-join (rows with NO match)

      **Question:** "Find customers who never ordered" (LeetCode 183).

      `LEFT JOIN` keeps every left-side row; the rows with no partner get
      NULLs on the right, so `WHERE right_col IS NULL` isolates them:

      ```sql
      CREATE TABLE Customers (id INT PRIMARY KEY, name VARCHAR(20));
      CREATE TABLE Orders (id INT PRIMARY KEY, customerId INT);
      INSERT INTO Customers VALUES (1, 'Joe'), (2, 'Henry'), (3, 'Sam'), (4, 'Max');
      INSERT INTO Orders VALUES (1, 3), (2, 1);   -- Sam and Joe ordered

      SELECT c.name AS Customers
      FROM Customers c
      LEFT JOIN Orders o ON c.id = o.customerId
      WHERE o.id IS NULL;
      -- Joe: matched → dropped; Sam: matched → dropped
      -- Henry, Max: no order → kept with NULL o.id
      -- → 2 rows: Henry, Max
      ```

      The `NOT IN` alternative silently breaks when the subquery contains a
      NULL — another reason the anti-join is the safe default (see Pattern 5).

      ## Pattern 5 — NULL traps

      **Question:** "Find customers NOT referred by customer 2"
      (LeetCode 584). The naive filter drops the NULLs:

      ```sql
      CREATE TABLE Customer (id INT PRIMARY KEY, name VARCHAR(20), referee_id INT);
      INSERT INTO Customer VALUES
        (1, 'Will', NULL), (2, 'Jane', NULL), (3, 'Alex', 2),
        (4, 'Bill', NULL), (5, 'Zack', 1),   (6, 'Mark', 2);

      -- WRONG: NULL != 2 evaluates to UNKNOWN, not true
      SELECT name FROM Customer WHERE referee_id != 2;
      -- only Zack (referee 1) → 1 row, but Will/Jane/Bill have no referee
      -- and should be included

      -- RIGHT: ask for NULLs explicitly
      SELECT name FROM Customer WHERE referee_id != 2 OR referee_id IS NULL;
      -- Will, Jane, Bill, Zack → 4 rows

      -- COUNT(*) counts rows; COUNT(col) skips NULLs
      SELECT COUNT(*), COUNT(referee_id) FROM Customer;
      -- 6, 4
      ```

      `COALESCE(referee_id, -1)` gives a display default; the fix for the
      query is the explicit `IS NULL`. Remember: three-valued logic —
      `NULL = NULL` is UNKNOWN, not true.

      ## Pattern 6 — running totals

      **Question:** "Show each day's sales plus the running total so far."

      `SUM() OVER (ORDER BY ...)` accumulates row by row without collapsing
      the result set:

      ```sql
      CREATE TABLE Sales (day DATE PRIMARY KEY, amount INT);
      INSERT INTO Sales VALUES
        ('2024-01-01', 100), ('2024-01-02', 150), ('2024-01-03', 200);

      SELECT day, amount,
             SUM(amount) OVER (ORDER BY day) AS running_total
      FROM Sales;
      -- 01-01: 100 → 100
      -- 01-02: 150 → 250
      -- 01-03: 200 → 450
      ```

      `SUM() OVER ()` (no ORDER BY) puts the grand total on every row instead;
      add `PARTITION BY` to restart the running total per group.

      ## Pattern 7 — division ("all of X")

      **Question:** "Students who took EVERY course" — relational division.

      Compare each group's distinct count against the total:

      ```sql
      CREATE TABLE Takes (student VARCHAR(20), course VARCHAR(20));
      INSERT INTO Takes VALUES
        ('Ana', 'DBMS'), ('Ana', 'OS'), ('Ana', 'Networks'),
        ('Ben', 'DBMS'), ('Ben', 'OS'),
        ('Cid', 'DBMS'), ('Cid', 'OS'), ('Cid', 'Networks');
      -- courses on offer: DBMS, OS, Networks → 3

      SELECT student
      FROM Takes
      GROUP BY student
      HAVING COUNT(DISTINCT course) = 3;
      -- Ana: 3 ✓   Ben: 2 ✗   Cid: 3 ✓
      -- → 2 rows: Ana, Cid
      ```

      `COUNT(DISTINCT ...)` (not `COUNT(*)`) makes the test immune to
      duplicate enrollment rows; the right-hand constant is the total number
      of things to be in "all of".

      ## Interview questions

      :::tip
      **Interview question:** What does the second-highest query return when
      all salaries are equal? — `LIMIT 1 OFFSET 1` returns no rows;
      `SELECT MAX(salary) WHERE salary < (SELECT MAX(salary) ...)` returns
      NULL. An aggregate over an empty set is NULL, not 0 — and any
      interview follow-up about "what if there is no second-highest" is
      testing exactly this.
      :::

      :::tip
      **Interview question:** Why does `WHERE referee_id != 2` miss the
      customers with no referee? — SQL uses three-valued logic: `NULL != 2`
      is UNKNOWN, and WHERE keeps only rows where the condition is TRUE.
      NULLs vanish unless you write `OR referee_id IS NULL` (or use
      `COALESCE`). Same reason `COUNT(col)` < `COUNT(*)` when the column has
      NULLs.
      :::

      :::tip
      **Interview question:** RANK or DENSE_RANK for top-N per group? —
      DENSE_RANK: ties share a rank and no ranks are skipped (50000, 50000,
      45000 → 1, 1, 2), so a top-3 window keeps both tied employees and the
      next one. RANK skips to 1, 1, 3 — the third slot is a different person.
      Say which you want and why.
      :::
