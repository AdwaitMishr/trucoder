      # Project 1: Cart Domain

      **Context.** You are building the storefront backend of a small
      e-commerce site ("Shop"). This lesson is the first of a four-lesson
      project arc: cart domain → checkout pipeline → rate limiter → Docker
      assembly. By the end of lesson 13 you will have shipped the whole API.
      Today you build the **cart domain**: the real service module that the
      `CartController` runs on every "add to cart" request.

      **What you are building this step.** A real module —
      `services/cartService.js` — with three exported functions:

      - `addItem(cart, productId, qty, unitPrice)` — the heart of the cart:
        *an item already in the cart is merged, not duplicated*. Two requests
        for the same product must produce one cart line with summed quantity —
        never two lines.
      - `lineTotal(item)` — the derived line total (`qty × unitPrice`), so
        the controller never does arithmetic.
      - `cartTotal(cart)` — the sum of line totals; the checkout pipeline of
        lesson 11 charges exactly this number.

      This is **real backend practice, done test-first**: the module ships
      with a full, visible `node:test` suite (`tests/cart.test.js`), and the
      module is *done* when the suite is green. Nothing is hidden — every
      test case is printed in this lesson.

      **Acceptance criteria**

      - `POST /api/cart/items` with `{productId, qty, unitPrice}` adds or
        merges a line.
      - `GET /api/cart` returns the cart rows, each with a derived line total.
      - `DELETE /api/cart/items/:id` removes a line.
      - Merging an existing line keeps its **original unit price** (the price
        snapshot from when it was first added) — the incoming price is
        ignored.
      - The merge + line-total logic is a pure function — no HTTP, no SQL —
        so it is trivially unit-testable. That purity is exactly what the
        test suite checks.

      **How this lesson is graded.** The platform grades the module exercise
      below — a visible node:test suite runs your `services/cartService.js`
      in a sandbox. The same suite is the real deliverable in the shipped
      project: run `npm test` and make `tests/cart.test.js` green.

      ## Module contract — `services/cartService.js`

      The project and this lesson agree **exactly** on this surface.
      Implement it to the letter — the test suite depends on it.

      **Exports**

      | Export | Signature | Behavior |
      |--------|-----------|----------|
      | `addItem` | `addItem(cart, productId, qty, unitPrice)` | Returns the updated cart. If a line with `productId` exists, add `qty` to its quantity and **keep the original `unitPrice`**; otherwise append `{productId, qty, unitPrice}`. |
      | `lineTotal` | `lineTotal(item)` | `item.qty * item.unitPrice` |
      | `cartTotal` | `cartTotal(cart)` | Sum of `lineTotal` over all items; `0` for an empty cart. |

      **Item shape.** A cart is an array of items, each an object
      `{ productId, qty, unitPrice }` — prices in integer cents, never
      floats. `addItem` returns the updated cart; the input cart may be
      treated as read-only.

      :::example
      Cart is `[{ productId: 1, qty: 2, unitPrice: 100 }]`. You add product 1,
      qty 3, at 100¢. The id exists, so qty merges: `2 + 3 = 5`. The updated
      cart is `[{ productId: 1, qty: 5, unitPrice: 100 }]`, and
      `cartTotal` = `5 × 100 = 500`.
      :::

      :::example
      Cart is
      `[{ productId: 1, qty: 1, unitPrice: 50 }, { productId: 2, qty: 2, unitPrice: 25 }]`.
      You add a *new* product 3, qty 1, at 10¢. No line has id 3, so it is
      appended. `cartTotal` = `50 + 50 + 10 = 110`.
      :::

      **Edge cases you must handle** (all covered by the visible suite): an
      empty cart (append into `[]`); merging keeps the **original** unit
      price even when the incoming price differs; repeated adds of the same
      product keep merging; large quantities and prices (line totals reach
      tens of billions — well inside JavaScript's exact integer range up to
      `2^53`, so plain `Number` arithmetic is exact).

      const { test } = require('node:test');
      const assert = require('node:assert/strict');
      const cartService = require('../services/cartService');

      test('lineTotal = qty x unitPrice', () => {
        assert.equal(cartService.lineTotal({ productId: 1, qty: 2, unitPrice: 100 }), 200);
        assert.equal(cartService.lineTotal({ productId: 7, qty: 1, unitPrice: 999 }), 999);
      });

      test('cartTotal sums every line total', () => {
        const cart = [
          { productId: 1, qty: 2, unitPrice: 100 }, // 200
          { productId: 2, qty: 3, unitPrice: 50 },  // 150
          { productId: 3, qty: 1, unitPrice: 25 },  // 25
        ];
        assert.equal(cartService.cartTotal(cart), 375);
        assert.equal(cartService.cartTotal([]), 0);
      });

      test('addItem appends a new product line', () => {
        const cart = [{ productId: 1, qty: 1, unitPrice: 50 }];
        const updated = cartService.addItem(cart, 2, 4, 10);
        assert.deepEqual(updated, [
          { productId: 1, qty: 1, unitPrice: 50 },
          { productId: 2, qty: 4, unitPrice: 10 },
        ]);
        assert.equal(cartService.cartTotal(updated), 90); // 50 + 40
      });

      test('addItem merges into an existing line and keeps the ORIGINAL unit price', () => {
        const cart = [{ productId: 1, qty: 2, unitPrice: 100 }];
        // The catalog now prices product 1 at 250 — the merge must IGNORE that
        // and keep the 100 snapshot from when the line was first added.
        const updated = cartService.addItem(cart, 1, 3, 250);
        assert.deepEqual(updated, [{ productId: 1, qty: 5, unitPrice: 100 }]);
        assert.equal(cartService.cartTotal(updated), 500); // 5 x 100, not 5 x 250
      });

      test('addItem works on an empty cart', () => {
        const updated = cartService.addItem([], 9, 2, 500);
        assert.deepEqual(updated, [{ productId: 9, qty: 2, unitPrice: 500 }]);
      });

      test('addItem keeps big numbers exact (full integer precision)', () => {
        const updated = cartService.addItem(
          [{ productId: 1, qty: 1_000_000, unitPrice: 9999 }],
          1,
          1_000_000,
          9999
        );
        assert.deepEqual(updated, [{ productId: 1, qty: 2_000_000, unitPrice: 9999 }]);
        assert.equal(cartService.cartTotal(updated), 2_000_000 * 9999); // 19,998,000,000
      });

      test('addItem merges across repeated adds of the same product', () => {
        let cart = [];
        cart = cartService.addItem(cart, 1, 1, 100);
        cart = cartService.addItem(cart, 1, 2, 100);
        cart = cartService.addItem(cart, 1, 3, 100);
        assert.deepEqual(cart, [{ productId: 1, qty: 6, unitPrice: 100 }]);
      });

      ## Wiring — where the cart service plugs in

      The request flows **route → controller → service → repository**. The
      route and controller are GIVEN (they ship with the project); your
      module is the pure service they delegate to.

      ```js
      // routes/cart.js — mounted at /api/cart (behind requireAuth + rate limiter)
      const router = require('express').Router();
      const cartController = require('../controllers/cartController');

      router.post('/items', cartController.addItem);          // POST /api/cart/items
      router.get('/', cartController.getCart);                // GET  /api/cart
      router.delete('/items/:id', cartController.removeItem); // DELETE /api/cart/items/:id

      module.exports = router;
      ```

      ```js
      // controllers/cartController.js — thin: parse, delegate, respond
      const cartRepository = require('../repositories/cartRepository');
      const cartService = require('../services/cartService'); // ← your module

      async function addItem(req, res, next) {
        try {
          const { productId, qty, unitPrice } = req.body; // validated upstream
          const rows = await cartRepository.getItems(req.user.id);
          const cart = rows.map((r) => ({
            productId: r.product_id,
            qty: r.qty,
            unitPrice: r.unit_price,
          }));
          const updated = cartService.addItem(cart, productId, qty, unitPrice);
          await cartRepository.upsertItems(req.user.id, updated);
          res.status(201).json({
            data: { items: updated, total: cartService.cartTotal(updated) },
          });
        } catch (err) { next(err); }
      }
      ```

      The controller is deliberately dumb: it reads `req.body`, maps database
      rows to cart items, calls your pure functions, and responds. The
      business rule "merge, don't duplicate" lives in `cartService`, next to
      the repository — testable in milliseconds, with no HTTP server in
      sight.

      ## Interview questions

      :::tip
      **Interview question:** Why is the cart's add-item rule a pure function
      of `(cart, productId, qty, unitPrice)` rather than living inline in the
      route handler? Because a pure function has no hidden state — no HTTP
      request, no database connection — so you can test every branch (merge,
      append, empty cart, big numbers) in milliseconds without spinning up
      the app. That is the whole point of the service layer: business rules
      that are fast to verify and safe to reuse.
      :::

      :::tip
      **Interview question:** Why merge quantities instead of always
      appending a new line per request? Because a cart is a *set of products
      with quantities*, not a log of clicks. Two lines for the same product
      make checkout ambiguous (which line wins?), double the storage, and
      confuse the shopper. Merging also preserves the price snapshot — the
      price at which the item was first added — which is what you actually
      charge at checkout.
      :::

      **Use case.** Every "add to cart" button on the storefront fans out to
      this one module. A user who taps *Add* twice for the same product gets
      qty 2 on one line — and the cart total (`Σ qty × unitPrice`) stays
      correct because the line total is derived, never stored separately.

      // services/cartService.js — lesson 10: the pure cart domain
      // A cart is an array of items { productId, qty, unitPrice }.
      // Pure functions only: no HTTP, no SQL — trivially unit-testable.

      function lineTotal(item) {
        return item.qty * item.unitPrice;
      }

      function cartTotal(cart) {
        return cart.reduce((sum, item) => sum + lineTotal(item), 0);
      }

      function addItem(cart, productId, qty, unitPrice) {
        const existing = cart.find((item) => item.productId === productId);
        if (existing) {
          // Merge: sum the quantities, KEEP the original unitPrice snapshot.
          return cart.map((item) =>
            item.productId === productId ? { ...item, qty: item.qty + qty } : item
          );
        }
        // Append a new line.
        return [...cart, { productId, qty, unitPrice }];
      }

      module.exports = { addItem, lineTotal, cartTotal };
