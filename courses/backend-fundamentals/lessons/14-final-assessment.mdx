      ## Revision tips

      - **Backend basics** — memorize the request lifecycle order (DNS →
        firewall → reverse proxy → app server); it is the number-one
        "walk me through a request" interview question.
      - **HTTP** — know the idempotency table (GET/PUT/DELETE yes, POST no)
        and the 401 vs 403 distinction cold.
      - **Routing** — path params identify *which* resource; query strings
        shape *how* it is returned.
      - **Controllers & middleware** — the chain order (logger → auth → rate
        limit → router → error handler last) and why controllers stay thin.
      - **Validation** — server-side validation is non-negotiable; DTOs stop
        mass assignment.
      - **Auth** — sessions = instant revocation, JWT = scale; bcrypt is slow
        on purpose; HttpOnly/Secure/SameSite on every cookie.
      - **API design** — plural nouns, no verbs, nest only real ownership,
        version URLs, Idempotency-Key on payments.
      - **PostgreSQL** — transactions give checkout atomicity; pools reuse
        connections; money is numeric, never float.
      - **Caching** — cache-aside: update the DB, then invalidate the key;
        TTL bounds staleness.
      - **The project arc** — re-run the module exercises by hand:
        merging keeps the original price, checkout checks stock before money,
        and the sliding window is inclusive on both edges.
      - **Docker** — non-root USER, healthchecks gate startup, and service
        names are DNS names on the Compose network.
      - Re-attempt any question you missed, then walk the curl walkthrough
        from lesson 13 (register → login → add to cart → checkout → 429) as
        the final end-to-end review.
