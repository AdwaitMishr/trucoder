      # Distinct Colors — subtree color counts

      A rooted tree of `n` nodes, each painted some color. For **every** node we
      must report how many *different* colors appear in its subtree. This is a
      query over tree "subtree ranges", and there are two classic toolboxes for
      it — the **Euler-tour + Mo's algorithm** (offline range counting) and
      **DSU on tree** (small-to-large subtree merging). Both run in
      `O(n log n)` or `O(n·sqrt(n))` and are the two answers you'd reach for.

      ## What both approaches exploit

      A DFS **Euler tour** gives each node an entry time `tin[v]`; the whole
      subtree of `v` occupies the *contiguous* index range
      `[tin[v], tout[v]]`. So "distinct colors in a subtree" becomes
      "distinct values in a subarray", which is the well-studied
      *range-distinct-count* problem.

      - **Mo's algorithm** answers many subarray distinct-count queries
        offline in `O((n + q)·sqrt(n))` by moving two pointers that maintain
        the current frequency table.
      - **DSU on tree** never flattens at all: it does one clever DFS that
        reuses the heavy child's color count, and adds only the *light*
        subtrees into it. Because every node is added only when it sits in a
        light subtree, each node is touched `O(log n)` times → `O(n log n)`.

      ## When to use which

      - **DSU on tree** — when every subtree must be answered (this problem)
        and the merge is *additive* (counts/aggregates). Cleanest here.
      - **Euler tour + Mo** — when you are given only a *set of arbitrary
        range queries* (subtree of x, subtree of y, ...) and no updates;
        it also generalizes to path queries via the direct-edge trick.

      ## Complexity

      - Euler tour: `O(n)`; DSU on tree: `O(n log n)` total, `O(n)` space.
      - Euler + Mo: `O(n + q)` build, `O((n + q)·sqrt(n))` query time,
        `O(n)` space.

      :::tip
      **Interview tip:** "How many distinct values in every subtree?" is the
      canonical DSU-on-tree problem, but the interview-safe version is often the
      *flattening* idea: "distinct values in a range" maps to Euler tour, then a
      counting + last-seen BIT, or Mo. Recognizing that a tree-subtree is a
      contiguous range after an Euler tour is a high-signal interview skill.
      :::

      # The Problem

      You are given a rooted tree consisting of `n` nodes, numbered
      `1, 2, ..., n`; node `1` is the root. Each node has a color. Determine for
      **each** node the number of distinct colors in the subtree of the node.

      ## Input

      The first input line has an integer `n`: the number of nodes.

      The next line has `n` integers `c1, c2, ..., cn`: the color of each node.

      Then there are `n - 1` lines describing the edges: each has two integers
      `a` and `b` — an edge between `a` and `b`.

      **Constraints:** `1 <= n <= 2 * 10^5`, `1 <= a, b <= n`, `1 <= ci <= 10^9`

      ## Output

      Print `n` integers: for node `1, 2, ..., n`, the number of distinct colors
      in its subtree.

      ## Sample

      **Input:**
      ```
      5
      2 3 2 2 1
      1 2
      1 3
      3 4
      3 5
      ```
      **Output:**
      ```
      3 1 2 1 1
      ```

      ### Solution — progressive tiers

      **① Brute force — count each subtree from scratch, O(n²)**

      For every node `v`, run a DFS over its subtree inserting colors into a
      `set`, and record its size. Correct but `O(n²)` on a path/star worst case
      — for `n = 2 * 10^5` that is `4 * 10^10` operations. Too slow.

      **② Optimization — Euler tour + Mo's algorithm, O((n + q)·sqrt(n))**

      Flatten the tree with an Euler tour, so each subtree is a range
      `[tin, tout]`. Compress colors, then answer all `n` range-distinct-count
      queries offline with Mo — move two pointers, maintaining a frequency
      array and a running "distinct" counter. Simpler to reason about, accepted
      for the constraints, and a natural fit when the query set is arbitrary.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      int n;
      vector<int> col;                     // 0-indexed, compressed
      vector<vector<int>> g;
      int tin[200005], tout[200005], euler[200005], timer_;
      int sz_[200005];
      int freq[200005], curDistinct;

      void dfs(int v, int p) {
          tin[v] = ++timer_; euler[timer_] = v; sz_[v] = 1;
          for (int u : g[v]) if (u != p) { dfs(u, v); sz_[v] += sz_[u]; }
          tout[v] = timer_;
      }

      struct Query { int l, r, id; };
      long long ans[200005];

      void add(int i)  { if (freq[col[euler[i]]]++ == 0) curDistinct++; }
      void remove(int i){ if (--freq[col[euler[i]]] == 0) curDistinct--; }

      int main() {
          ios::sync_with_stdio(false); cin.tie(0);
          cin >> n;
          col.resize(n);
          vector<long long> raw(n);
          for (int i = 0; i < n; i++) { cin >> raw[i]; col[i] = i; }
          // compress colors
          {
              vector<int> ord(n); iota(ord.begin(), ord.end(), 0);
              sort(ord.begin(), ord.end(), [&](int a, int b){ return raw[a] < raw[b]; });
              int cc = -1; long long last = LLONG_MIN;
              for (int i : ord) { if (raw[i] != last) { cc++; last = raw[i]; } col[i] = cc; }
          }
          g.assign(n, {});
          for (int i = 0; i + 1 < n; i++) {
              int a, b; cin >> a >> b; --a; --b;
              g[a].push_back(b); g[b].push_back(a);
          }
          timer_ = 0;
          dfs(0, -1);

          vector<Query> qs(n);
          for (int v = 0; v < n; v++) qs[v] = {tin[v], tout[v], v};
          int S = max(1, (int)sqrt(n));
          sort(qs.begin(), qs.end(), [&](const Query& x, const Query& y){
              int bx = x.l / S, by = y.l / S;
              if (bx != by) return bx < by;
              return (bx & 1) ? x.r > y.r : x.r < y.r;
          });

          int curL = 1, curR = 0;
          for (auto& q : qs) {
              while (curL > q.l) add(--curL);
              while (curR < q.r) add(++curR);
              while (curL < q.l) remove(curL++);
              while (curR > q.r) remove(curR--);
              ans[q.id] = curDistinct;
          }
          for (int v = 0; v < n; v++) cout << ans[v] << (v + 1 < n ? " " : "\n");
          return 0;
      }
      ```

      *`O(n·sqrt(n))` time, `O(n)` space. Correct and accepted; guaranteed fast
      enough for `n = 2 * 10^5`.*

      **③ Further optimization — DSU on tree, O(n log n) (optimal)**

      One DFS that keeps the **heavy child's** contribution and adds only light
      subtrees. This is the fastest, tightest solution for "answer every
      subtree" — compiled and run against the sample below.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      int n;
      vector<int> col;                 // 0-indexed, compressed
      vector<vector<int>> g;
      int sz_[200005], big[200005];
      int cnt[200005], curDistinct;    // color frequency + distinct counter
      int ans[200005];

      void calcSize(int v, int p) {
          sz_[v] = 1;
          for (int u : g[v]) if (u != p) { calcSize(u, v); sz_[v] += sz_[u]; }
      }

      void process(int v, int p, int delta) {
          cnt[col[v]] += delta;
          if (delta ==  1 && cnt[col[v]] == 1) curDistinct++;
          if (delta == -1 && cnt[col[v]] == 0) curDistinct--;
          for (int u : g[v]) if (u != p && !big[u]) process(u, v, delta);
      }

      void dsuOnTree(int v, int p, bool keep) {
          int mx = -1, heavyC = -1;
          for (int u : g[v]) if (u != p && sz_[u] > mx) { mx = sz_[u]; heavyC = u; }
          for (int u : g[v]) if (u != p && u != heavyC) dsuOnTree(u, v, false); // light: keep nothing
          if (heavyC != -1) { big[heavyC] = 1; dsuOnTree(heavyC, v, true); }    // heavy: keep all
          for (int u : g[v]) if (u != p && u != heavyC) process(u, v, +1);      // add light subtrees
          process(v, p, +1);                                                     // add v itself
          ans[v] = curDistinct;
          if (heavyC != -1) big[heavyC] = 0;
          if (!keep) process(v, p, -1);                                          // clear if needed
      }

      int main() {
          ios::sync_with_stdio(false); cin.tie(0);
          cin >> n;
          col.resize(n);
          vector<long long> raw(n);
          for (int i = 0; i < n; i++) { cin >> raw[i]; col[i] = i; }
          {
              vector<int> ord(n); iota(ord.begin(), ord.end(), 0);
              sort(ord.begin(), ord.end(), [&](int a, int b){ return raw[a] < raw[b]; });
              int cc = -1; long long last = LLONG_MIN;
              for (int i : ord) { if (raw[i] != last) { cc++; last = raw[i]; } col[i] = cc; }
          }
          g.assign(n, {});
          for (int i = 0; i + 1 < n; i++) {
              int a, b; cin >> a >> b; --a; --b;
              g[a].push_back(b); g[b].push_back(a);
          }
          calcSize(0, -1);
          dsuOnTree(0, -1, true);
          for (int v = 0; v < n; v++) cout << ans[v] << (v + 1 < n ? " " : "\n");
          return 0;
      }
      ```

      *`O(n log n)` total (each node inserted/removed only when it lies in a
      light subtree), `O(n)` space. The optimal tier.*

      **④ Alternative algorithm — small-to-large set merging**

      Merge each node's subtree color-`set` into its parent's, always moving the
      *smaller* set into the larger (classic small-to-large). Each color moves
      `O(log n)` times → `O(n log² n)` with `std::set`, or `O(n log n)` with
      hash sets. Conceptually the simplest to write; DSU on tree is the
      "batched" version of the same idea.

      # Code logic

      The DSU-on-tree tier has three moving parts, and the order is critical.

      - **Preprocessing (`calcSize`).** Compute subtree sizes to find each
        node's *heavy child* (largest subtree). Sizes aren't stored per heavy
        array, but the heavy child is chosen on the fly from `sz_`.
      - **The recursion (`dsuOnTree`).** Process light children with `keep =
        false` (run and then wipe their counts), then the heavy child with
        `keep = true` (leave its counts in place), then push the light
        subtrees (+ own node) into the still-loaded heavy-child counts. The
        slotted frequency table now holds exactly this node's subtree, so
        `curDistinct` is the answer.
      - **`process`.** Adjusts the frequency of one color and updates
        `curDistinct` only at the boundaries `0 <-> 1`. The `!big[u]` guard is
        what stops a light subtree from re-adding the already-kept heavy child
        — without it, colors would be double counted.

      The amortized argument: a node is re-added only when the subtree it lives
      in is *light* at that recursion level, and light means "smaller half", so
      each node is re-added at most `O(log n)` times across the recursion.

      Compression maps `ci <= 10^9` down to `0 .. dedup-1` so frequency arrays
      fit in `O(n)` memory — this is the same trick the Mo tier uses.

      # Walkthrough

      Sample: `n = 5`, colors `2 3 2 2 1`, edges `1-2, 1-3, 3-4, 3-5`. Compressed
      colors become `[0, 1, 0, 0, 2]`. Subtree sizes (root `1`): `sz[1]=5`,
      `sz[2]=1`, `sz[3]=3`, `sz[4]=1`, `sz[5]=1`. Node 1's heavy child is 3
      (size 3); node 3's heavy child is 4 (tie, first found).

      DFS trace (`keep` flags):
      - node 1's light child 2 → `dsuOnTree(2, keep=false)`: heavy none.
        `process(2,+1)` → cnt[1]=1, distinct=1; ans[2]=1; wipe (`process(2,-1)`)
        → distinct=0.
      - handle node 3 (kept): node 3's light child 5 →
        `dsuOnTree(5, false)`: cnt[2]=1, ans[5]=1, wiped. Heavy child 4 → kept:
        cnt[0]=1, ans[4]=1. Then add light subtree 5: cnt[2]=1 (distinct→2), add
        node 3: cnt[0]=2. distinct=2 → ans[3]=2. Then node 1's kept heavy
