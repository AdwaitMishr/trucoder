      ## Theory — count, sum and product of divisors from a factorization

      A number's divisors are controlled entirely by its prime factorisation
      `N = p1^k1 · p2^k2 · … · pn^kn`. Every divisor picks one exponent `e_i` with
      `0 <= e_i <= k_i` independently for each prime, so multiplication counts the
      choices and closed-form formulas give the rest:

      - **Number of divisors** — each prime independently contributes `(k_i + 1)`
        choices, so
        `τ(N) = ∏ (k_i + 1)`.
      - **Sum of divisors** — each prime contributes the geometric series
        `1 + p_i + p_i² + … + p_i^k_i = (p_i^(k_i+1) − 1) / (p_i − 1)`, and the divisors
        are just products of one factor per prime, so
        `σ(N) = ∏ ( (p_i^(k_i+1) − 1) / (p_i − 1) )`.
      - **Product of divisors** — if `D = τ(N)` is the count, then
        `∏divisors = ∏ p_i^e_i` where `e_i = k_i(k_i+1)/2 · ∏_{j≠i}(k_j+1)`.
        Reason: every divisor contains `p_i` with some exponent `0..k_i`; summing
        those exponents over all divisors, the `p_i` exponent is
        `(0+1+…+k_i)` times the number of ways to choose the *other* primes'
        exponents, i.e. `k_i(k_i+1)/2 · ∏_{j≠i}(k_j+1)`.

      All results are reported `mod 10^9+7`. Because the exponents `k_i` can be as
      large as `10^9`, every power is computed with **binary exponentiation**
      `O(log k)` and the modular inverses with Fermat's little theorem
      (`a^(M−2) mod M`, valid since `10^9+7` is prime).

      **Time complexity:** `O(n log k)` — a few `modpow` calls per prime, perfectly
      fine for `n = 10^5`.

      :::tip
      **Interview tip:** "how many divisors, what's their sum, what's their product"
      is a classic modular-number-theory question. The three formulas above are the
      memorable core; the tricky part — dividing inside a geometric series and
      handling exponents in the product — is exactly what interviewers probe. Note
      the exponents for the *product* are taken `mod (M−1)` (Fermat), because the
      base is invertible mod the prime `M`.
      :::

      ## Question

      Given an integer, find the number, sum and product of its divisors. As an
      example, consider the number `12`: the number of divisors is `6`
      (they are `1, 2, 3, 4, 6, 12`), the sum of divisors is `1+2+3+4+6+12 = 28`,
      and the product of divisors is `1·2·3·4·6·12 = 1728`.

      Since the input number may be large, it is given as a prime factorization.

      **Input**

      The first line has an integer `n`: the number of parts in the prime
      factorization. After this, there are `n` lines that describe the
      factorization. Each line has two numbers `x` and `k`, where `x` is a prime
      and `k` is its power.

      **Output**

      Print three integers modulo `10^9+7`: the number, sum and product of the
      divisors.

      **Constraints**

      - `1 <= n <= 10^5`
      - `2 <= x <= 10^6`
      - each `x` is a distinct prime
      - `1 <= k <= 10^9`

      **Example**

      Input:

      ```
      2
      2 2
      3 1
      ```

      Output:

      ```
      6 28 1728
      ```

      ### Solution

      **① Brute force — O(∏(k_i+1)) time, O(∏(k_i+1)) space (enumerate every divisor).**

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      typedef long long ll;
      const ll MOD = 1000000007LL;

      int main() {
          ios::sync_with_stdio(false);
          cin.tie(nullptr);
          int n; cin >> n;
          vector<ll> x(n), k(n);
          for (int i = 0; i < n; i++) cin >> x[i] >> k[i];

          vector<ll> divs = {1};                 // all divisors mod M
          for (int i = 0; i < n; i++) {
              vector<ll> nxt;
              ll pw = 1;
              for (ll e = 0; e <= k[i]; e++) {   // (k_i+1) choices per prime
                  for (ll d : divs) nxt.push_back(d * pw % MOD);
                  pw = pw * x[i] % MOD;
              }
              divs.swap(nxt);
          }

          ll cnt = (ll)divs.size() % MOD;
          ll sm = 0, prod = 1;
          for (ll d : divs) { sm = (sm + d) % MOD; prod = prod * d % MOD; }
          cout << cnt << " " << sm << " " << prod << "\n";
          return 0;
      }
      ```

      Exactly mirrors the definition: build every divisor, then count/sum/multiply
      them. It is correct but materialises `∏(k_i+1)` divisors — already `3` for the
      sample (`6` divisors) yet astronomically large in general: with `n = 10^5`
      primes each of power `1` the count alone is `2^100000`. It only works when the
      number of divisors is tiny, so it fails every real constraint.

      **② Optimization — O(n log k) time, O(n) space (closed forms + one-pass product).**

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      typedef long long ll;
      const ll MOD = 1000000007LL;
      const ll MODM1 = MOD - 1;   // exponent modulus by Fermat (M-1)

      ll modpow(ll a, ll e, ll mod) {
          ll r = 1 % mod;
          a %= mod;
          while (e > 0) {
              if (e & 1) r = r * a % mod;
              a = a * a % mod;
              e >>= 1;
          }
          return r;
      }

      int main() {
          ios::sync_with_stdio(false);
          cin.tie(nullptr);
          int n; cin >> n;
          ll cnt = 1, cntExp = 1, sm = 1, prod = 1;  // counts kept mod M and mod (M-1)
          while (n--) {
              ll x, k; cin >> x >> k;

              // --- product --- new_prod = prod^(k+1) * x^( cntExp * k(k+1)/2 )
              // cntExp = divisor count BEFORE this prime, reduced mod (M-1) (Fermat exponent)
              ll tri = (k * (k + 1) / 2) % MODM1;     // k<=1e9 so k(k+1)/2 fits exactly
              ll e = cntExp * tri % MODM1;
              prod = modpow(prod, k + 1, MOD) * modpow(x, e, MOD) % MOD;

              // --- counters --- cnt is the output count mod M; cntExp feeds Fermat exponents
              cnt = cnt * ((k + 1) % MOD) % MOD;
              cntExp = cntExp * ((k + 1) % MODM1) % MODM1;

              // --- sum ---  geometric series (x^(k+1)-1)/(x-1) mod M
              ll num = (modpow(x, k + 1, MOD) - 1 + MOD) % MOD;
              ll inv = modpow(x - 1, MOD - 2, MOD);   // Fermat inverse of (x-1)
              sm = sm * (num * inv % MOD) % MOD;
          }
          cout << cnt << " " << sm << " " << prod << "\n";
          return 0;
      }
      ```

      The three formulas are applied incrementally. Count and sum are direct. For the
      product, when a new prime `(x, k)` arrives the old `prod` (product over the
      primes seen so far) becomes `prod^(k+1)` (each previous divisor multiplied by
      `1, x, …, x^k`) and the new prime contributes a factor for every way the other
      primes are chosen: exponent `cntExp · k(k+1)/2`. All exponents are taken
      `mod (M−1)` per Fermat. This is `O(n log k)` and is the intended solution.

      **③ Further optimization — not needed.**

      The step above already runs in `O(n log k)` ≈ a couple of `modpow` calls per
      prime, which for `n = 10^5` is a few microseconds-scale total. There is no
      meaningful asymptotic win left; the three formulas are optimal. (One micro-opt,
      `O(n)` storage is already only the input; the recurrence keeps state constant.)

      **④ Alternative algorithm — O(n log k) time, O(n) space (prefix/suffix exponent form).**

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      typedef long long ll;
      const ll MOD = 1000000007LL;
      const ll MODM1 = MOD - 1;

      ll modpow(ll a, ll e, ll mod) {
          ll r = 1 % mod; a %= mod;
          while (e > 0) { if (e & 1) r = r * a % mod; a = a * a % mod; e >>= 1; }
          return r;
      }

      int main() {
          ios::sync_with_stdio(false);
          cin.tie(nullptr);
          int n; cin >> n;
          vector<ll> x(n), k(n);
          for (int i = 0; i < n; i++) cin >> x[i] >> k[i];

          ll cnt = 1;
          for (int i = 0; i < n; i++) cnt = cnt * ((k[i] + 1) % MOD) % MOD;

          ll sm = 1;
          for (int i = 0; i < n; i++) {
              ll num = (modpow(x[i], k[i] + 1, MOD) - 1 + MOD) % MOD;
              ll inv = modpow(x[i] - 1, MOD - 2, MOD);
              sm = sm * (num * inv % MOD) % MOD;
          }

          // product: e_i = k_i(k_i+1)/2 * (product of the OTHER (k_j+1)), mod (M-1)
          vector<ll> pref(n, 1), suff(n, 1);
          for (int i = 1; i < n; i++) pref[i] = pref[i - 1] * ((k[i - 1] + 1) % MODM1) % MODM1;
          for (int i = n - 2; i >= 0; i--) suff[i] = suff[i + 1] * ((k[i + 1] + 1) % MODM1) % MODM1;

          ll prod = 1;
          for (int i = 0; i < n; i++) {
              ll other = pref[i] * suff[i] % MODM1;              // ∏_{j≠i}(k_j+1) mod (M-1)
              ll tri = (k[i] * (k[i] + 1) / 2) % MODM1;
              ll e = other * tri % MODM1;
              prod = prod * modpow(x[i], e, MOD) % MOD;
          }
          cout << cnt << " " << sm << " " << prod << "\n";
          return 0;
      }
      ```

      A different derivation of the same product: compute each prime's exact exponent
      `e_i` up front using a prefix and suffix product of the `(k_j+1)` factors, then
      raise each prime to it. It is equally correct and `O(n log k)`; the recurrence
      in ② is just more compact because it folds the "other primes" factor into the
      running `prod`.

      ## Code logic

      The reason the three quantities can all be updated in a single left-to-right
      sweep is that they are **products of independent per-prime factors**.

      - **Count** uses `cnt = cnt * (k+1)`: adding prime `(x,k)` multiplies the
        divisor count by the number of exponent choices, `k+1`.
      - **Sum** multiplies the running sum by the prime's geometric series
        `(x^(k+1)−1)/(x−1)`. The quotient is computed as
        `num * modpow(x−1, M−2, M)` — Fermat's inverse — because `M` is prime and
        `x−1` is never `0 mod M` (since `x <= 10^6`).
      - **Product** is the only subtle part. The running `prod` covers only the
        primes seen so far; adding `(x,k)` gives every old divisor `d` the companion
        values `d, d·x, …, d·x^k`, which (a) raises `prod` to the `(k+1)`-th power
        and (b) adds a fresh `x` factor for each of the `cntExp` old divisors, with
        total exponent `cntExp · k(k+1)/2`. All exponents are reduced `mod (M−1)`.
        Note the program keeps **two** running counts for this reason: `cnt` is the
        output count reduced mod `M`, while `cntExp` is the same product reduced mod
        `M−1` because it feeds a Fermat exponent.

      Just enough modular care keeps everything in `long long`: every multiplication
      in `modpow` is of two residues `< M`, whose product `< M² ≈ 10^18` fits.

      ## Walkthrough

      Trace the sample input `n = 2`, then `2 2` and `3 1`:

      | step | x,k | count   | sum        | product                                         |
      |------|-----|---------|------------|-------------------------------------------------|
      | init | –   | 1       | 1          | 1                                               |
      | 1    | 2,2 | 1·3 = 3 | (7/1)·1 = 7 | 1³ · 2^(1·3) = 8                                 |
      | 2    | 3,1 | 3·2 = 6 | 7 · (8/2)=7·4=28 | 8² · 3^(3·1) = 64 · 27 = 1728                 |

      Output `6 28 1728`, matching the sample. Sanity check against the divisor list of
      `12 = 2²·3`: divisors `1,2,3,4,6,12` → count `6`, sum `1+2+3+4+6+12 = 28`,
      product `1·2·3·4·6·12 = 1728`. The formulas reproduce the definition exactly.
