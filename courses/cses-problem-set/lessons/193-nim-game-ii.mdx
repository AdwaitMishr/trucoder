      # Nim Game II — every heap is a small subtraction game (Grundy)

      As in Nim Game I there are `n` heaps, but now a move removes exactly
      **1, 2, or 3** sticks from the chosen heap (any number is no longer
      allowed). Last move wins. Who wins with optimal play?

      The difference from plain Nim is that a heap is no longer a Nim-heap with
      Grundy value `x`; removing at most 3 sticks changes the Grundy values.
      This is exactly what **Grundy numbers (Sprague–Grundy)** are for: each
      heap is an *independent subgame*, and the combined position is losing iff
      the XOR of the subgames' Grundy values is zero.

      ## Grundy of a single heap that allows removing 1, 2, or 3

      For a heap of size `x`, the moves lead to sizes `x-1`, `x-2`, `x-3`. By
      definition:

      ```
      g(0) = 0
      g(x) = mex{ g(x-1), g(x-2), g(x-3) }   for x ≥ 1
      ```

      Fill it in:

      | x | reachable g | mex |
      |---|-------------|-----|
      | 0 | — | 0 |
      | 1 | {g(0)} = {0} | 1 |
      | 2 | {g(1), g(0)} = {1, 0} | 2 |
      | 3 | {g(2), g(1), g(0)} = {2, 1, 0} | 3 |
      | 4 | {g(3), g(2), g(1)} = {3, 2, 1} | 0 |
      | 5 | {g(4), g(3), g(2)} = {0, 3, 2} | 1 |
      | 6 | {g(5), g(4), g(3)} = {1, 0, 3} | 2 |
      | 7 | {g(6), g(5), g(4)} = {2, 1, 0} | 3 |

      The pattern is `g(x) = x mod 4`. A heap of size `x` behaves, on its own,
      like a Nim heap of size `x mod 4`. The overall winning position is decided
      by XOR-ing those residues, exactly like the plain-XOR rule of Nim Game I.

      **Time:** O(n) per test, **Space:** O(1).

      :::tip
      **Interview tip:** when the allowed removals are a *fixed small window*
      (`1..m`), the Grundy sequence is periodic with period `m+1`; here that
      gives `g(x) = x mod 4`. Spotting "remove at most k ⇒ Grundy cycles mod
      k+1" is a fast, impressive interview takeaway, and it is the cleanest
      introduction to how Grundy numbers generalise Nim.
      :::

      # Question — Nim Game II

      There are `n` heaps of sticks and two players who move alternately. On
      each move, a player chooses a non-empty heap and removes 1, 2, or 3
      sticks. The player who removes the last stick wins the game.

      Your task is to find out who wins if both players play optimally.

      **Input**

      The first input line contains an integer `t`: the number of tests. After
      this, `t` test cases are described:

      The first line contains an integer `n`: the number of heaps.

      The next line has `n` integers `x_1, x_2, ..., x_n`: the number of sticks
      in each heap.

      **Output**

      For each test case, print "first" if the first player wins the game and
      "second" if the second player wins the game.

      **Constraints**

      - `1 <= t <= 2·10^5`
      - `1 <= n <= 2·10^5`
      - `1 <= x_i <= 10^9`
      - the sum of all `n` is at most `2·10^5`

      **Example**

      Input:

      ```
      3
      4
      5 7 2 5
      2
      4 1
      3
      4 4 4
      ```

      Output:

      ```
      first
      first
      second
      ```

      ### Solution

      **① Brute force — compute each heap's Grundy by DP, O(max_x) per test**

      Build `g[0..m]` with `g[x] = mex{ g[x-1], g[x-2], g[x-3] }` for the largest
      heap size `m`, then XOR the `g[x_i]` values. Correct, but `x_i` reaches
      `10^9`, so building an array up to the largest heap is impossible:

      ```cpp
      int mex3(int a, int b, int c) {          // smallest value not in {a,b,c}
          bool seen[4] = {};
          seen[a] = seen[b] = seen[c] = true;
          for (int v = 0; v < 4; v++) if (!seen[v]) return v;
          return 3;
      }
      // g[0]=0; g[x]=mex3(g[x-1],g[x-2],g[x-3]) — O(m) work, too big for x~1e9
      ```

      **② Optimization — closed form g(x) = x mod 4, O(n) time, O(1) space**

      Recognise the `mod 4` cycle and XOR the residues directly — no array at
      all:

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      int main() {
          ios::sync_with_stdio(false);
          cin.tie(nullptr);

          int t;
          cin >> t;
          while (t--) {
              int n;
              cin >> n;
              int xr = 0;
              for (int i = 0; i < n; i++) {
                  long long x;
                  cin >> x;
                  xr ^= (int)(x % 4);          // Grundy value of this heap
              }
              cout << (xr ? "first" : "second") << "\n";
          }
      }
      ```

      **③ Further optimisation** — none: reading every heap (`O(n)`) is already
      the minimum work required.

      **④ Alternative algorithm** — a *periodicity argument* reaches the same
      answer without the table: because the game (remove `1..3`) has only four
      Grundy states that cycle, `(x mod 4)`. If you were unsure whether the
      period holds, you would precompute `g` up to, say, `64` and verify the
      repetition rather than trusting the pattern.

      # Code logic

      Walk through the `O(n)` solution:

      - The single-pile rule `g(x) = x mod 4` is the heart: removing 1–3 sticks
        from a heap cycles its Grundy value among `{0, 1, 2, 3}` (and we reuse
        the `4`-long period).
      - `x % 4` is computed on `long long` (heap sizes reach `10^9` but `mod 4`
        always fits an `int`), cast to `int`, and XOR-ed into `xr`.
      - Sprague-Grundy says the *combined* position is losing iff the XOR of
        all heaps' Grundy values is `0`. Hence the combined Grundy is just the
        XOR of the per-heap `x mod 4`.
      - `xr ? "first" : "second"`: non-zero XOR → first wins; zero XOR →
        second wins. Identical in shape to Nim Game I, only the Grundy value of
        one heap changed.

      # Walkthrough

      Apply `g(x) = x mod 4` to the sample's three tests.

      | test | heaps | residues (x mod 4) | XOR | result |
      |------|-------|---------------------|-----|--------|
      | 1 | 5 7 2 5 | 1, 3, 2, 1 | 1⊕3⊕2⊕1 = 1 | ≠0 → **first** |
      | 2 | 4 1 | 0, 1 | 0⊕1 = 1 | ≠0 → **first** |
      | 3 | 4 4 4 | 0, 0, 0 | 0 | 0 → **second** |

      - Test 1: residues `1⊕3⊕2⊕1=1`, non-zero → first moves to a zero-Grundy
        position and wins.
      - Test 2: `0⊕1=1` → first wins.
      - Test 3: all heaps are multiples of 4, so every residue is `0` and the
        XOR is `0` → second wins.

      All three match the expected output. Note how a heap of `4` behaves like a
      "done" Nim heap (Grundy 0): on its own it contributes nothing to the sum.
