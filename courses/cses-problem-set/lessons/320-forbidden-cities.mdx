      # Forbidden Cities — can a path avoid a banned vertex?

      We have an undirected, connected city/road graph. For each of `q` queries
      `(a, b, c)` we must answer: is there a route from city `a` to city `b`
      that **does not visit** city `c`?

      The answer is `NO` exactly when **every** `a-b` path passes through `c`.
      A vertex that lies on every path between two other vertices is precisely an
      **articulation point** (cut vertex) that *separates* them.

      Two quick wins first:

      - If `a == c` or `b == c` the answer is trivially `NO` (you cannot leave /
        arrive without visiting `c`).
      - If `c` is **not** an articulation point, removing it never disconnects
        the graph, so some path always avoids it → answer `YES`.

      The real work: when `c` *is* an articulation point, decide whether `a` and
      `b` fall in different **biconnected components** hanging off `c` — i.e.
      whether `c` sits on the unique `a-b` path in the block-cut tree.

      **Block-cut tree.** Decompose the graph into **biconnected components**
      (maximal vertex sets where removing any *one* vertex still keeps the rest
      connected — a single bridge edge is its own tiny component). Build a tree
      whose nodes are the articulation vertices plus one node per biconnected
      component, with an articulation connected to every component that contains
      it. In this tree the unique path between any two vertices exactly mirrors
      which articulation points separate them.

      **Query with LCA.** Map each city to its node in the block-cut tree. Then
      `c` separates `a` and `b` iff `c`'s node lies on the tree path
      `node(a) .. node(b)`, which is true iff
      `dist(a,c) + dist(c,b) == dist(a,b)` (all tree distances via LCA).

      **Time:** Tarjan + LCA preprocessing `O(n + m)`, each query `O(log n)`.
      **Space:** `O(n + m)`.

      :::tip
      **Interview tip:** "Does a path exist that avoids vertex `X`?" is asking
      whether `X` is an articulation point *between* two endpoints. Reach for
      **biconnected components + block-cut tree**: it answers all such
      separation queries in `O(1)`/`O(log n)` after preprocessing. The
      `dist(u,c)+dist(c,v) == dist(u,v)` test on a tree is a reusable idiom for
      "is `c` on the `u-v` path".
      :::

      # Question

      There are `n` cities and `m` roads between them. Kaaleppi is currently in
      city `a` and wants to travel to city `b`. However, Kaaleppi has recently
      robbed a bank in city `c` and can't enter the city, because the local
      police would catch him. Find out if there is a route from city `a` to city
      `b` that does not visit city `c`. As an additional challenge, you have to
      process `q` queries where `a`, `b` and `c` vary.

      **Input**

      The first input line has three integers `n`, `m` and `q`: the number of
      cities, roads and queries. The cities are numbered `1, 2, ..., n`. Then
      there are `m` lines describing the roads; each line has two integers `a`
      and `b`: there is a road between cities `a` and `b`. Each road is
      bidirectional. Finally, there are `q` lines describing the queries; each
      has three integers `a`, `b`, `c`. You can assume there is a route between
      any two cities (the graph is connected).

      **Output**

      For each query, print `YES` if there is such a route, and `NO` otherwise.

      **Constraints**

      - `1 <= n <= 10^5`
      - `1 <= m <= 2*10^5`
      - `1 <= q <= 10^5`

      **Example**

      Input:
      ```
      5 6 3
      1 2
      1 3
      2 3
      2 4
      3 4
      4 5
      1 4 2
      3 5 4
      3 5 2
      ```
      Output:
      ```
      YES
      NO
      YES
      ```

      ### Solution — progressive tiers

      **① Brute force — BFS per query avoiding c, O(q * (n + m))**

      For each query, run a BFS from `a` that simply refuses to step on `c`; if
      it reaches `b`, output `YES`. Correct, but `q` can be `10^5` and each BFS
      scans the whole graph.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int n,m,q; vector<vector<int>> adj;
      int main(){
          cin>>n>>m>>q; adj.assign(n,{});
          for (int i=0;i<m;i++){int a,b;cin>>a>>b;--a;--b;adj[a].push_back(b);adj[b].push_back(a);}
          while (q--){
              int a,b,c; cin>>a>>b>>c; --a;--b;--c;
              if (a==c || b==c){ cout<<"NO\n"; continue; }
              vector<char> vis(n,0); vis[c]=1; queue<int> qq; qq.push(a); vis[a]=1;
              bool ok=false;
              while (!qq.empty()){ int u=qq.front(); qq.pop(); if (u==b){ok=true;break;}
                  for (int v:adj[u]) if (!vis[v]){vis[v]=1; qq.push(v);} }
              cout<<(ok?"YES":"NO")<<"\n";
          }
      }
      ```
      *O(q * (n + m)) — too slow for `q, n` up to `10^5`.*

      **② Optimization — block-cut tree + LCA, O((n+m+q) log n)**

      Find articulation points and biconnected components with Tarjan's low-link
      DFS, build the block-cut tree, preprocess LCA, and answer each query with
      the on-path distance test.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int n,m,q; vector<vector<int>> adj;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          cin>>n>>m>>q; adj.assign(n,{});
          for (int i=0;i<m;i++){int a,b;cin>>a>>b;--a;--b;adj[a].push_back(b);adj[b].push_back(a);}
          // articulation points
          vector<int> tin(n,-1), low(n); vector<char> cut(n,0); int timer=0;
          function<void(int,int)> tar=[&](int u,int p){ tin[u]=low[u]=timer++; int child=0;
              for (int v:adj[u]){ if (v==p) continue;
                  if (tin[v]==-1){ child++; tar(v,u); low[u]=min(low[u],low[v]);
                      if (low[v]>=tin[u]){ if (p!=-1||child>=2) cut[u]=1; } }
                  else low[u]=min(low[u],tin[v]); } };
          for (int i=0;i<n;i++) if (tin[i]==-1) tar(i,-1);
          // biconnected components via edge stack
          tin.assign(n,-1); low.assign(n,0); timer=0;
          vector<pair<int,int>> st; vector<vector<int>> blocks;
          function<void(int,int)> bdfs=[&](int u,int p){ tin[u]=low[u]=timer++;
              for (int v:adj[u]){ if (v==p) continue;
                  if (tin[v]==-1){ st.push_back({u,v}); bdfs(v,u); low[u]=min(low[u],low[v]);
                      if (low[v]>=tin[u]){ vector<int> comp;
                          while (true){ auto e=st.back(); st.pop_back(); comp.push_back(e.first); comp.push_back(e.second);
                              if (e.first==u&&e.second==v) break; }
                          sort(comp.begin(),comp.end()); comp.erase(unique(comp.begin(),comp.end()),comp.end());
                          blocks.push_back(comp); } }
                  else if (tin[v]<tin[u]){ st.push_back({u,v}); low[u]=min(low[u],tin[v]); } } };
          for (int i=0;i<n;i++) if (tin[i]==-1) bdfs(i,-1);
          int B=blocks.size(), N=n+B;
          vector<vector<int>> tree(N); vector<int> vnode(n,-1);
          auto link=[&](int x,int y){ tree[x].push_back(y); tree[y].push_back(x); };
          for (int bi=0;bi<B;bi++){ int bn=n+bi;
              for (int x:blocks[bi]){ if (cut[x]) link(x,bn); else if (vnode[x]==-1) vnode[x]=bn; } }
          for (int i=0;i<n;i++){ if (cut[i]) vnode[i]=i; else if (vnode[i]==-1) vnode[i]=i; }
          // LCA
          int LOG=1; while ((1<<LOG)<N) LOG++;
          vector<vector<int>> up(LOG, vector<int>(N,-1)); vector<int> depth(N); vector<char> vis(N,0);
          function<void(int,int)> dtr=[&](int u,int p){ up[0][u]=p; depth[u]=(p==-1?0:depth[p]+1); vis[u]=1;
              for (int v:tree[u]) if (v!=p && !vis[v]) dtr(v,u); };
          for (int i=0;i<N;i++) if (!vis[i]) dtr(i,-1);
          for (int k=1;k<LOG;k++) for (int v=0;v<N;v++)
              if (up[k-1][v]!=-1) up[k][v]=up[k-1][up[k-1][v]];
          auto lca=[&](int u,int v){ if (depth[u]<depth[v]) swap(u,v);
              int d=depth[u]-depth[v]; for (int k=LOG-1;k>=0;k--) if (d&(1<<k)) u=up[k][u];
              if (u==v) return u; for (int k=LOG-1;k>=0;k--)
                  if (up[k][u]!=up[k][v]){ u=up[k][u]; v=up[k][v]; } return up[0][u]; };
          auto dist=[&](int u,int v){ int w=lca(u,v); return depth[u]+depth[v]-2*depth[w]; };
          while (q--){
              int a,b,c; cin>>a>>b>>c; --a;--b;--c;
              if (a==c||b==c){ cout<<"NO\n"; continue; }
              if (!cut[c]){ cout<<"YES\n"; continue; }
              int na=vnode[a], nb=vnode[b], nc=vnode[c];
              bool on = dist(na,nc)+dist(nc,nb)==dist(na,nb);
              cout<<(on?"NO":"YES")<<"\n";
          }
      }
      ```
      *O((n+m+q) log n) — the intended solution.*

      **③ Special case first**

      The cheapest pre-check is huge: a non-articulation `c` can *never* force a
      reroute, so the majority of queries where `c` is a "normal" city answer
      `YES` immediately without LCA at all. Only cut vertices need the tree path
      test. This makes the practical runtime even smaller.

      **④ Further optimization** — the per-query test can be `O(1)` with tarjan
      `tin`/`tout` intervals instead of binary-lifting distances; the idea is
      identical (check `c` is an ancestor-style separator). The LCA version is
      clearer to read and well within `10^5` queries, so we stop here.

      # Code logic

      - **Articulation points.** Tarjan's low-link: `low[v] >= tin[u]` and
        `u` is not the root of its DFS tree (or has > 1 root child) marks `u` as
        a cut vertex.
      - **Biconnected components.** A second low-link DFS pops an edge stack
        whenever `low[v] >= tin[u]`; the popped edges' vertices form a component
        (the "single bridge" case naturally yields a two-vertex component).
      - **Block-cut tree.** Vertex `n + bi` represents component `bi`. Every
        articulation vertex is linked to each component containing it; every
        non-cut vertex is assigned to its single component via `vnode`.
      - **LCA + distances.** `vnode[a]`, `vnode[b]`, `vnode[c]` are nodes of the
        tree. `c` separates `a` and `b` iff `c` is on the tree path, tested by
        `dist(a,c)+dist(c,b) == dist(a,b)`.

      - Query `(3, 5, 2)`: `c = 2` is not an articulation point → answer `YES`
