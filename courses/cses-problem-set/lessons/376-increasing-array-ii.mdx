      ## Theory — minimum cost to make an array non-decreasing

      We may raise or lower any element by one (cost 1 per unit change) and want
      the array **non-decreasing**: `b_1 ≤ b_2 ≤ … ≤ b_n`, minimizing the total
      `Σ |a_i − b_i|`. The `b_i` may be *any* integers — we choose a whole new
      non-decreasing sequence that is "closest" to `a`.

      **Why the optimal `b_i` take values from `a`.** The cost is a sum of
      absolute values (piecewise-linear, convex), and the constraint is that
      consecutive `b`'s are ordered. A classic result for L1 isotonic regression
      is that an optimal solution only uses values that appear in the input — no
      final `b_i` needs a value that no `a` has. So for small `n` we can
      brute-force a DP over the distinct values of `a`.

      **The greedy (used for the real constraints).** There is a famously simple
      max-heap algorithm that computes the answer in one pass (this is an
      "isotonic regression by slope trick"). Process elements left to right,
      keeping a max-heap of the values seen so far. For each `x`:
       1. push `x` into the heap;
       2. if the heap's **maximum** exceeds `x`, then `top − x` is the cheapest
          way to resolve the inversion: add `top − x` to the answer, drop that
          `top`, and push `x` back.
      Intuitively the heap's top tracks the "cheapest value to trim down to"
      for the current run; each time it exceeds the new element we pay exactly
      the difference, exactly once per element.

      :::tip
      **Interview tip:** Making an array monotone with minimal absolute cost
      (L1 isotonic regression) appears in many "min operations to sort/tidy an
      array" questions. Memorise this O(n log n) max-heap greedy: `push x; if
      (top > x) ans += top − x, pop, push x`. A harder twin is the *strictly*
      increasing variant, handled by replacing each `b_i` with `b_i − i` first.
      :::

      ## The Problem

      You are given an array of `n` integers. You want to modify the array so
      that it is increasing, i.e., every element is at least as large as the
      previous element. On each move you can increase or decrease the value of
      any element by one. What is the minimum number of moves required?

      **Input.** The first input line contains an integer `n`. The second line
      contains `n` integers `x_1, x_2, …, x_n`.

      **Output.** Print the minimum number of moves.

      **Constraints**
      - `1 ≤ n ≤ 2·10^5`
      - `1 ≤ x_i ≤ 10^9`

      **Sample**

      Input:
      ```
      5 3 8 5 6 5
      ```

      Output:
      ```
      4
      ```

      *(Here `n = 5` and the array is `3 8 5 6 5`; e.g. lower the `8` by 3 and
      raise the last `5` by 1 → `3 5 5 6 6`, four moves.)*

      ### Solution — progressive tiers

      **① Brute force — O(n·C) DP over candidate values.** Since an optimal
      solution uses only values present in `a`, compress the distinct `x`
      values as `v_0 < … < v_(C-1)`. Let `dp[i][j]` = min cost to make the
      first `i+1` elements non-decreasing with `b_i = v_j`. Transition via a
      running prefix minimum over the previous row. Exact, but `C ≤ n` and the
      table is `O(n·n)` — fine for small `n`, impossible for `2·10^5`.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      typedef long long ll;
      int main(){
          int n; cin>>n; vector<ll> a(n);
          for(auto&v:a) cin>>v;
          vector<ll> v=a; sort(v.begin(),v.end());
          v.erase(unique(v.begin(),v.end()),v.end());
          int C=v.size();
          vector<ll> dp(C), nxt(C);
          for(int j=0;j<C;j++) dp[j]=llabs(a[0]-v[j]);
          for(int i=1;i<n;i++){
              ll best=LLONG_MAX;
              for(int j=0;j<C;j++){
                  best=min(best, dp[j]);           // b_i can equal any earlier value
                  nxt[j]=best + llabs(a[i]-v[j]);
              }
              swap(dp,nxt);
          }
          cout<<*min_element(dp.begin(),dp.end())<<"\n";
      }
      ```
      *Complexity: O(n·C) time, O(C) memory (with `C ≤ n`, O(n²) worst). Too
      slow for `n = 2·10^5`.*

      **② Optimization — O(n log n) max-heap greedy.** The single-pass slope-trick
      greedy described in the theory. Push each `x`; whenever the heap max
      exceeds `x`, add the difference and trim.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      typedef long long ll;
      int main(){
          ios::sync_with_stdio(false); cin.tie(0);
          int n; cin>>n;
          priority_queue<ll> pq; ll res=0;
          for(int i=0;i<n;i++){
              ll x; cin>>x;
              pq.push(x);
              if(pq.top()>x){ res += pq.top()-x; pq.pop(); pq.push(x); }
          }
          cout<<res<<"\n";
      }
      ```
      *Complexity: O(n log n) time, O(n) memory — instant for `n ≤ 2·10^5`.*

      **④ Alternative / note.** The strictly-increasing variant (`b_1 < b_2 <
      …`) maps to this problem by the substitution `b_i = c_i + i` and running
      the same greedy on `a_i − i`. That single transform is the standard trick
      when a problem demands *strictly* increasing rather than non-decreasing.

      ## Code logic

      `solve` — O(n log n) max-heap greedy. Key lines:

      1. **`pq.push(x)`** — every element is a "candidate ceiling" for the
         current run.
      2. **`if (pq.top() > x)`** — the current element breaks non-decreasing
         order against the largest value seen; the minimum cost to fix it is
         lowering that large value down to `x`, i.e. `top − x`.
      3. **`res += top − x; pq.pop()`** — pay the trim.
      4. **`pq.push(x)`** — reinsert `x` (it is now the max and the new
         effective ceiling for the rest of the run).
      The invariant: after processing each `x`, `pq` holds a set of "plateau
      ceilings" whose multiset sum is exactly the total move count already paid
      plus paid-as-you-go; the running total is the final answer.
