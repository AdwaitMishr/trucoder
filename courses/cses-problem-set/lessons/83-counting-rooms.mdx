      # Counting Rooms — flood fill / connected components on a grid

      A building map is an `n × m` grid of floor (`.`) and wall (`#`) squares.
      Floor cells that touch by an edge (up / down / left / right) belong to the
      same **room**. The task: count how many rooms the map has.

      ## The idea: treat the grid as a graph

      Think of every floor cell as a node and every pair of adjacent floor cells
      as an edge. A **room** is exactly a *connected component* of this graph —
      a maximal set of floor cells you can walk between. So counting rooms
      reduces to **counting connected components**.

      The standard tool is a graph traversal — DFS or BFS — that starts at an
      unvisited floor cell and **floods** through every floor cell reachable
      from it. Each time you start a fresh flood you have found one new room;
      the flood marks its whole room visited, so the next room never re-touches
      it. Because a single traversal claims an entire component, you never
      double-count.

      This direct application of a search on a 2-D grid is called a **flood
      fill** — the backbone of grid problems from "number of islands" to
      minesweeper to image segmentation.

      ## Why it works

      A room is the equivalence class of the *walk* relation: `u ~ v` if a path
      of adjacent floor cells joins them. Every traversal launched from an
      unvisited floor cell visits exactly one equivalence class, and every class
      is launched exactly once. Hence *floods started = rooms counted*.

      ## Complexity

      Each floor cell is discovered exactly once, and each claims ≤ 4 neighbours.
      Time `O(n·m)`, space `O(n·m)` for the grid plus a visited marker.

      ## Worked micro-example

      ```
      5 8
      ########
      #..#...#
      ####.#.#
      #..#...#
      ########
      ```

      Scanning top-left to bottom-right: the first unvisited floor at `(1,1)`
      floods the top-left room; the next flood from `(1,4)` covers the middle
      room; the third from `(2,5)` covers the right room. Exactly 3 floods ⇒ 3
      rooms. (Row 0 is the top wall row.)

      :::tip
      **Interview tip:** "Count connected regions" (islands, rooms, territories
      on a grid) is one of the most common graph warm-ups. The reliable move is
      grid → graph → traversal with a visited marker. Know both BFS (explicit
      queue, no recursion) and DFS; in a contest the iterative BFS is the safe
      choice because it can never hit a recursion-depth limit.
      :::

      # The Problem

      You are given a map of a building, and your task is to count the number
      of its rooms. The size of the map is `n × m` squares, and each square is
      either floor (`.`) or wall (`#`). You can walk left, right, up, and down
      through the floor squares.

      ## Input

      The first input line has two integers `n` and `m`: the height and width
      of the map.

      Then there are `n` lines of `m` characters describing the map. Each
      character is either `.` (floor) or `#` (wall).

      **Constraints:** `1 ≤ n, m ≤ 1000`

      ## Output

      Print one integer: the number of rooms.

      ## Sample

      **Input:**

      ```
      5 8
      ########
      #..#...#
      ####.#.#
      #..#...#
      ########
      ```

      **Output:**

      ```
      3
      ```

      ### Solution — progressive tiers

      **① Brute force — recursive DFS flood fill, O(n·m)**

      Flood every room with a recursive DFS that marks its cells visited. This
      is the most literal reading of the definition and, for this problem, is
      already linear — but the recursion can be a worry on very deep floods.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int n, m;
      vector<string> g;
      vector<vector<char>> vis;
      int dr[4] = {-1, 1, 0, 0}, dc[4] = {0, 0, -1, 1};

      void dfs(int r, int c) {
          vis[r][c] = 1;
          for (int k = 0; k < 4; k++) {
              int nr = r + dr[k], nc = c + dc[k];
              if (nr >= 0 && nr < n && nc >= 0 && nc < m && !vis[nr][nc] && g[nr][nc] == '.')
                  dfs(nr, nc);
          }
      }

      int main() {
          ios::sync_with_stdio(false); cin.tie(nullptr);
          cin >> n >> m;
          g.resize(n); vis.assign(n, vector<char>(m, 0));
          for (int i = 0; i < n; i++) cin >> g[i];
          int rooms = 0;
          for (int i = 0; i < n; i++)
              for (int j = 0; j < m; j++)
                  if (g[i][j] == '.' && !vis[i][j]) { rooms++; dfs(i, j); }
          cout << rooms << '\n';
          return 0;
      }
      ```

      *O(n·m) time, O(n·m) space — correct and already fast here; the recursion
      is the only soft spot.*

      **② Optimization — iterative BFS flood fill, O(n·m)**

      Replace recursion with an explicit queue and mark cells visited *in
      place* (turn the floor into a wall) as soon as you push them. This is the
      robust contest version: no recursion, each cell enqueued at most once.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main() {
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n, m; cin >> n >> m;
          vector<string> g(n);
          for (int i = 0; i < n; i++) cin >> g[i];
          int dr[4] = {-1, 1, 0, 0}, dc[4] = {0, 0, -1, 1};
          int rooms = 0;
          for (int i = 0; i < n; i++) for (int j = 0; j < m; j++) {
              if (g[i][j] == '.') {
                  rooms++;                                  // a new room found
                  queue<pair<int,int>> q; q.push({i, j});
                  g[i][j] = '#';                            // claim it now
                  while (!q.empty()) {
                      auto [r, c] = q.front(); q.pop();
                      for (int k = 0; k < 4; k++) {
                          int nr = r + dr[k], nc = c + dc[k];
                          if (nr >= 0 && nr < n && nc >= 0 && nc < m && g[nr][nc] == '.') {
                              g[nr][nc] = '#';              // claim before push
                              q.push({nr, nc});
                          }
                      }
                  }
              }
          }
          cout << rooms << '\n';
          return 0;
      }
      ```

      *O(n·m) time, O(n·m) space — the intended solution.*

      **③ Further optimization — none needed**

      You must inspect every cell to learn the map, so any correct algorithm is
      at least `Ω(n·m)`. `O(n·m)` is optimal; there is nothing to shave off
      asymptotically.

      **④ Alternative — Disjoint Set Union (DSU), O(n·m · α)**

      Sweep the grid and merge each floor cell with any floor cell to its right
      or below; at the end a floor cell is the root of exactly one component, so
      counting distinct roots counts rooms. Different framework, same answer —
      and DSU pays off on problems where edges arrive *online*.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      struct DSU {
          vector<int> p;
          DSU(int n) : p(n) { iota(p.begin(), p.end(), 0); }
          int find(int x) { return p[x] == x ? x : p[x] = find(p[x]); }
          void uni(int a, int b) { p[find(a)] = find(b); }
      };
      int main() {
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n, m; cin >> n >> m;
          vector<string> g(n);
          for (int i = 0; i < n; i++) cin >> g[i];
          auto id = [&](int r, int c) { return r * m + c; };
          DSU d(n * m);
          for (int i = 0; i < n; i++) for (int j = 0; j < m; j++) {
              if (g[i][j] != '.') continue;
              if (i + 1 < n && g[i + 1][j] == '.') d.uni(id(i, j), id(i + 1, j));
              if (j + 1 < m && g[i][j + 1] == '.') d.uni(id(i, j), id(i, j + 1));
          }
          int rooms = 0;
          for (int i = 0; i < n; i++) for (int j = 0; j < m; j++)
              if (g[i][j] == '.' && d.find(id(i, j)) == id(i, j)) rooms++;
          cout << rooms << '\n';
          return 0;
      }
      ```

      *O(n·m · α(n·m)) time, O(n·m) space — `α` is the tiny inverse-Ackermann
      factor; practically linear.*

      # Code logic

      Key lines of the iterative BFS solution:

      - **Claiming before pushing.** Every time a floor cell is enqueued, it is
        immediately rewritten to `'#'`. This both marks it visited and *removes*
        it from the pool of future flood starts, so each cell enters the queue
        at most once — the invariant that keeps the whole search linear.
      - **Neighbour loop.** `dr/dc` encode the four moves (up, down, left,
        right). Bounds are checked first, then whether the neighbour is still
        floor.
      - **The outer double loop.** It sees exactly the cells never reached by
        any previous flood — i.e. the seed of each new component. `rooms++`
        fires once per component. Because a floor cell is either already
        claimed (visited) or the seed of a new room, `rooms` ends as the true
        component count — no re-scanning of claimed cells is ever needed.

      ####.#.#
      #..#...#

      Row/column indices are 0-based. The scan visits cells left-to-right,

      | scan hits | action | rooms |
      |-----------|--------|-------|
      | (1,1) `.`  | new room → BFS floods (1,1) up/down/left/right; reaches (1,1) only (neighbours are walls on the left/up, `#` on the right/down) | 1 |
      | (1,2) `#`  | wall, skip | 1 |
      | (1,3) `#`  | wall, skip | 1 |
      | (1,4) `.`  | new room → BFS floods (1,4), (2,4), (1,5), (1,6), (2,6), (3,4), (3,5), (3,6), (2,6 already) — the middle room | 2 |
      | ... rows 2–3: the only unvisited floor left is (2,5) | new room → BFS floods (2,5), (3,5) | 3 |
      | rest | walls / already claimed | 3 |

      Final count — `3`.

      Expected (sample) — `3`. Actual — `3`. Match.

      The three rooms are exactly the three separated `#`-walled regions of the
      map.
