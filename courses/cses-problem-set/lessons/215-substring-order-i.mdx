      # Substring Order I — the k-th lexicographically smallest distinct substring

      Given a string, we want the **k-th smallest distinct substring** in
      lexicographic order. This is the classic "unroll a suffix array with the
      LCP array" problem.

      **Why the suffix array + LCP is the natural tool.** List the suffixes in
      sorted (lexicographic) order. A suffix's **prefixes are its substrings**,
      and as you move along the sorted suffixes, the substrings they introduce
      are produced in lexicographic order — *except* that a suffix shares its
      first `lcp[i]` characters with the previous suffix in the order. So the
      `i`-th sorted suffix contributes exactly

      ```
      new distinct substrings = (length of suffix i) − lcp[i] = (n − sa[i]) − lcp[i]
      ```

      brand-new distinct substrings (its prefixes longer than the overlap). The
      `lcp` (longest common prefix) array is built in **O(n)** by the **Kasai**
      algorithm: iterate positions in the original string and reuse the previous
      overlap height.

      **The algorithm.** Maintain a running total of distinct substrings seen;
      for each sorted suffix in order, add its `new` count; the first suffix
      where the running total reaches `k` is the one containing the answer —
      which is `s[ sa[i] .. sa[i] + lcp[i] + remaining - 1 ]`.

      **Complexity.** Suffix array construction is O(n log n) (doubling);
      Kasai LCP is O(n); the scan is O(n). Total **O(n log n)** time and
      **O(n)** space.

      :::tip
      **Interview tip:** "k-th smallest substring/subsequence" is a recurring
      pattern. The mental model interviewers want is *"the sorted suffixes
      generate distinct substrings in order, and the LCP tells you how many you
      already counted."* If even that is too slow, the answer is a linear-time
      suffix automaton walk (next lesson) — so know both.
      :::

      # Question — Substring Order I

      You are given a string of length `n`. If **all of its distinct
      substrings** are ordered lexicographically, what is the **k-th smallest**
      of them?

      **Constraints**

      - `1 ≤ n ≤ 10^5`
      - `1 ≤ k ≤ n(n+1)/2`
      - It is guaranteed that `k` does not exceed the number of distinct
        substrings.

      **Input.** The first input line has the string of length `n` (characters
      `a`–`z`). The second line has the integer `k`.

      **Output.** Print the k-th smallest distinct substring in lexicographical
      order.

      Sample input:

      ```
      babaacbaab
      10
      ```

      Sample output:

      ```
      aba
      ```

      Explanation: the 10 smallest distinct substrings in order are `a`, `aa`,
      `aab`, `aac`, `aacb`, `aacba`, `aacbaa`, `aacbaab`, `ab`, and `aba`.

      ### Solution — progressive tiers

      **① Brute force — collect, sort, pick, O(n³ log n)**

      Enumerate every distinct substring into a `set`, copy them into a list,
      sort, and return the k-th.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      int main() {
          ios::sync_with_stdio(false); cin.tie(nullptr);
          string s; long long k; cin >> s >> k;
          int n = (int)s.size();

          set<string> all;
          for (int i = 0; i < n; ++i) {
              string cur;
              for (int j = i; j < n; ++j) { cur += s[j]; all.insert(cur); }
          }
          vector<string> v(all.begin(), all.end());
          cout << v[k - 1] << "\n";
          return 0;
      }
      ```

      **O(n³ log n)** time (n² substrings, each O(n) to copy+compare) — fine for
      tiny inputs, hopeless at `n = 10^5` where the answer string alone dwarfs
      any feasible enumeration.

      **② Optimization — suffix array + Kasai LCP, O(n log n) (submission)**

      Sort the suffixes (doubling), compute the LCP array (Kasai), then walk the
      sorted suffixes accumulating the number of brand-new distinct substrings
      each introduces.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      int main() {
          ios::sync_with_stdio(false); cin.tie(nullptr);
          string s; long long k; cin >> s >> k;
          int n = (int)s.size();

          // Suffix array of s + '$' (sentinel), minimised via doubling.
          string t = s; t.push_back('$');
          int N = (int)t.size();
          vector<int> p(N), c(N);
          {
              vector<pair<char,int>> a(N);
              for (int i = 0; i < N; ++i) a[i] = {t[i], i};
              sort(a.begin(), a.end());
              for (int i = 0; i < N; ++i) p[i] = a[i].second;
              c[p[0]] = 0;
              for (int i = 1; i < N; ++i) c[p[i]] = c[p[i-1]] + (a[i].first != a[i-1].first);
          }
          for (int h = 0; (1 << h) < N; ++h) {
              for (int i = 0; i < N; ++i) p[i] = (p[i] - (1 << h) + N) % N;
              sort(p.begin(), p.end(), [&](int i, int j) {
                  return c[i] != c[j] ? c[i] < c[j]
                                      : c[(i + (1 << h)) % N] < c[(j + (1 << h)) % N];
              });
              vector<int> cn(N);
              cn[p[0]] = 0;
              for (int i = 1; i < N; ++i)
                  cn[p[i]] = cn[p[i-1]] + ( (c[p[i]] != c[p[i-1]])
                       || (c[(p[i] + (1 << h)) % N] != c[(p[i-1] + (1 << h)) % N]) );
              c = cn;
          }
          vector<int> sa;                       // drop the sentinel suffix (it ranks first)
          for (int i = 0; i < N; ++i) if (p[i] < n) sa.push_back(p[i]);

          // Kasai LCP over the original suffixes
          vector<int> rank(n), lcp(n, 0);
          for (int i = 0; i < n; ++i) rank[sa[i]] = i;
          int h = 0;
          for (int i = 0; i < n; ++i) {
              if (rank[i] > 0) {
                  int j = sa[rank[i] - 1];
                  while (i + h < n && j + h < n && s[i + h] == s[j + h]) ++h;
                  lcp[rank[i]] = h;
                  if (h) --h;
              }
          }

          long long run = 0;
          for (int r = 0; r < n; ++r) {
              long long fresh = (long long)(n - sa[r]) - lcp[r];
              if (k <= run + fresh) {
                  int need = (int)(k - run);     // 1-based rank among this suffix's fresh prefixes
                  cout << s.substr(sa[r], lcp[r] + need) << "\n";
                  return 0;
              }
              run += fresh;
          }
          return 0;
      }
      ```

      **O(n log n)** time, **O(n)** space — this is the submission tier.

      **③ Alternative — suffix automaton, O(n)**

      A suffix automaton encodes every distinct substring as a unique root-to-
      node path. Count, from each state, the number of distinct substrings
      reachable further (`total[v] = Σ_c (1 + total[next])`), then walk the
      automaton greedily by character, subtracting counts until `k` lands in a
      single transition — see the next lesson for the full SAM machinery. Linear
      time, and the natural choice when the alphabet order (not just distinct
      count) dominates the workload.

      # Code-logic

      The submission tier has three independent parts, each standard:

      - **Suffix array.** Appending `'$'` (a char smaller than all `a..z`) makes
        every suffix comparable without worrying about one being a prefix of
        another; sorting the `n+1` suffixes by 1-, 2-, 4-, ... character
        prefixes (doubling, `std::sort`, O(n log n)) yields `p`. Removing the
        sentinel entry leaves the suffix array of the original string.
      - **Kasai LCP.** `lcp[i]` = longest common prefix of the `i`-th and
        `(i-1)`-th sorted suffixes. Reusing the overlap height `h` as the index
        `i` moves through the original string makes the total work O(n).
      - **The scan.** For sorted suffix `r` (start `sa[r]`), the substrings it
        introduces span lengths `lcp[r]+1 .. n-sa[r]`; all shorter ones were
        introduced by the previous suffix. So `fresh = (n - sa[r]) - lcp[r]`
        distinct new substrings, all in lexicographic order. When `k` falls
        inside, the answer is the prefix of `s[sa[r]..]` of length
        `lcp[r] + (k - run)`.

      # Walkthrough

      **Input (sample):** `s = babaacbaab`, `k = 10`.

      Sorted suffixes (start indices) with LCP and fresh-substring counts:

      | r | sa[r] | suffix | lcp[r] | fresh = (n-sa[r])−lcp | running total |
      |---|-------|--------|--------|-------|---------------|
      | 0 | 7 | aab | 0 | 3 | 3 |
      | 1 | 3 | aacbaab | 2 | 5 | 8 |
      | 2 | 8 | ab | 1 | 1 | 9 |
      | 3 | 1 | abaacbaab | 2 | 7 | 16 |

      Walk:

      - **r = 0**: suffix `aab` (length 3), lcp 0 → fresh `3` substrings `a`,
        `aa`, `aab`. Running total `3`. Still `3 < 10`, continue.
      - **r = 1**: suffix `aacbaab` (length 7), lcp 2 (shares `aa` with the
        previous) → fresh `5` = `aac, aacb, aacba, aacbaa, aacbaab`. Total `8`.
      - **r = 2**: suffix `ab` (length 2), lcp 1 → fresh `1` = `ab`. Total `9`.
      - **r = 3**: suffix `abaacbaab` (length 9), lcp 2 → fresh `7` =
        `aba, abaa, abaac, abaacb, abaacba, abaacbaa, abaacbaab`. Total jumps to
        `16 ≥ 10`, so the answer is here. `need = k − run_before = 10 − 9 = 1`,
        i.e. the 1st fresh substring of this suffix → prefix of `abaacbaab` of
        length `lcp[3] + need = 2 + 1 = 3` = `aba`.

      The first 10 distinct substrings collected in this order are exactly
      `a, aa, aab, aac, aacb, aacba, aacbaa, aacbaab, ab, aba` (they interleave
      across the sorted suffixes, which is precisely why the LCP-based scan —
      not a per-suffix grouping — is required).
