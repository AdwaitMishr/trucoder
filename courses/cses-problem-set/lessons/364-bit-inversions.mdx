      ## Theory — long runs of equal bits under point flips

      We have a bit string; a single bit is flipped, and after every flip we must
      report the length of the **longest run** (maximal substring of identical
      bits). With `n, m ≤ 2·10^5`, recomputing the longest run from scratch after
      each of `m` flips is too slow, so we maintain the run structure
      incrementally.

      **Boundaries.** A flip at position `p` only touches the equality between
      `p` and its neighbours — bits `p-1/p` and `p/p+1`. So the set of "run
      boundaries" changes only locally. Define a **boundary** between indices
      `i` and `i+1` when `s[i] != s[i+1]`. Consecutive boundaries (with implicit
      boundaries at positions `1` and `n`) delimit the runs.

      **Key fact.** The run lengths are exactly the gaps between consecutive
      points of `{0} ∪ boundaries ∪ {n}`. Keeping the boundaries in a balanced
      BST (`std::set`) and the gap lengths in a `std::multiset` gives the answer
      in `O(log n)` per flip: when a boundary appears, split the gap that
      contained it into two; when it disappears, merge those two back.

      This is the classic "dynamic longest run / max adjacent difference" pattern,
      useful whenever a single point toggle only changes a few adjacent gaps.

      :::tip
      **Interview tip:** "After each update, report some adjacency property
      (longest equal run, largest gap, split count) is the signature of a
      balanced-tree + `multiset`-of-gaps solution: the update is *local*, only
      the two neighbours of the changed position are affected, and each costs
      `O(log n)`. Don't rescan."
      :::

      ## The Problem

      There is a bit string consisting of `n` bits. Some changes invert one given
      bit. After each change, report the length of the longest substring whose
      every bit is the same.

      **Input.** The first input line has a bit string consisting of `n` bits.
      The bits are numbered `1, 2, …, n`. The next line contains an integer `m`:
      the number of changes. The last line contains `m` integers
      `x₁, x₂, …, xₘ` — the changes (each is a bit position to invert).

      **Output.** After each change, print the length of the longest run.

      **Constraints**
      - `1 ≤ n ≤ 2·10^5`
      - `1 ≤ m ≤ 2·10^5`
      - `1 ≤ xᵢ ≤ n`

      **Sample**

      Input:
      ```
      001011
      3
      3 2 5
      ```

      Output:
      ```
      4 2 3
      ```

      *Explanation:* the bit string first becomes `000011` (long run 4), then
      `010011` (max 2), and finally `010001` (max 3).

      ### Solution — progressive tiers

      **① Brute force — O(n·m).** After each flip, scan the whole string and
      track the current run length plus the best seen so far.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          string s; cin >> s;
          int m; cin >> m;
          while(m--){
              int p; cin >> p;
              s[p-1] = (s[p-1]=='0')?'1':'0';
              int best = 0, cur = 0; char prev = 0;
              for(char c : s){
                  cur = (c==prev) ? cur+1 : 1;
                  prev = c;
                  best = max(best, cur);
              }
              cout << best << " ";
          }
      }
      ```
      *Complexity: O(n) per flip → O(n·m) total, far too slow for 2·10^5 flips.*

      **② Optimization — O((n+m) log n).** Maintain the run boundaries in a
      `std::set` and the gap (run) lengths in a `std::multiset`. Flipping bit `p`
      re-evaluates only the two adjacent boundaries. When a boundary appears we
      split one gap into two; when it vanishes we merge two gaps into one, then
      the answer is the largest gap.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          string s; cin >> s;
          int n = (int)s.size();
          int m; cin >> m;
          set<int> B;                 // boundaries stored as point (i+1)
          multiset<int> gaps; gaps.insert(n);   // one implicit run of length n
          auto add_p = [&](int p){
              auto it = B.lower_bound(p);
              int nxt = (it==B.end())? n : *it;
              int prv = (it==B.begin())? 0 : *prev(it);
              gaps.erase(gaps.find(nxt-prv));
              gaps.insert(p-prv); gaps.insert(nxt-p);
              B.insert(p);
          };
          auto del_p = [&](int p){
              auto it = B.find(p);
              int nxt = (next(it)==B.end())? n : *next(it);
              int prv = (it==B.begin())? 0 : *prev(it);
              gaps.erase(gaps.find(p-prv)); gaps.erase(gaps.find(nxt-p));
              gaps.insert(nxt-prv);
              B.erase(it);
          };
          for(int i=0;i<n-1;i++) if(s[i]!=s[i+1]) add_p(i+1);
          while(m--){
              int p; cin >> p; --p;
              s[p] = (s[p]=='0')?'1':'0';
              auto fix = [&](int i){
                  if(i<0 || i+1>=n) return;
                  bool b = (s[i]!=s[i+1]);
                  if(b && !B.count(i+1)) add_p(i+1);
                  else if(!b && B.count(i+1)) del_p(i+1);
              };
              fix(p-1); fix(p);
              cout << *gaps.rbegin() << " ";
          }
      }
      ```
      *Complexity: O(log n) per boundary change → O((n+m) log n) total, fast for
      2·10^5.*

      **③ Further optimization — segment tree.** We can avoid two containers by
      storing, in a segment tree, for each segment the longest prefix run,
      longest suffix run, and best internal run of equal bits; each flip is an
      `O(log n)` point update and the global answer is the root's best. Same
      complexity, one data structure — a clean alternative when you prefer a
      classic tree over coupled `set`/`multiset`.

      **④ Alternative.** Replace the `multiset` of gaps with a `std::map<length,
      count>` (a frequency table) plus a cached running maximum, still `O(log n)`
      per boundary event and slightly lower memory. The idea is identical — the
      multiset is the simplest choice, and the choice of container does not
      change the asymptotics.

      ## Code logic

      `solve` — ordered set + multiset of gaps. Key lines:

      1. **Boundary points.** Boundary between `s[i]` and `s[i+1]` is stored as
         the point `i+1` (the first index of the new run). Runs are the gaps of
         `{0} ∪ B ∪ {n}`.
      2. **`add_p(p)`.** Look up the neighbours of `p` in `B`. The current gap
         between them (`nxt - prv`) is erased from `gaps` and replaced by the two
         gaps `p - prv` and `nxt - p`; then `p` is inserted into `B`.
      3. **`del_p(p)`.** Mirror image: erase the two gaps adjacent to `p`, merge
         them into `nxt - prv`, and remove `p`.
      4. **Flipping.** After toggling `s[p]`, `fix(p-1)` and `fix(p)` recompute
         the two boundary pairs that can change, inserting or deleting points as
         needed.
      5. **Answer.** `*gaps.rbegin()` is the largest run length.

      ## Walkthrough

      **Input:** `s = 001011`, `m = 3`, changes `3 2 5` → expected `4 2 3`.

      Initial string `0 0 1 0 1 1`. Boundaries where neighbours differ: between
      2-3, 3-4, 4-5 → points `{3,4,5}`. Gaps of `{0,3,4,5,6}`: `3,1,1,2` → max 3
      (not printed).

      | step | flip | string | boundaries | gaps | max |
      |------|------|--------|------------|------|-----|
      | start | — | `001011` | 3,4,5 | 3,1,1,2 | 3 |
      | 1 | pos 3 | `000011` | 5 | 5,1 | **4** |
      | 2 | pos 2 | `010011` | 2,4,5 | 2,2,1,1 | **2** |
      | 3 | pos 5 | `010001` | 2,4 | 2,2,2 | **3** |

      After flip 1 (`000011`): only boundary at `5` → gaps `5, 1` → max 4 ✓.
      After flip 2 (`010011`): boundaries `2,4,5` → gaps `2,2,1,1` → max 2 ✓.
      After flip 3 (`010001`): boundaries `2,4` → gaps `2,2,2` → max 3 ✓.

      Both tiers agree: the brute scan (①) recomputes the max each time from
      scratch, while the boundary tier (②) only touches the two neighbour gaps —
      and both print `4 2 3`.
