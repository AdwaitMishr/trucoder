      # Planets and Kingdoms — strongly connected components

      A game has `n` planets joined by `m` one-way teleporters (edge `a → b`
      means you can travel from planet `a` to planet `b`). Two planets
      `a` and `b` are put in the **same kingdom** exactly when there is a route
      **both** from `a` to `b` **and** from `b` to `a` — that is, you can reach
      each one from the other.

      **The technique: strongly connected components (SCCs).** A *strongly
      connected component* is a maximal set of vertices where every vertex can
      reach every other vertex *within the set*. Every directed graph splits
      uniquely into SCCs; contract each SCC to a single node and the result is a
      **directed acyclic graph (DAG)** — so the graph's "skeleton" has no
      cycles even though the original may be full of them.

      **Why it matters:** in any SCC you can start anywhere and visit every
      vertex of the component (that is the very definition of mutual
      reachability). So an SCC behaves like one super-vertex. Many hard graph
      problems become easy once you compress SCCs.

      **Kosaraju's algorithm** (two DFS passes, `O(n + m)`):

      1. **DFS #1** on the graph, recording each vertex in a list *when its DFS
         finishes* (post-order / finish order).
      2. **DFS #2** on the **reverse graph** (every edge `u → v` flipped to
         `v → u`), processing vertices in **reverse finish order**. Each new DFS
         tree is exactly one SCC; give every vertex in it the same component id.

      The magic is that reversing the finish order and walking the reversed
      graph peels off SCCs one by one, in topological order of the condensation.

      **Worked mini-example.** Edges `1→2`, `2→3`, `3→1` put `{1,2,3}` in one
      strongly connected component: from any of them you can walk a cycle
      through all three. Add `3→4`, `4→5`, `5→4` and you get a second component
      `{4,5}` (you can go `4→5→4`). Vertex `1` reaches `4` but `4` cannot reach
      `1`, so they stay different kingdoms.

      **Complexity.** Two DFS passes → **O(n + m)** time, **O(n + m)** space
      (adjacency + reverse adjacency).

      :::tip
      **Interview tip:** "Is there a path from *every* node to *every* other
      node?" and "partition nodes into mutually reachable groups" are the
      classic SCC prompts. Reach for Kosaraju or Tarjan when a problem says two
      cities/people are "equal iff they can reach each other". Kosaraju is the
      easiest to explain on a whiteboard (two reverses); Tarjan is a single
      DFS. Interviewers often follow up with the condensation-DAG insight, so be
      ready to say what happens when you contract the SCCs.
      :::

      # Question — Planets and Kingdoms

      A game has `n` planets, connected by `m` teleporters. Two planets `a` and
      `b` belong to the same kingdom exactly when there is a route both from
      `a` to `b` and from `b` to `a`.

      Your task is to determine, for each planet, which kingdom it belongs to.

      **Constraints**

      - `1 ≤ n ≤ 10^5`, `1 ≤ m ≤ 2·10^5`
      - `1 ≤ a, b ≤ n` (a route goes `a → b`)

      **Input.** First line: `n` and `m`. Then `m` lines describing the
      teleporters; each line has two integers `a` and `b` meaning you can
      travel from planet `a` to planet `b`.

      **Output.** First print an integer `k` — the number of kingdoms. Then
      print, for each planet `1..n`, a kingdom label between `1` and `k`.
      Any valid labelling is accepted.

      Sample input:

      ```
      5 6
      1 2
      2 3
      3 1
      3 4
      4 5
      5 4
      ```

      Sample output:

      ```
      2
      1 1 1 2 2
      ```

      Here `{1,2,3}` is one kingdom (the cycle `1→2→3→1`) and `{4,5}` is
      another (the cycle `4→5→4`).

      ### Solution — progressive tiers

      **① Brute force — BFS reachability per planet, O(n·(n+m))**

      A planet `v` is in planet `u`'s kingdom iff `u` reaches `v` *and* `v`
      reaches `u`. So scan each unassigned planet `c`, compute the set of nodes
      reachable from `c` (one BFS) and the set of nodes that can reach `c`
      (one BFS on the reversed graph), then union — a new kingdom is the
      intersection.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      vector<char> reach(int s, int n, const vector<vector<int>>& g) {
          vector<char> r(n + 1, 0);
          queue<int> q; q.push(s); r[s] = 1;
          while (!q.empty()) {
              int u = q.front(); q.pop();
              for (int v : g[u]) if (!r[v]) { r[v] = 1; q.push(v); }
          }
          return r;
      }

      int main() {
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n, m; cin >> n >> m;
          vector<vector<int>> g(n + 1), gr(n + 1);
          for (int i = 0; i < m; ++i) {
              int a, b; cin >> a >> b;
              g[a].push_back(b);
              gr[b].push_back(a);          // reversed graph
          }
          vector<int> comp(n + 1, 0);
          int k = 0;
          for (int c = 1; c <= n; ++c) {
              if (comp[c]) continue;
              vector<char> to = reach(c, n, g);      // reachable from c
              vector<char> from = reach(c, n, gr);   // can reach c
              ++k;
              for (int v = 1; v <= n; ++v)
                  if (to[v] && from[v]) comp[v] = k; // same kingdom as c
          }
          cout << k << "\n";
          for (int u = 1; u <= n; ++u) cout << (u > 1 ? " " : "") << comp[u];
          cout << "\n";
          return 0;
      }
      ```

      **O(n·(n+m))** — for every (possibly-empty) kingdom we run two BFSs of
      cost `O(n+m)`. Correct, but hopeless at `n = 10^5` (`10^5 × 10^5 ≈ 10^10`
      operations).

      **② Optimization — Kosaraju, O(n+m) (submission)**

      One DFS to get a finish order, one DFS on the reversed graph in reverse
      finish order to peel off SCCs. Each peeled component is a kingdom.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      int main() {
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n, m; cin >> n >> m;
          vector<vector<int>> g(n + 1), gr(n + 1);
          for (int i = 0; i < m; ++i) {
              int a, b; cin >> a >> b;
              g[a].push_back(b);
              gr[b].push_back(a);
          }
          // 1st pass: finish order on the graph
          vector<char> vis(n + 1, 0);
          vector<int> order; order.reserve(n);
          function<void(int)> dfs1 = [&](int u) {
              vis[u] = 1;
              for (int v : g[u]) if (!vis[v]) dfs1(v);
              order.push_back(u);
          };
          for (int u = 1; u <= n; ++u) if (!vis[u]) dfs1(u);
          // 2nd pass: reversed graph, reverse finish order => components 1..k
          int k = 0;
          vector<int> comp(n + 1, 0);
          function<void(int)> dfs2 = [&](int u) {
              comp[u] = k;
              for (int v : gr[u]) if (!comp[v]) dfs2(v);
          };
          for (int it = (int)order.size() - 1; it >= 0; --it) {
              int u = order[it];
              if (!comp[u]) { ++k; dfs2(u); }
          }
          cout << k << "\n";
          for (int u = 1; u <= n; ++u) cout << (u > 1 ? " " : "") << comp[u];
          cout << "\n";
          return 0;
      }
      ```

      **O(n + m)** time, **O(n + m)** space. This is the tier to submit.

      **③ Further optimization — iterative Kosaraju (stack-safe)**

      Recursive DFS can overflow the call stack on a long chain (e.g. a path of
      `10^5` planets). The same two passes run iteratively with explicit
      stacks — identical logic, no recursion-depth risk.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      int main() {
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n, m; cin >> n >> m;
          vector<vector<int>> g(n + 1), gr(n + 1);
          for (int i = 0; i < m; ++i) {
              int a, b; cin >> a >> b;
              g[a].push_back(b); gr[b].push_back(a);
          }
          // 1st pass: iterative post-order DFS
          vector<char> vis(n + 1, 0);
          vector<int> order;
          for (int s = 1; s <= n; ++s) {
              if (vis[s]) continue;
              vector<pair<int,int>> st;         // (vertex, next-neighbour index)
              st.push_back({s, 0}); vis[s] = 1;
              while (!st.empty()) {
                  auto [u, i] = st.back();
                  if (i < (int)g[u].size()) {
                      int v = g[u][i]; st.back().second++;
                      if (!vis[v]) { vis[v] = 1; st.push_back({v, 0}); }
                  } else {
                      order.push_back(u); st.pop_back();
                  }
              }
          }
          // 2nd pass: reverse graph, reverse finish order
          int k = 0; vector<int> comp(n + 1, 0);
          for (int it = (int)order.size() - 1; it >= 0; --it) {
              int s = order[it]; if (comp[s]) continue;
              ++k;
              vector<int> st(1, s); comp[s] = k;
              while (!st.empty()) {
                  int u = st.back(); st.pop_back();
                  for (int v : gr[u]) if (!comp[v]) { comp[v] = k; st.push_back(v); }
              }
          }
          cout << k << "\n";
          for (int u = 1; u <= n; ++u) cout << (u > 1 ? " " : "") << comp[u];
          cout << "\n";
          return 0;
      }
      ```

      **O(n + m)** time, **O(n + m)** space — same complexity, no recursion to
      overflow. Useful when the judge's stack is small or the graph is a long
      path.

      **④ Alternative — Tarjan's single-pass algorithm**

      Tarjan finds all SCCs in **one** DFS, tracking a `disc` (discovery time)
      and `low` (lowest ancestor reachable) for each vertex. A vertex is the
      "root" of an SCC when `low[u] == disc[u]`; then pop the SCC stack. It
      needs no reverse graph and no separate finish ordering.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      int main() {
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n, m; cin >> n >> m;
          vector<vector<int>> g(n + 1);
          for (int i = 0; i < m; ++i) {
              int a, b; cin >> a >> b; g[a].push_back(b);
          }
          int timer = 0, k = 0;
          vector<int> disc(n + 1, 0), low(n + 1, 0), comp(n + 1, 0);
          vector<char> inStack(n + 1, 0);
          stack<int> stk;
          function<void(int)> dfs = [&](int u) {
              disc[u] = low[u] = ++timer;
              stk.push(u); inStack[u] = 1;
              for (int v : g[u]) {
                  if (!disc[v]) { dfs(v); low[u] = min(low[u], low[v]); }
                  else if (inStack[v]) low[u] = min(low[u], disc[v]);
              }
              if (low[u] == disc[u]) {           // u is SCC root
                  ++k;
                  while (true) {
                      int w = stk.top(); stk.pop(); inStack[w] = 0;
                      comp[w] = k;
                      if (w == u) break;
                  }
              }
          };
          for (int u = 1; u <= n; ++u) if (!disc[u]) dfs(u);
          cout << k << "\n";
          for (int u = 1; u <= n; ++u) cout << (u > 1 ? " " : "") << comp[u];
          cout << "\n";
          return 0;
      }
      ```

      **O(n + m)** time, **O(n + m)** space — one pass and a single adjacency,
      at the cost of a slightly subtler invariant. Kosaraju and Tarjan both
      solve every SCC task; pick the one you can reproduce without errors.

      # Code-logic

      All four tiers output the same set of kingdoms (up to label ordering);
      they differ only in how they discover mutual reachability.

      - **Tier ① (brute force).** For the first unassigned planet `c`, one BFS
        on `g` finds every planet reachable *from* `c`; a second BFS on the
        reversed graph `gr` finds every planet that can reach *back to* `c`.
        The intersection `to[v] && from[v]` is precisely `c`'s strongly
        connected component — the whole kingdom — so those cells are stamped
        with a fresh id `k`. The loop skips already-stamped planets, so each
        component is processed exactly once.
      - **Tier ② (Kosaraju).** `dfs1` walks forward edges and appends a vertex
        *after* its neighbours (post-order): the first vertex to finish is the
        deepest in a DFS tree. Replaying the reverse graph in reverse finish
        order, each new `dfs2` tree stays trapped inside one SCC (because cross
        edges point "the wrong way" after reversal), so every tree is a kingdom.
        `comp` is filled with the running counter `k`, giving `k` kingdoms.
      - **Tier ③ (iterative).** `dfs1` replays post-order with an explicit stack
        of `(vertex, next-index)` pairs instead of recursion; `dfs2` floods the
        reverse graph with a plain stack. All logic matches tier ②.
      - **Tier ④ (Tarjan).** `low[u]` records the smallest discovery time of
        any vertex reachable from `u` within the current DFS tree and SCC stack.
        When `low[u] == disc[u]`, no ancestor can reach up through `u`, so
        `u` caps an SCC: pop it off the stack. The single DFS finds SCCs in
        reverse-topological order of the condensation — labels are still valid.

      Every tier reads the same input, prints `k`, then the per-planet label.

      # Walkthrough

      **Input (sample):**

      ```
      5 6
      1 2
      2 3
      3 1
      3 4
      4 5
      5 4
      ```

      Three cycles exist: `1→2→3→1`, `3→4→5→4`... but note `3 → 4`, `4 → 5`,
      `5 → 4`, and `3` is already in `{1,2,3}`. So the second cycle is really
      `{4,5}` (`4 → 5 → 4` and `4` also reaches `3`). There is no edge back
      from `{4,5}` into `{1,2,3}` **and** room back, so they stay separate:
      exactly **2 kingdoms**.

      Using Kosaraju (tier ②):

      | phase | action | result |
      |-------|--------|--------|
      | DFS1 finish order | post-order over forward edges | e.g. `4 5 3 2 1` (order depends on adjacency order) |
      | DFS2 on `gr`, reverse order | start at `1` → bounce `1,2,3` → comp 1 | `comp[1..3] = 1` |
      | continue reverse order | `4` → bounce `4,5` → comp 2 | `comp[4..5] = 2` |

      Output:

      ```
      2
      1 1 1 2 2
      ```

      **Expected `2 / 1 1 1 2 2` — Actual `2 / 1 1 1 2 2`. Match.**

      Sanity check on a trivial case: a single directed cycle `1→2→3→1` with no
      other edges → one kingdom, `1 / 1 1 1`. And two isolated nodes with no
      edges → each its own kingdom (a node trivially reaches itself), `2 / 1 2`.

    prompt: 'Why is contracting every strongly connected component guaranteed to leave a graph with no cycles (a DAG)?'
    options:
      - Because SCCs have no edges between one another at all
      - A directed cycle among components would mean the vertices of that cycle can reach one another end-to-end, so they would be one SCC — a contradiction, hence the condensation has no cycles

      - Because edges only ever go from lower-numbered to higher-numbered components

    explanation: If the condensation had a cycle C1 → C2 → ... → C1, then (picking one vertex in each) you could reach the next component's vertex and finally swing back to C1's vertex — so every vertex on the cycle can reach every other on it, and any two such components would actually be the single SCC containing all of them. Since SCCs are maximal, that is impossible; the condensation therefore has no directed cycles. This DAG property is what makes SCC condensation so useful for the next two lessons (topological DP on the compressed graph).
