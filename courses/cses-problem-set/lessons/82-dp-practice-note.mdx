      # Dynamic Programming — what we just built

      The previous four lessons each reached for a *different* DP structure. The
      real skill is choosing which one. Here is the map we used:

      | Problem | DP kind | State insight | Complexity |
      |---------|---------|---------------|------------|
      | Elevator Rides | **Subset (bitmask) DP** | who is already carried, `dp[mask]` | `O(2^n · n)` |
      | Counting Tilings | **Profile DP** | the thin frontier between columns, `dp[mask]` over rows | `O(m · 2^n · n)` |
      | Counting Numbers | **Digit DP** | position, previous digit, started, tight | `O(len · 10)` |
      | Increasing Subseq. II | **DP accelerated by Fenwick** | last element's value, `dp = 1 + sum of smaller` | `O(n log n)` |

      ## How to choose

      - **Small `n <= 20` and the decision is "which subset of items"?**
        → subset/bitmask DP. Encode the chosen set as an integer, add one item
        at a time, minimize/maximize a scalar riding along (`dp[mask]` may carry
        a second value as a tie-break, like the elevator's load).
      - **One dimension is tiny (`<= 10`) and the other is long?**
        → profile/broken-profile DP: sweep the long axis, put the thin axis in a
        bitmask, and keep only the boundary. Works for tiling, matching,
        grid-traversal counting.
      - **"How many integers in `[a,b]` with a digit-local property"?**
        → digit DP: write `f(N) = count[0..N]`, answer `f(b) - f(a-1)`, thread
        `tight` + `started`. Led by "no two adjacent equal digits".
      - **"Count sequences/subsequences where the DP recurrence sums over
        earlier, value-comparable states"?**
        → reorganize the DP value-axis and accelerate with a Fenwick/segment
        tree (with coordinate compression if values are large).

      ## Common threads

      1. **State must be a *sufficient* statistic.** You only keep what the
         future needs: the set already taken (subset DP), the frontier (profile
         DP), the previous digit (digit DP), the previous value's count (Fenwick
         DP). Everything else is discarded.
      2. **Process in an order where dependencies are already computed.**
         Masks in increasing order, columns left to right, digits most-to-least
         significant, array positions left to right.
      3. **Counts blow up** — reduce modulo `10^9 + 7` at every sum/update, and
         use `long long`.
      4. **Verify a tier against a brute force first.** Always write the obvious
         correct solution (the ① tier), then confirm your optimized tier matches
         it on small random inputs before trusting the fast one.

      ## Practice path

      Before moving on, re-derive each of the four solves from scratch on paper,
      then code them with your eyes closed:

      1. **Elevator Rides** — code the subset DP; check `4 10 / 4 8 6 1 → 2`.
      2. **Counting Tilings** — code the profile DP; check `4 7 → 781`.
      3. **Counting Numbers** — code the digit DP; check `123 321 → 171`.
      4. **Increasing Subsequence II** — code the Fenwick DP; check `2 1 3 → 5`.

      Then harden yourself: run each against the brute-force tier on a few dozen
      random tiny inputs and confirm they always agree. If they do, you own the
      technique — not just the code.

      These four transfer directly to further DP problems (knapsack-family
      subset DP, grid/profile DP on boards, digit constraints like
      divide-by-k), so treat this note as your reusable cheat sheet.
