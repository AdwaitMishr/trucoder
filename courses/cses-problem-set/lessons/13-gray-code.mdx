      # Gray Code

      A **Gray code** is an ordering of all `2^n` binary strings of length `n`
      such that any two **adjacent** strings differ in exactly **one bit**. The
      most common one is the *reflected binary Gray code*.

      Why do we care? In many real problems a Gray-code-like order is what you
      want — from error-correcting encoders to Karnaugh maps and rotating
      encoders in robotics that must never toggle two signals at once.

      ## The one-line formula

      The `i`-th Gray-code value (for `0 <= i < 2^n`) is

      ```
      g[i] = i ^ (i >> 1)
      ```

      where `^` is bitwise XOR. This maps the binary counting order `0,1,2,...`
      onto an order in which successive values differ by exactly one bit. Let's
      build it by hand for `n = 3`:

      | i (binary) | i >> 1      | i ^ (i>>1) | gray string |
      |------------|-------------|------------|-------------|
      | 000        | 000         | 000        | `000`       |
      | 001        | 000         | 001        | `001`       |
      | 010        | 001         | 011        | `011`       |
      | 011        | 001         | 010        | `010`       |
      | 100        | 010         | 110        | `110`       |
      | 101        | 010         | 111        | `111`       |
      | 110        | 011         | 101        | `101`       |
      | 111        | 011         | 100        | `100`       |

      Read the string column top to bottom: `000, 001, 011, 010, 110, 111, 101,
      100` — every step changes exactly one bit. That is the classic reflected
      Gray code.

      ## Why it works (the reflection)

      Start with `n=1`: `0, 1`. To get `n+1`: take the `n`-code, then mirror it
      (reverse the order) and prepend `1` to the mirrored half, prepend `0` to
      the original half. `0,1` → prepend `0` to `0,1` and prepend `1` to the
      reverse `1,0` → `00,01,11,10`. The XOR formula produces exactly this
      pattern. Because the two halves join at two values that differ only in
      the new leading bit, the whole sequence still changes one bit at a time.

      **Complexity:** O(2^n) time to emit all `2^n` strings, each of length n —
      so O(n·2^n) characters total, which is optimal because that is the size
      of the output. Space O(n) besides the answer itself.

      :::tip
      **Interview tip:** The `i ^ (i>>>1)` one-liner is a classic whiteboard
      factoid — interviewers who ask "generate all n-bit Gray codes" expect
      exactly this. If they instead ask *"find the number that differs from a
      given value in exactly one bit"*, that's the inverse transformation:
      `i = gray; do { gray ^= gray >> 1; }` — know both directions.
      :::

      # The Problem

      A **Gray code** is a list of all `2^n` strings of length `n`, where any
      two successive strings differ in exactly one character (i.e. their Hamming
      distance is one). Your task is to create a Gray code for a given `n`.

      ## Input

      The only input line contains an integer `n`: the number of bits.

      **Constraints:** `1 <= n <= 16`

      ## Output

      Print `2^n` lines that describe a Gray code from the set `0, 1, ..., n-1`
      bits. Each line must be a string of `n` bits (`0`/`1`). The strings may be
      in any order, but two consecutive strings must differ in exactly one bit.

      ## Sample

      **Input:**
      ```
      2
      ```
      **Output:**
      ```
      00
      01
      11
      10
      ```

      ### Solution — four tiers

      All four approaches below are correct; they differ only in speed. The key
      fact every tier relies on: the `2^n` binary strings, ordered so that
      adjacent strings flip exactly one bit, form a valid Gray code.

      **① Brute force — O(n·4ⁿ) worst case (DFS over the bit-flip graph).**
      Model the search as an exhaustive walk: start at `000...0`, and keep
      exploring unused strings that differ in exactly one bit, backtracking when
      a branch dead-ends. Because every neighbor test scans all `2^n` values,
      and the DFS explores the whole graph, this is correct — but it touches far
      more than the `2^n` outputs and becomes unusably slow for `n ≥ 12`.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      int m;
      vector<int> used, path;

      bool dfs() {
          if ((int)path.size() == m) return true;      // found a full ordering
          int u = path.back();
          for (int v = 0; v < m; v++) {                // try every candidate
              if (used[v]) continue;
              if (__builtin_popcount(u ^ v) != 1) continue;   // must flip 1 bit
              used[v] = 1; path.push_back(v);
              if (dfs()) return true;
              path.pop_back(); used[v] = 0;            // backtrack on dead end
          }
          return false;
      }

      std::vector<std::string> solve(int n) {
          m = 1 << n;
          used.assign(m, 0);
          path = {0};
          used[0] = 1;
          dfs();
          std::vector<std::string> res;
          for (int g : path) {
              std::string s(n, '0');
              for (int b = 0; b < n; b++)
                  if ((g >> (n - 1 - b)) & 1) s[b] = '1';
              res.push_back(s);
          }
          return res;
      }
      ```
      Complexity: O(n·4^n) worst case, O(2^n) space — too slow for the real
      `n ≤ 16` limit.

      **② Optimization — O(n·2ⁿ) (mirror-and-prepend recursion).** Build the
      code from the bottom up: the length-`k` code is the length-`(k-1)` code
      with `0` prepended, followed by the reversed length-`(k-1)` code with `1`
      prepended. This is exactly the reflection construction from the theory
      block, and each of the `2^n` strings is copied once.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      void reflect(int k, std::vector<std::string>& out) {
          if (k == 1) { out = {"0", "1"}; return; }
          std::vector<std::string> prev;
          reflect(k - 1, prev);
          out.clear();
          for (auto& s : prev) out.push_back("0" + s);
          for (auto it = prev.rbegin(); it != prev.rend(); ++it)
              out.push_back("1" + *it);                // mirrored, prepend '1'
      }

      std::vector<std::string> solve(int n) {
          std::vector<std::string> res;
          reflect(n, res);
          return res;
      }
      ```
      Complexity: O(n·2^n) time, O(n·2^n) space for the answer.

      **③ Further optimization — O(n·2ⁿ) (closed-form XOR).** The reflected
      code has a direct formula: the `i`-th value is `g = i ^ (i >> 1)`. No
      recursion, no mirroring — a single loop over `i`. This is the version to
      ship.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      std::vector<std::string> solve(int n) {
          std::vector<std::string> res;
          res.reserve(1 << n);
          for (int i = 0; i < (1 << n); i++) {
              int g = i ^ (i >> 1);          // reflected Gray code value
              std::string s(n, '0');
              for (int b = 0; b < n; b++)    // MSB first
                  if ((g >> (n - 1 - b)) & 1) s[b] = '1';
              res.push_back(s);
          }
          return res;
      }
      ```
      Complexity: O(n·2^n) time, O(n) extra space. Optimal output size is the
      floor, so this cannot be beat asymptotically.

      **④ Alternative algorithm — O(n·2ⁿ) (single-bit-flip iteration).** A
      second correct construction that avoids the XOR formula: `Gray[0] = 0`,
      and for `i ≥ 1`, `Gray[i]` differs from `Gray[i-1]` in exactly the bit at
      the position of the **lowest set bit of `i`**. Flipping that bit each step
      reproduces the same sequence and only needs `__builtin_ctz`.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      std::vector<std::string> solve(int n) {
          int m = 1 << n;
          std::vector<int> g(m, 0);
          for (int i = 1; i < m; i++) {
              int b = __builtin_ctz(i);      // index of lowest set bit of i
              g[i] = g[i - 1] ^ (1 << b);    // flip exactly that bit
          }
          std::vector<std::string> res;
          for (int i = 0; i < m; i++) {
              std::string s(n, '0');
              for (int j = 0; j < n; j++)
                  if ((g[i] >> (n - 1 - j)) & 1) s[j] = '1';
              res.push_back(s);
          }
          return res;
      }
      ```
      Complexity: O(n·2^n) time, O(n·2^n) space for the answer. Correct and
      equivalent to the XOR version; useful when you want to generate codes
      incrementally without recomputing each next value from scratch.

      # Code logic

      The whole algorithm is inside one loop. For every counter value `i` from
      `0` to `2^n - 1`, we:

      1. **Fold it into a Gray code value** with `g = i ^ (i >> 1)`. The XOR of
         a number with itself shifted right one place flips bit `k` exactly when
         bits `k` and `k-1` of `i` differ — and because consecutive integers `i`
         and `i+1` differ in "the rightmost run of 1s," consecutive `g` values
         are guaranteed to differ in exactly one position.
      2. **Rasterize `g` to a string.** We need fixed width `n`, so we start
         from `"00...0"` and switch a `'1'` on wherever `g` has a bit, writing
         the most significant bit first (`s[0]` is the leftmost character).
      3. **Collect** the string in the answer vector.

      Because the tests ask for a `std::vector<std::string>` (the judge would
      print one string per line), that is exactly what `solve` returns — no
      extra newline handling needed.

      | 3 | 1    | 2            | `10`      | `10`   |

      Expected (sample) — lines `00 01 11 10`. Actual — `00 01 11 10`. Match.
      Consecutive lines differ in exactly one bit (`00→01`, `01→11`, `11→10`),
      which is precisely the definition of a Gray code.

      For `n=3`: `000 001 011 010 110 111 101 100` — again every adjacent pair
      flips a single bit, and the two halves (`000…010` and `110…100`) are
      mirror images prefixed with `0` vs `1`, as the reflection construction
      predicts.
