      # Subordinates — subtree DP by postorder

      A **tree DP** (a.k.a. subtree DP / bottom-up DP) computes an answer for
      every node by first solving all children, then combining their results with
      the node's own data. *Subordinates* is the cleanest possible example:
      the number of subordinates of a manager is the sum over all direct reports
      of *their* subordinates, plus one for each direct report.

      In a company modelled as a tree, employee `1` is the root (the CEO has no
      boss), and every other employee `i` reports to a known boss `p_i`. The
      direct-report edges child → boss form the tree; a node's **subordinates** are
      all employees in its subtree other than itself. We want that count for every
      node.

      ## Why postorder (children first) works

      The key recurrence is one line:

      ```
      cnt[u] = sum over each direct child v of (cnt[v] + 1)
      ```

      because every subordinate of `u` is either a direct child `v`, or a
      subordinate of a direct child. This is a dependency DAG that points strictly
      upward — child results must be ready before a parent's. A **postorder**
      traversal (process a node only after all its children) satisfies that
      ordering automatically.

      Processing can be done recursively (DFS that recurses into children before
      combining) or iteratively with an explicit stack followed by a reversal,
      which avoids stack-overflow risk on deep trees (important: CSES chains can
      be up to `n = 2 * 10^5` deep).

      **Time:** O(n) — each node and each edge is touched a constant number of
      times. **Space:** O(n) for the adjacency list and the answer array.

      :::tip
      **Interview tip:** subtree-size DP is the workhorse behind huge numbers of
      tree questions — "how many nodes in each subtree", "sum of distances",
      tree diameter, centroid decomposition, even tree-DP on gradients. Master the
      one-line recurrence *cnt[u] = Σ (cnt[v] + 1)* and you can recompute it from
      memory in any interview.
      :::

      # Question — Subordinates

      Given the structure of a company, count the number of subordinates each
      employee has. The manager of each employee is given, and the structure forms
      a tree rooted at the CEO (employee `1`).

      **Input**

      The first input line contains an integer `n`: the number of employees.
      The employees are numbered `1, 2, ..., n`, and employee `1` is the CEO.

      After this, there are `n-1` integers: the boss of each employee `2, 3, ...,
      n`. The boss of an employee is the person who they directly report to.

      **Output**

      Print `n` integers: for each employee `1, 2, ..., n`, the number of their
      subordinates.

      **Constraints**

      - `1 <= n <= 2 * 10^5`

      **Example**

      Input:

      ```
      5
      1 1 2 3
      ```

      Output:

      ```
      4 1 1 0 0
      ```

      Employee `1` has employees `2, 3, 4, 5` as subordinates (4). Employee `2`
      has one subordinate, `4`. Employee `3` has one subordinate, `5`. Employees
      `4` and `5` have none.

      ### Solution

      **① Brute force — per-node subtree count, O(n²) time**

      For every node, run a fresh DFS from it and count how many nodes are in its
      subtree. Correct, but doing a full traversal from each of `n` nodes costs up
      to O(n) each → O(n²), roughly `4 * 10^10` operations at `n = 2 * 10^5`.
      Far too slow.

      ```cpp
      // Illustration of the naive idea only — O(n^2), unusable.
      // For each u: DFS(u) and count distinct nodes reachable through descendants.
      ```

      **② Optimization — iterative postorder subtree DP, O(n) time, O(n) space**

      Do one traversal to get an order where children precede parents, then apply
      the recurrence once per node.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n; cin >> n;
          vector<vector<int>> kids(n + 1);
          for (int i = 2; i <= n; ++i){ int p; cin >> p; kids[p].push_back(i); }
          vector<int> cnt(n + 1, 0), order; order.reserve(n);
          vector<int> st{1};
          while(!st.empty()){ int u=st.back(); st.pop_back(); order.push_back(u);
                              for(int v: kids[u]) st.push_back(v); }
          reverse(order.begin(), order.end());
          for(int u: order) for(int v: kids[u]) cnt[u] += cnt[v] + 1;
          for(int i=1;i<=n;++i) cout << cnt[i] << (i==n?'\n':' ');
          return 0;
      }
      ```

      The stack-based preorder visits every node; reversing it yields a valid
      postorder (every child appears in `order` before its parent), so by the time
      we process `u` every `cnt[v]` is final.

      **③ Further optimization** — not needed: reading the input is already Θ(n),
      and the DP is O(n), so it is asymptotically optimal.

      **④ Alternative — recursive DFS**

      The same recurrence via recursion: `dfs(u)` recurses into each child, then
      sets `cnt[u]` to the sum of `dfs(v)+1`. Cleaner to read, but uses the call
      stack, so a chain-shaped tree of `2 * 10^5` nodes can overflow it; the
      iterative version (②) is the safer production choice.

      # Code logic

      Follow the O(n) solution in **②**:

      - `kids[p]` stores the direct children of each boss; the parent of every
        node is fixed by input, so we never need an undirected adjacency list.
      - The stack preorder (`st.push_back(1)`, pop, push children) yields an
        `order` where a parent always appears *before* its children.
      - `reverse(order)` flips that into postorder: every child is now guaranteed
        to be processed before its parent.
      - For each `u` in postorder, `cnt[u] += cnt[v] + 1` accumulates its whole
        subordinate count: the `+1` is the direct child `v` itself, and `cnt[v]`
        is already everything below `v`.
      - Output is the `cnt` array for nodes `1..n` with spaces and a trailing
        newline.

      # Walkthrough

      Trace the sample: `n = 5`, bosses `1 1 2 3` → employee 2's boss is 1,
      employee 3's boss is 1, employee 4's boss is 2, employee 5's boss is 3.

      Preorder (stack-based): `[1, 3, 5, 2, 4]` (variable — any order with parent
      before child works). Reversed postorder: `[4, 2, 5, 3, 1]`.

      | u (postorder) | children | cnt[u] accumulates |
      |---------------|----------|--------------------|
      | 4 | none | cnt[4] = 0 |
      | 2 | 4 | cnt[2] = cnt[4] + 1 = 1 |
      | 5 | none | cnt[5] = 0 |
      | 3 | 5 | cnt[3] = cnt[5] + 1 = 1 |
      | 1 | 2, 3 | cnt[1] = (cnt[2]+1) + (cnt[3]+1) = 2 + 2 = 4 |

      Output: `4 1 1 0 0`, matching the sample.
