      ## Theory — four ways to sort a permutation, four clean answers

      The input is a *permutation* `1..n`, and we must report the minimum number
      of operations to sort it under **four different move models**. Each model
      has a crisp combinatorial formula:

      **① Adjacent swaps → number of inversions.** A swap of neighbours changes
      the inversion count by ±1 and sorting needs 0 inversions, so the minimum is
      exactly the number of pairs `(i<j)` with `a[i] > a[j]` = **inversions**.
      Computed with a Fenwick tree in `O(n log n)`.

      **② Swap any two elements → `n − cycles`.** Write the permutation as a
      disjoint cycle decomposition. A swap merges or splits cycles by one; the
      cheapest way sorts a length-L cycle in `L−1` swaps. Total =
      `Σ (L_c − 1) = n − (#cycles)`.

      **③ Move any element to any other position → `n − LIS`.** The elements you
      *don't* move must already be in increasing order (relative order is
      preserved by insertions), so the kept set is the **longest increasing
      subsequence** (LIS). Everything else is extracted and reinserted → `n − |LIS|`.

      **④ Move any element to the front → `n − longest top-value suffix`.**
      Moves-to-front only grow prefixes, so what can stay in place is a suffix of
      the *largest* values `k, k+1, …, n` that already occur in increasing
      position order. Keep the longest such run scanning `n` downwards while
      `pos[val]` keeps decreasing.

      The insight connecting all four: **know which elements you can leave
      untouched**, then count only the forced moves — the invariant differs per
      model (inversion pairs vs. cycles vs. LIS vs. position order).

      :::tip
      **Interview tip:** This bundle tests the classic "sorting-metric"
      vocabulary: **inversions**, **cycle decomposition / minimum swaps**, and
      **LIS-based** move counts all recur in interviews (e.g. "minimum adjacent
      swaps to sort", "minimum arbitrary swaps", LeetCode 945/LIS-related). If
      the problem says *move to position*, think `n − LIS`; if it says *swap
      anywhere*, think `n − cycles`; if it says *adjacent*, think inversions.
      :::

      ## The Problem

      Here are some possible methods with which we can sort the elements of an
      array in increasing order:

      1. At each step, choose two adjacent elements and swap them.
      2. At each step, choose any two elements and swap them.
      3. At each step, choose any element and move it to another position.
      4. At each step, choose any element and move it to the front of the array.

      Given a permutation of numbers `1,2,…,n`, calculate the minimum number of
      steps to sort the array using each method.

      **Input.** The first input line contains an integer `n`. The second line
      contains `n` integers describing the permutation.

      **Output.** Print four numbers: the minimum number of steps using each
      method.

      **Constraints**
      - `1 ≤ n ≤ 2·10^5`

      **Sample**

      Input:
      ```
      8
      7 8 2 6 5 1 3 4
      ```

      Output:
      ```
      20 6 5 6
      ```

      ### Solution — progressive tiers

      **① Brute force — O(n²).** For method 1, count inversions by a double loop.
      For method 2, either simulate a swap-sorting (slow) or still use the cycle
      count (O(n)). For method 3, compute the LIS with an O(n²) DP. Method 4's
      prefix keeps the same O(n) suffix scan. Everything is correct, but the
      O(n²) inversion and O(n²) LIS die on `n = 2·10^5`.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      typedef long long ll;
      int main(){
          ios::sync_with_stdio(false); cin.tie(0);
          int n; cin>>n; vector<int> a(n);
          for(int i=0;i<n;i++) cin>>a[i];
          ll inv=0;                                   // method 1, O(n^2)
          for(int i=0;i<n;i++) for(int j=i+1;j<n;j++) if(a[i]>a[j]) ++inv;
          vector<char> vis(n+1,0); int cyc=0;         // method 2
          for(int i=1;i<=n;i++) if(!vis[i]){ ++cyc; int v=i; while(!vis[v]){vis[v]=1;v=a[v-1];} }
          int sw=n-cyc;
          vector<int> dp(n,1); int lis=1;             // method 3, O(n^2) LIS
          for(int i=0;i<n;i++){ for(int j=0;j<i;j++) if(a[j]<a[i]) dp[i]=max(dp[i],dp[j]+1); lis=max(lis,dp[i]); }
          int mpos=n-lis;
          vector<int> pos(n+1); for(int i=0;i<n;i++) pos[a[i]]=i;   // method 4
          int keep=1, cur=pos[n];
          for(int v=n-1;v>=1;v--){ if(pos[v]<cur){ ++keep; cur=pos[v]; } else break; }
          int mfront=n-keep;
          cout<<inv<<" "<<sw<<" "<<mpos<<" "<<mfront<<"\n";
      }
      ```
      *Complexity: O(n²) time — unusable at `n = 2·10^5`.*

      **② Optimization — O(n log n).** Replace the O(n²) parts: a **Fenwick
      tree** counts inversions in `O(n log n)`, and **patience sorting** finds
      the LIS in `O(n log n)`. Cycles and the move-to-front suffix scan were
      already O(n).

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      typedef long long ll;
      int main(){
          ios::sync_with_stdio(false); cin.tie(0);
          int n; cin>>n; vector<int> a(n);
          for(int i=0;i<n;i++) cin>>a[i];
          vector<int> bit(n+3,0);                     // Fenwick
          auto upd=[&](int i,int v){ for(;i<=n;i+=i&-i) bit[i]+=v; };
          auto qry=[&](int i){ int s=0; for(;i>0;i-=i&-i) s+=bit[i]; return s; };
          ll inv=0;                                   // method 1: inversions
          for(int i=0;i<n;i++){ inv+=(ll)i-qry(a[i]); upd(a[i],1); }
          vector<char> vis(n+1,0); int cyc=0;         // method 2: cycles
          for(int i=1;i<=n;i++) if(!vis[i]){ ++cyc; int v=i; while(!vis[v]){vis[v]=1;v=a[v-1];} }
          int sw=n-cyc;
          vector<int> tails;                          // method 3: LIS (patience)
          for(int x:a){ auto it=lower_bound(tails.begin(),tails.end(),x);
              if(it==tails.end()) tails.push_back(x); else *it=x; }
          int mpos=n-(int)tails.size();
          vector<int> pos(n+1); for(int i=0;i<n;i++) pos[a[i]]=i;
          int keep=1, cur=pos[n];                     // method 4
          for(int v=n-1;v>=1;v--){ if(pos[v]<cur){ ++keep; cur=pos[v]; } else break; }
          int mfront=n-keep;
          cout<<inv<<" "<<sw<<" "<<mpos<<" "<<mfront<<"\n";
      }
      ```
      *Complexity: O(n log n) time, O(n) space — instant for `n ≤ 2·10^5`.*

      **④ Alternative / note.** Each method already has its optimal linear-ish
      form; there is no further asymptotic tier. A useful mental cross-check: for
      a *reverse-sorted* permutation of `n` elements the four answers are
      `n(n-1)/2`, `n-1`, `n-1`, `n-1`; for the *identity* they are all `0` — good
      sanity cases for any implementation.

      ## Code logic

      One pass assembly of four independent counts:

      1. **Inversions (method 1):** scan left to right; `qry(a[i])` counts the
         elements `< a[i]` already seen; of the `i` prior elements, those not in
         that set exceed `a[i]` and are inversions with it → add `i - qry(a[i])`.
      2. **Cycles (method 2):** walk each unvisited value following
         `v = a[v-1]` until it returns home; each start is one cycle.
      3. **LIS (method 3):** patience-sort piles; `tails` stores the minimum tail
         of an increasing subsequence of each length, so its size is the LIS
         length. `lower_bound` keeps `tails` sorted and minimal.
      4. **Move-to-front (method 4):** scan values `n, n-1, …` keeping the
         longest run whose positions strictly decrease — those are precisely the
         top values already forming a sorted suffix. Everything else = one
         move-to-front each.

      ## Walkthrough

      **Input:** `n = 8`, `7 8 2 6 5 1 3 4` → expected `20 6 5 6`.

      Compute each method independently:

      - **Method 1 (adjacent swaps = inversions):** count pairs `a[i]>a[j]`.
        The total is **20** (largest in the sample).
      - **Method 2 (arbitrary swaps):** cycles: `1→6→4→8→2→3→7→1` (a 7-cycle)
        and `5→5` (fixed). `#cycles = 2`, so `n − cycles = 8 − 2 = 6`.
      - **Method 3 (move-to-position):** an LIS is `2 3 4` (length 3); also true
        LIS length = 3, so `n − LIS = 8 − 3 = 5`.
      - **Method 4 (move-to-front):** the top values `7 (pos 1), 8 (pos 2)`
        already sit in increasing position order; `6 (pos 4)` breaks the run.
        Keep length 2, so `n − 2 = 6`.

      Output: `20 6 5 6`. ✓ matches the sample. The brute tier (①) yields the same
      four numbers; only its inversion and LIS computations are quadratic.
