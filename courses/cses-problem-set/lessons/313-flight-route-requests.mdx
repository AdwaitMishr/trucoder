      ## Theory — each "tight" group costs its size, minus one if it is acyclic

      We must add the fewest **one-way connections** so that, for every request `(a, b)`, city `b` becomes
      reachable from city `a`. We may add *any* directed edges — not just the requested ones — and extra edges are
      fine as long as the count is minimal.

      Two requests `(a,b)` and `(b,a)` force a 2-cycle; more generally, treat each request as an **undirected**
      edge to group cities that are tangled together. Within one undirected component of size `V`:
      - If the directed request subgraph is **acyclic** (a DAG), we can realise every reachability with exactly
        `V − 1` edges: topologically sort the component and connect its nodes in a Hamiltonian path — every
        requested `a → b` still holds because `a` precedes `b` in topo order. Fewer than `V − 1` edges cannot
        even make the `V` mutually-requesting cities barely connected.
      - If the directed subgraph contains a **cycle**, `V` edges suffice (a cycle through the component realises
        all pairwise reachability), and `V − 1` is impossible — one edge must be "saved" to close the cycle
        demand.

      So the answer is `Σ_components ( V_c − [component is acyclic] )` — i.e. sum the sizes and subtract 1 for
      every component whose directed request subgraph has no directed cycle. Only cycle-detection is needed; no
      edge must actually be reconstructed.

      :::tip
      **Interview tip:** "Minimum edges to make every requested reachability true" decomposes along the
      *undirected* connected components of the requirement graph, and each component answers against one boolean
      — "does a directed cycle exist here?". Always ask whether a problem wants you to *count* an invariant rather
      than *build* the object.
      :::

      ## The Problem

      :::note
      **Concrete formulation.** This is the CSES problem *Flight Route Requests* (Advanced Graph Problems).
      :::

      There are `n` cities with airports but **no flight connections** yet. You are given `m` requests, where each
      request says a route must be possible to travel. Determine the **minimum number of one-way flight
      connections** that makes it possible to fulfil **all** requests.

      **Input.** The first line has two integers `n` and `m`: the number of cities and requests (cities numbered
      `1..n`). Then `m` lines, each with two integers `a b`: there must be a route from city `a` to city `b`.
      Each request is unique.

      **Output.** Print one integer: the minimum number of flight connections.

      **Constraints.**
      - `1 ≤ n ≤ 10^5`
      - `1 ≤ m ≤ 2·10^5`

      **Sample.**

      **Input:**
      ```
      4 5
      1 2
      2 3
      2 4
      3 1
      3 4
      ```

      **Output:**
      ```
      4
      ```

      *Explanation:* create `1→2`, `2→3`, `2→4`, `3→1` — then `3→4` works via `3→1→2→4`.

      ### Solution — progressive tiers

      **① Brute force — O(2^{n²}·xm).** Try every subset of the possible `n(n−1)` one-way edges and check whether
      its transitive closure contains every request; keep the smallest feasible subset. Correct but astronomically
      slow.

      ```cpp
      // conceptual — not runnable for real constraints
      // for mask in 0..2^{n(n-1)}:  build reachability of mask's edges, check all requests
      ```
      *Complexity: O(2^{n²}) — only for `n ≤ ~5`.*

      **② Optimization — undirected components + directed-cycle detection, O(n + m) (the solution).**
      Group cities by undirected connectivity of the requests. For each component in isolation, detect whether its
      directed subgraph contains a directed cycle; add `V` if it does, else `V − 1`.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int n,m;
      vector<int> adj[100005];   // directed requests
      vector<int> und[100005];   // undirected (component) adjacency
      int visUnd[100005];
      int color[100005];         // 0=white 1=gray 2=black  (cycle detection)
      int comp[100005]; int cc;  // nodes of current component
      int hasCycle;
      void dfsUnd(int u){ visUnd[u]=1; comp[cc++]=u;
          for(int v: und[u]) if(!visUnd[v]) dfsUnd(v); }
      void dfsDir(int u){ color[u]=1;
          for(int v: adj[u]){
              if(color[v]==1) hasCycle=1;
              else if(color[v]==0) dfsDir(v);
          }
          color[u]=2; }
      int main(){ ios::sync_with_stdio(false); cin.tie(nullptr);
          cin>>n>>m;
          for(int i=0;i<m;i++){int a,b;cin>>a>>b; adj[a].push_back(b); und[a].push_back(b); und[b].push_back(a);}
          long long ans=0;
          for(int s=1;s<=n;s++) if(!visUnd[s]){
              cc=0; dfsUnd(s); int V=cc;
              for(int i=0;i<cc;i++) color[comp[i]]=0;
              hasCycle=0;
              for(int i=0;i<cc;i++) if(color[comp[i]]==0) dfsDir(comp[i]);
              ans += hasCycle ? V : V-1;
          }
          cout<<ans<<"\n";
          return 0;
      }
      ```
      *Complexity: O(n + m) time, O(n + m) memory — each vertex and edge is touched a constant number of times.*

      **③ Alternative — a single fused DFS.** Instead of a separate cycle-check DFS, one Kosaraju-style sweep
      (undirected `dfs1` for the component + directed `dfs2` returning whether a back-edge was seen) computes the
      same boolean in one pass. Same `O(n + m)`.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int n,m,vis[100005]; vector<int> adj[100005], adj2[100005]; // adj=directed, adj2=undirected
      int sz; vector<int> stk;
      void dfs1(int u){ sz++; vis[u]=1; for(int v:adj2[u]) if(!vis[v]) dfs1(v); stk.push_back(u); }
      bool dfs2(int u){ vis[u]=2; bool ok=false;
          for(int v:adj[u]){ if(vis[v]==1) ok=dfs2(v)||ok; else if(vis[v]==2) ok=true; }
          vis[u]=3; return ok; }
      int main(){ ios::sync_with_stdio(false); cin.tie(0);
          cin>>n>>m;
          for(int i=0;i<m;i++){int a,b;cin>>a>>b; adj[a].push_back(b); adj2[a].push_back(b); adj2[b].push_back(a);}
          long long ans=0;
          for(int i=1;i<=n;i++) if(!vis[i]){
              sz=0; dfs1(i); bool ok=false;
              while(!stk.empty()){ int u=stk.back(); if(vis[u]==1) ok=dfs2(u)||ok; stk.pop_back(); }
              ans += ok ? sz : sz-1;
          }
          cout<<ans; }
      ```
      *Complexity: O(n + m) time — an even more cache- and code-friendly single pass.*

      ## Code logic

      The key block (tier ②), `solve` — O(n + m):
      1. **`und[a] ↔ und[b]`** stores every request symmetrically, exposing the undirected connected components.
      2. **`dfsUnd(s)`** gathers the node set `comp[0..cc)` and the component size `V = cc`.
      3. **`color[·]`** is reset to 0 for that component's nodes only; **`dfsDir`** runs over the *directed*
         request edges, and `color[v]==1` (a back edge) sets `hasCycle = 1`.
      4. **`ans += hasCycle ? V : V-1`** is the whole payoff: size count, minus 1 exactly when the component is a
         DAG.

      ## Walkthrough

      **Input:** `n = 4, m = 5`, requests `1→2, 2→3, 2→4, 3→1, 3→4`.

      Undirected edges: `1-2, 2-3, 2-4, 3-1, 3-4` — all four cities form one component, `V = 4`.

      Directed edges within it: `1→2, 2→3, 2→4, 3→1, 3→4`. Running `dfsDir` from city 1: `1→2→3→1` is a back edge
      (`3` is already gray when `3→1` is scanned → `color[1]==1`), so `hasCycle = 1`.

      Answer = `V = 4` ✓. Concretely the 4 connections are `1→2, 2→3, 2→4, 3→1`; the request `3→4` is then
      satisfied by the route `3→1→2→4`, so no fifth connection is needed.
