      # Dynamic Range Sum Queries

      **The technique: the Fenwick tree (Binary Indexed Tree).** When the array
      **can change** between queries — a point update, then a range sum — prefix
      sums no longer work: each update would require rewriting many prefix
      entries. A Fenwick tree keeps the array inside a clever tree-shaped
      accumulator where **both** a point update and a prefix sum cost **O(log n)**
      by walking the `i & -i` pointer (least-significant-bit) up and down.

      ```
      add(i, delta):   for (; i <= n; i += i & -i) bit[i] += delta
      sum(i):          for (; i > 0;  i -= i & -i) s += bit[i]
      range(l, r) = sum(r) - sum(l - 1)
      ```

      `i & -i` isolates the lowest set bit (`lowbit`). In an update you climb up
      (`+= lowbit`) to every node that covers position `i`; in a prefix sum you
      descend (`-= lowbit`) through precisely the nodes whose union is
      `[1..i]`. Each walk touches O(log n) nodes.

      **When you reach for it.** Sequence of mixed point-upddate + prefix/range
      sum queries. Fenwick is the lightest such structure — minimal memory
      (a single `n+1` array), no build recursion, and very small constants.
      It is the go-to for inversion counting, and it generalizes to any
      *invertible, associative* operation (sum, xor, product).

      **Worked mini-example.** Start `[0,0,0]`. `add(2,5)` touches `bit[2]` and
      `bit[4]`; `add(2,−5)` cancels the same nodes. A prefix sum walks `bit`
      read-only: `sum(3)` reads `bit[3] + bit[2]`.

      **Complexity.** O(log n) per update and per query, O(n) build/memory.
      For `q = 2·10^5` operations that is about `q·18 ≈ 3.6·10^6` steps.

      :::tip
      **Interview tip:** Fenwick is one of the most-asked "advanced" data
      structures. Strong answers emphasize *why* the diagram is a tree of binary
      intervals and *why* `i += i & -i` is the update climb. The key insight to
      state: `bit[i]` holds the sum of an interval ending at `i` of length equal
      to `i`'s lowest set bit. Interviews often pair it with an inversion-count /
      count-of-smaller-elements problem, and follow-ups probe its limits: range
      *min* is not directly supported (min has no inverse — that is a segment
      tree job, next lesson), while range *update + point query* and 2D Fenwick
      are natural extensions. It is the standard answer where the input size is
      too large for a balanced BST but you only need prefix aggregates.
      :::

      # Question — Dynamic Range Sum Queries

      Given an array of `n` integers, your task is to process `q` queries of
      two types:

      1. `1 k u` — update the value at position `k` to `u`
      2. `2 a b` — what is the **sum** of values in the range `[a, b]`?

      **Constraints:**
      - `1 ≤ n, q ≤ 2·10^5`
      - `1 ≤ x[i], u ≤ 10^9`
      - `1 ≤ k ≤ n`, `1 ≤ a ≤ b ≤ n`

      **Input:** the first line has `n` and `q`. The second line has the `n`
      values. Then `q` lines, each either `1 k u` or `2 a b`.

      **Output:** print the result of each type-2 query.

      Sample input:

      ```
      8 4
      3 2 4 5 1 1 5 3
      2 1 4
      2 5 6
      1 3 1
      2 1 4
      ```

      Sample output:

      ```
      14
      2
      11
      ```

      ### Solution — progressive tiers

      **① Brute force — O(n·q)**
      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      int main() {
          ios::sync_with_stdio(false);
          cin.tie(nullptr);
          int n, q; cin >> n >> q;
          vector<long long> a(n + 1);
          for (int i = 1; i <= n; ++i) cin >> a[i];
          while (q--) {
              int t; cin >> t;
              if (t == 1) { int k; long long u; cin >> k >> u; a[k] = u; }
              else {
                  int l, r; cin >> l >> r;
                  long long s = 0;
                  for (int i = l; i <= r; ++i) s += a[i];
                  cout << s << '\n';
              }
          }
          return 0;
      }
      ```
      Updates O(1) (a single overwrite), queries O(n). With up to `q = 2·10^5`
      queries of length `n = 2·10^5` that is `4·10^10` — far too slow.

      **② Optimization — Fenwick tree, O(log n) per operation** (the chosen
      solution)
      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      using ll = long long;

      struct Fenwick {
          int n; vector<ll> bit;
          Fenwick(int n) : n(n), bit(n + 1, 0) {}
          void add(int i, ll delta) { for (; i <= n; i += i & -i) bit[i] += delta; }
          ll sum(int i) const { ll s = 0; for (; i > 0; i -= i & -i) s += bit[i]; return s; }
          ll range(int l, int r) const { return sum(r) - sum(l - 1); }
      };

      int main() {
          ios::sync_with_stdio(false);
          cin.tie(nullptr);
          int n, q; cin >> n >> q;
          Fenwick fw(n);
          for (int i = 1; i <= n; ++i) { ll x; cin >> x; fw.add(i, x); }
          while (q--) {
              int t; cin >> t;
              if (t == 1) {
                  int k; ll u; cin >> k >> u;
                  ll cur = fw.range(k, k);
                  fw.add(k, u - cur);          // delta = new - old
              } else {
                  int a, b; cin >> a >> b;
                  cout << fw.range(a, b) << '\n';
              }
          }
          return 0;
      }
      ```
      O(log n) per update and per query, O(n) build. Handles `q = 2·10^5`
      comfortably.

      **③ Further optimization — O(log n) is optimal here**
      For a fully dynamic sequence with point updates and range sums, no
      comparison-based structure beats Ω(log n) per operation (Fenwick, segment
      tree). A sqrt decomposition gives O(√n) and a balanced BST gives O(log n)
      with larger constants — so the Fenwick's O(log n) and tiny memory are
      already the target.

      **④ Alternative — segment tree, O(log n)**
      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      using ll = long long;

      int main() {
          ios::sync_with_stdio(false);
          cin.tie(nullptr);
          int n, q; cin >> n >> q;
          vector<ll> a(n);
          for (int i = 0; i < n; ++i) cin >> a[i];
          vector<ll> st(4 * n);
          function<ll(int,int,int)> build = [&](int node, int lo, int hi) {
              if (lo == hi) return st[node] = a[lo];
              int mid = (lo + hi) / 2;
              return st[node] = build(2*node, lo, mid) + build(2*node+1, mid+1, hi);
          };
          function<void(int,int,int,int,ll)> upd = [&](int node, int lo, int hi, int pos, ll u) {
              if (lo == hi) { st[node] = u; return; }
              int mid = (lo + hi) / 2;
              if (pos <= mid) upd(2*node, lo, mid, pos, u);
              else upd(2*node+1, mid+1, hi, pos, u);
              st[node] = st[2*node] + st[2*node+1];
          };
          function<ll(int,int,int,int,int)> qry = [&](int node, int lo, int hi, int l, int r) {
              if (r < lo || hi < l) return 0LL;
              if (l <= lo && hi <= r) return st[node];
              int mid = (lo + hi) / 2;
              return qry(2*node, lo, mid, l, r) + qry(2*node+1, mid+1, hi, l, r);
          };
          build(1, 0, n - 1);
          while (q--) {
              int t; cin >> t;
              if (t == 1) { int k; ll u; cin >> k >> u; upd(1, 0, n-1, k-1, u); }
              else { int a, b; cin >> a >> b; cout << qry(1, 0, n-1, a-1, b-1) << '\n'; }
          }
          return 0;
      }
      ```
      Same O(log n) bounds, recursive, ~4× the constants, 4× the memory of a
      Fenwick — but it is the *general* structure that also answers range
      minimum (no inverse needed), as the next lesson shows.

      # Code-logic

      The chosen tier is **② Fenwick**. Three pieces:

      - **`add(i, delta)`** climbs `i += i & -i`. `i & -i` is the lowest set bit,
        the width of the interval stored in `bit[i]`. Each step moves to the next
        node whose interval also contains position `i`; at most `log2 n` such
        nodes exist.
      - **`sum(i)`** descends `i -= i & -i`, summing the disjoint intervals that
        partition `[1..i]`. It is read-only; the same walk does not modify `bit`.
      - **`range(l,r) = sum(r) − sum(l−1)`** is the same prefix-minus trick from
        the static lesson, now on the Fenwick accumulators.
      - **Update as a delta:** the problem sets a value (`position k becomes u`),
        so we first read the current value `cur = range(k,k)` and push
        `u − cur` through `add`. That way existing sums stay correct.

      Note how the static prefix-sum solution (lesson 119) is exactly the case
      where no `add` ever happens after the build — the Fenwick is its dynamic
      generalization.

      # Walkthrough

      **Input:**
      ```
      8 4
      3 2 4 5 1 1 5 3
      2 1 4
      2 5 6
      1 3 1
      2 1 4
      ```

      The Fenwick is built by `add(i, x)` for each value, so `range(l,r)` always
      mirrors the current array `[3, 2, 4, 5, 1, 1, 5, 3]`:

      | op | effect on array | range query / result |
      |----|-----------------|----------------------|
      | `2 1 4` | – | range(1,4) = 3+2+4+5 = **14** |
      | `2 5 6` | – | range(5,6) = 1+1 = **2** |
      | `1 3 1` | pos 3: 4 → 1 (delta −3) | update via add(3, −3) |
      | `2 1 4` | array now `[3,2,1,5,1,1,5,3]` | range(1,4) = 3+2+1+5 = **11** |

      Result: `14 2 11` ✓. The key check: after the update to position 3, the
      third answer correctly reflects the new value, which a naive cached prefix
      array could not do without rebuilding.

      **Edge cases:** an update to the same value (`u == cur`) pushes delta 0 (a
      no-op); a single-point query `2 k k` is answered as `range(k,k)`.
