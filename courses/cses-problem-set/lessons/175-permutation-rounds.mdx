      # Permutation Rounds

      **The technique: cycle decomposition + LCM of cycle lengths.** A
      permutation `p[1..n]` maps "the element at position `i` moves to position
      `p[i]`". Re-applying the permutation over and over walks every element
      around the *cycles* of the permutation: `i → p[i] → p[p[i]] → … → i`.

      The sorted array `[1,2,…,n]` comes back to itself after `k` rounds **iff
      every cycle has a length dividing `k`** — and the first such `k` is the
      **least common multiple (LCM) of all cycle lengths**:

      ```
      answer = lcm( len(c1), len(c2), …, len(cc) )   mod 10^9 + 7
      ```

      This is the same "when do all planets align again" idea as the classic
      line-up/road-cycle problems: the whole arrangement is sorted again
      exactly when every individual closed loop completes a whole number of its
      own laps at once.

      **Why LCM mod is subtle.** You cannot compute the LCM with the naive
      `lcm(a,b) = a/gcd(a,b)·b` and take mod along the way: the true LCM of
      cycle lengths can be astronomically larger than `long long`, and mod does
      *not* distribute over division. The safe route is **prime factorization**:
      factor each cycle length into primes, keep the maximum exponent seen for
      every prime, and build the answer as `Π prime^maxExp mod MOD`.

      **When you reach for it.** Any "apply a fixed permutation repeatedly, how
      many applications until we return to the start" question — shuffles,
      card decks, rotating ciphers, scheduling rounds, functional-graph cycles.
      It also generalizes: "after how many rounds does position `i` come back to
      itself" is just its cycle's length.

      **Complexity.** Traversing the cycles is O(n). Factoring every distinct
      cycle length is O(total prime factors) ≤ O(n log n) with a
      smallest-prime-factor sieve. Total **O(n log n)** time, O(n) memory.

      :::tip
      **Interview tip:** "Repeatedly apply a permutation — when do we return to
      the start?" always means LCM of cycle lengths. Interviewers probe two
      traps: (1) a *single* element returns after its own cycle length, but the
      whole array needs the LCM; and (2) why plain `a/gcd·b` LCM breaks under a
      mod — the moment everything must be mod `10^9+7`, switch to prime-exponent
      maximums. Sieving smallest prime factors up to `n` is the standard
      enabler.
      :::

      # Question — Permutation Rounds (CSES 3398)

      There is a sorted array `[1, 2, …, n]` and a permutation
      `p[1], p[2], …, p[n]`. On each round, all elements move according to the
      permutation: the element at position `i` moves to position `p[i]`.

      After how many rounds is the array **sorted again for the first time**?

      **Input:** the first line has an integer `n`. The next line contains `n`
      integers `p[1], …, p[n]`.

      **Output:** print the number of rounds modulo `10^9 + 7`.

      **Constraints:**
      - `1 ≤ n ≤ 2·10^5`

      Sample input:

      ```
      8
      5 3 2 6 4 1 8 7
      ```

      Sample output:

      ```
      4
      ```

      Explanation: the array changes as follows after each round:
      - Round 1: `[6, 3, 2, 5, 1, 4, 8, 7]`
      - Round 2: `[4, 2, 3, 1, 6, 5, 7, 8]`
      - Round 3: `[5, 3, 2, 6, 4, 1, 8, 7]`
      - Round 4: `[1, 2, 3, 4, 5, 6, 7, 8]`

      ### Solution — progressive tiers

      **① Brute force — simulate rounds until sorted, O(LCM·n)**
      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      using ll = long long;
      int main() {
          int n; cin >> n;
          vector<int> p(n + 1); for (int i = 1; i <= n; i++) cin >> p[i];
          vector<int> a(n + 1); for (int i = 1; i <= n; i++) a[i] = i;
          auto sorted = [&]() { for (int i = 1; i <= n; i++) if (a[i] != i) return false; return true; };
          vector<int> b(n + 1);
          ll round = 0;
          do {
              for (int i = 1; i <= n; i++) b[p[i]] = a[i];  // element at i -> position p[i]
              a = b; round++;
          } while (!sorted());
          cout << round << '\n';
      }
      ```
      One round per LCM step. The LCM of cycle lengths up to `2·10^5` can be
      enormous (far larger than any 64-bit integer), so this never terminates
      in general — only works when the LCM happens to be tiny.

      **② Optimization — cycle lengths, then LCM by prime exponents, O(n log n)**
        (the chosen solution)
      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      using ll = long long;
      const ll MOD = 1e9 + 7;

      int main() {
          ios::sync_with_stdio(false);
          cin.tie(nullptr);
          int n; cin >> n;
          vector<int> p(n + 1);
          for (int i = 1; i <= n; i++) cin >> p[i];

          // smallest prime factor sieve up to n
          vector<int> spf(n + 1);
          for (int i = 0; i <= n; i++) spf[i] = i;
          for (int i = 2; i * i <= n; i++)
              if (spf[i] == i)
                  for (int j = i * i; j <= n; j += i)
                      if (spf[j] == j) spf[j] = i;

          vector<int> mx(n + 1, 0);              // max exponent per prime
          vector<char> vis(n + 1, 0);
          for (int s = 1; s <= n; s++) {
              if (vis[s]) continue;
              int v = s, len = 0;
              do { vis[v] = 1; v = p[v]; len++; } while (v != s);   // walk cycle
              int x = len;
              while (x > 1) {                    // factorize length
                  int pr = spf[x], e = 0;
                  while (x % pr == 0) { x /= pr; e++; }
                  mx[pr] = max(mx[pr], e);
              }
          }
          auto modpow = [&](ll a, ll e) {
              ll r = 1; while (e) { if (e & 1) r = r * a % MOD; a = a * a % MOD; e >>= 1; } return r;
          };
          ll ans = 1;
          for (int pr = 2; pr <= n; pr++)
              if (mx[pr] > 0) ans = ans * modpow(pr, mx[pr]) % MOD;
          cout << ans << '\n';
          return 0;
      }
      ```
      O(n) for the cycles plus O(n log n) for the sieve + per-length
      factorization. This is the safe way to do LCM modulo a prime.

      **③ Further optimization — none needed**
      The cycle traversal is O(n) and the sieve is O(n log log n);
      the result is already optimal. There is no faster closed-form for an LCM
      of many values.

      **④ Alternative — none distinct**
      The naive `lcm(a,b) = a/gcd(a,b)·b` is perfectly fine when the resulting
      LCM fits in `long long`, but here it cannot be embedded: the true LCM may
      overflow 64-bit, and you cannot take `% MOD` partway because the integer
      division `l / gcd(l,x)` cannot be split by a modulus. For an
      LCM mod `10^9+7` there is no closed-form shortcut — prime-exponent
      factorization (as in ②) is the standard and only reliable route, so no
      distinct alternative tier is worth showing. Skip.

      # Code-logic

      The chosen tier is **②**. Three stages:

      - **Sieve:** `spf[i]` stores each number's smallest prime factor. Building
        it up to `n` lets us factor any cycle length in `O(π·log)`.
      - **Cycle walk:** from each unvisited start `s`, follow `v = p[v]` until
        returning to `s`, counting `len`. Each vertex belongs to exactly one
        cycle, so total work is O(n). We use `len` (not the elements) for LCM.
      - **Factorize each length:** for `pr = spf[x]`, count `e` occurrences,
        and store `mx[pr] = max(mx[pr], e)`. The maximum exponent across all
        cycles is exactly the exponent `pr` needs in the overall LCM.
      - **Rebuild:** `ans = Π pr^mx[pr] mod MOD` via fast exponentiation. This
        is the guaranteed-termination, overflow-free of the LCM.

      `vis[]` prevents revisiting cycles and `v = p[v]` is the single line that
      turns the permutation into a functional graph.

      # Walkthrough

      **Sample:** `n = 8`, `p = [5, 3, 2, 6, 4, 1, 8, 7]`. Expected `4`.

      Cycle decomposition (`i → p[i]`):

      | start | walk | length |
      |-------|------|--------|
      | 1 | 1→5→4→6→1 | 4 |
      | 2 | 2→3→2 | 2 |
      | 7 | 7→8→7 | 2 |

      Track max exponent per prime across the lengths `{4, 2, 2}`:

      | length | factorization | exponents |
      |--------|---------------|-----------|
      | 4 | 2² | 2:2 |
      | 2 | 2¹ | 2:1 |
      | 2 | 2¹ | 2:1 |

      `mx[2] = max over all = 2`. Answer `= 2² = 4`. ✓

      This matches the round-by-round simulation in the statement (array is
      sorted again first at round 4). The brute-force tier simulates `4` rounds
      and confirms: all tiers agree on the sample.
