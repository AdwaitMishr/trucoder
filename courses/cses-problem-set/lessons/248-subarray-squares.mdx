      # Subarray Squares — split a sequence into k pieces

      You have an array of `n` numbers and must divide it into **k contiguous
      subarrays**. The cost of a subarray is the **square of its sum**. You want
      the minimum total cost. This is the classic **`dp[k][n]` partitioning
      problem** and the flagship example for *two* DP accelerations: the
      **divide-and-conquer optimization** and the **convex hull trick**.

      ## The DP

      Let `pref[i] = x_1 + ... + x_i` be prefix sums. Let
      `dp[t][i]` = minimum cost to cover the first `i` elements with exactly `t`
      subarrays. The last of those `t` subarrays covers elements `[j+1, i]`, so

      ```
      dp[t][i] = min over j in [t-1, i-1] of  dp[t-1][j] + (pref[i] - pref[j])^2
      ```

      with `dp[0][0] = 0`. The answer is `dp[k][n]`. Filling this naively is
      `O(k·n²)`, and at `n = k = 3000` that is `2.7·10^10` — too slow.

      ## Why divide-and-conquer works (cost is Monge)

      The single-piece cost `cost(j, i) = (pref[i] - pref[j])^2` satisfies the
      **quadrangle / Monge inequality**: for `a <= b <= c <= d`,

      ```
      cost(b, c) + cost(a, d)  <=  cost(a, c) + cost(b, d)
      ```

      A Monge row-cost means the optimal split index for the current row is
      **monotone**: `opt[i] <= opt[i+1]`. We can exploit that with a recursive
      **divide-and-conquer** sweep that computes the middle of a range first,
      learns its optimal split, and shrinks the search interval for the two
      halves — `O(k·n log n)`.

      ## Why the convex hull trick works (expand the square)

      ```
      (pref[i] - pref[j])^2 = pref[i]^2  -  2·pref[i]·pref[j]  +  pref[j]^2
      ```

      So for a fixed `i`, `pref[i]^2` is a constant and the rest is a *line* in
      the variable `pref[i]` built from the previous row:

      ```
      dp[t][i] = pref[i]^2  +  min over j of  (  (dp[t-1][j] + pref[j]^2) - 2·pref[j]·pref[i] )
      ```

      Each `j` gives the line `y = m·x + b` with `m = -2·pref[j]`,
      `b = dp[t-1][j] + pref[j]^2`, evaluated at `x = pref[i]`. Because
      `x_i >= 1`, `pref` is strictly increasing, so slopes are added in
      **decreasing** order and queries arrive at **increasing** `x` — a
      monotone-deque CHT gives `O(k·n)`.

      **Complexities:** brute `O(k n²)`; divide-and-conquer `O(k n log n)`;
      convex hull `O(k n)`.

      :::tip
      **Interview tip:** when a partitioning DP has cost `(pref[i]-pref[j])^c`
      or any piecewise-nice cost, first check whether it is **Monge** (then
      divide-and-conquer applies, `opt` is monotone). If the square can be
      expanded into a linear form in `pref[i]`, the **convex hull trick** applies
      and is even faster. Learn to rewrite `(a-b)^2 = a^2 - 2ab + b^2` — it
      appears constantly in optimisation-DP interviews.
      :::

      # Question — Subarray Squares

      Given an array of `n` elements, your task is to divide it into `k`
      subarrays. The cost of each subarray is the **square of the sum** of the
      values in the subarray. What is the **minimum total cost** if you act
      optimally?

      **Input**

      The first input line has two integers `n` and `k`: the array elements and
      the number of subarrays.
      The second line has `n` integers `x_1, x_2, ..., x_n`: the contents of the
      array.

      **Output**

      Print one integer: the minimum total cost.

      **Constraints**

      - `1 <= k <= n <= 3000`
      - `1 <= x_i <= 10^5`

      **Example**

      Input:

      ```
      8 3
      2 3 1 2 2 3 4 1
      ```

      Output:

      ```
      110
      ```

      Explanation: an optimal solution is `[2,3,1]`, `[2,2,3]`, `[4,1]`, whose
      cost is `(2+3+1)^2 + (2+2+3)^2 + (4+1)^2 = 36 + 49 + 25 = 110`.

      ### Solution — Subarray Squares

      **① Brute force — O(k n²) time, O(n) space**

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      using ll = long long;
      const ll INF = (1LL << 62);

      int main() {
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n, k; cin >> n >> k;
          vector<ll> pref(n + 1, 0);
          for (int i = 1; i <= n; ++i) { ll x; cin >> x; pref[i] = pref[i - 1] + x; }

          vector<vector<ll>> dp(k + 1, vector<ll>(n + 1, INF));
          dp[0][0] = 0;
          for (int t = 1; t <= k; ++t)
              for (int i = 1; i <= n; ++i)
                  for (int j = 0; j < i; ++j) {
                      ll s = pref[i] - pref[j];
                      dp[t][i] = min(dp[t][i], dp[t - 1][j] + s * s);
                  }
          cout << dp[k][n] << "\n";
      }
      ```

      `O(k n²)` — at `n = k = 3000`, `2.7·10^10` operations. Too slow.

      **② Optimisation — divide-and-conquer, O(k n log n) time, O(n) space**

      Cost is Monge, so the optimal split `opt[i]` is monotone. Compute row `t`
      recursively, caching the feasible split range per index:

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      using ll = long long;
      const ll INF = (1LL << 62);

      int n, K;
      vector<ll> pref, dpP, dpC;

      void solve(int lo, int hi, int optLo, int optHi) {
          if (lo > hi) return;
          int mid = (lo + hi) >> 1;
          ll best = INF; int who = optLo;
          for (int j = optLo; j <= min(mid - 1, optHi); ++j) {
              if (dpP[j] == INF) continue;
              ll s = pref[mid] - pref[j];
              ll v = dpP[j] + s * s;
              if (v < best) { best = v; who = j; }
          }
          dpC[mid] = best;
          solve(lo, mid - 1, optLo, who);
          solve(mid + 1, hi, who, optHi);
      }

      int main() {
          ios::sync_with_stdio(false); cin.tie(nullptr);
          cin >> n >> K;
          pref.assign(n + 1, 0);
          for (int i = 1; i <= n; ++i) { ll x; cin >> x; pref[i] = pref[i - 1] + x; }
          dpP.assign(n + 1, INF); dpC.assign(n + 1, INF);
          dpP[0] = 0;
          for (int t = 1; t <= K; ++t) {
              fill(dpC.begin(), dpC.end(), INF);
              solve(1, n, 0, n);
              dpP.swap(dpC);
          }
          cout << dpP[n] << "\n";
      }
      ```

      **③ Further optimisation — convex hull trick, O(k n) time, O(n) space**

      Expand the square and keep the previous row as lines in the variable
      `x = pref[i]`. Slopes arrive in decreasing order and queries are at
      increasing `x`, so a monotone deque works:

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      using ll = long long;
      const ll INF = (1LL << 62);

      struct Line {                       // y = m*x + b
          ll m, b;
          Line(ll _m = 0, ll _b = INF) : m(_m), b(_b) {}
          long double xcross(const Line& o) const { return (long double)(o.b - b) / (m - o.m); }
          ll eval(ll x) const { return m * x + b; }
      };

      struct DequeCHT {                   // slopes DECREASING, queries x increasing
          deque<Line> dq;
          bool empty() const { return dq.empty(); }
          void add(Line nw) {
              while (dq.size() >= 2) {
                  Line l1 = dq[dq.size() - 2], l2 = dq.back();
                  if (l1.xcross(l2) >= l2.xcross(nw)) dq.pop_back();  // l2 useless
                  else break;
              }
              dq.push_back(nw);
          }
          ll query(ll x) {
              while (dq.size() >= 2 && dq[0].eval(x) >= dq[1].eval(x)) dq.pop_front();
              return dq[0].eval(x);
          }
      };

      int main() {
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n, k; cin >> n >> k;
          vector<ll> pref(n + 1, 0);
          for (int i = 1; i <= n; ++i) { ll x; cin >> x; pref[i] = pref[i - 1] + x; }

          vector<ll> dpP(n + 1, INF), dpC(n + 1);
          dpP[0] = 0;
          for (int t = 1; t <= k; ++t) {
              DequeCHT cht;
              for (int j = 0; j <= n - 1; ++j) {
                  // line for "last subarray covers [j+1, ...]": eval at x = pref[i]
                  if (dpP[j] != INF)
                      cht.add(Line(-2 * pref[j], dpP[j] + pref[j] * pref[j]));
                  if (cht.empty()) { dpC[j + 1] = INF; continue; }
                  dpC[j + 1] = pref[j + 1] * pref[j + 1] + cht.query(pref[j + 1]);
              }
              dpP.swap(dpC);
          }
          cout << dpP[n] << "\n";
      }
      ```

      **④ Alternative — Li Chao tree, O(k n log C)**. If the input allowed
      negative elements, `pref` could stop being monotone and the deque version
      breaks. A **Li Chao tree** handles arbitrary slopes and arbitrary query
      points in `O(log C)` each — the same expansion, no monotonicity required.
      For the always-positive CSES constraints the deque form is smallest and
      fastest; the Li Chao is the robust generalisation.

      # Code logic — Subarray Squares

      Focus on **③**, the convex hull trick:

      - `pref[i]` prefix sums let us express any subarray sum in O(1):
        `sum(j+1..i) = pref[i] - pref[j]`.
      - Expanding `(pref[i]-pref[j])^2 = pref[i]^2 - 2·pref[i]·pref[j] + pref[j]^2`
        separates the target index `i` from the decision index `j`. The `pref[i]^2`
        term is moved out of the `min`.
      - For each previous split `j` we insert the line `m = -2·pref[j]`,
        `b = dpP[j] + pref[j]^2`. Querying it at `x = pref[i]` yields
        `-2·pref[i]·pref[j] + dpP[j] + pref[j]^2`; adding `pref[i]^2` reconstructs
        the true cost. Taking the `min` across the hull is the `min` over `j`.
      - `x_i >= 1` means `pref` is strictly increasing, so we insert lines in
        strictly decreasing slope order and query at strictly increasing `x` —
        exactly the two preconditions of the monotone `DequeCHT`: lines added at
        the back (dropping any made useless by `l1.xcross(l2) >= l2.xcross(nw)`),
        and the front pointer advanced while the next line is better at the
        current `x`.
      - We only insert lines whose previous-row value is finite
        (`dpP[j] != INF`) so unreachable prefixes (`j < t-1`) never pollute the
        hull.
      - Row by row we swap `dpP`/`dpC`; after `k` rows, `dpP[n]` is the answer.

      **②** reaches the same answer with divide-and-conquer: compute `dpC[mid]`
      by scanning only splits in `[optLo, optHi]`, then recurse left with
      `[optLo, who]` and right with `[who, optHi]`. The Monge property is what
      justifies shrinking those ranges.

      :::tip
      **Interview question:** When should you pick divide-and-conquer DP instead
      of the convex hull trick? — If the cost expands to a linear form in `pref[i]`
      (like `(pref[i]-pref[j])^2`), CHT is faster (`O(k n)`). Use divide-and-conquer
      when the cost is Monge but *not* separable into a line per split, so CHT
      doesn't apply — e.g. median/window costs. Recognise both patterns.
      :::
