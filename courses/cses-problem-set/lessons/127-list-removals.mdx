      # List Removals — Fenwick kth remaining element

      We have a list of `n` integers. The task gives `n` positions; at each
      step we **remove the element at a given position** and report what we
      removed. The positions are always relative to the *current* list
      (elements are numbered `1..k` where `k` is the current size), so after
      each removal all later indices shift down by one.

      Naive removal from a vector is `O(n)` per step (shifting everything
      right of the gap). We need to answer all `n` removals faster. The trick:
      **the surviving elements keep their original order**, so "the element
      currently at position `p`" is exactly the **`p`-th element still present
      in the original array**. Find that element, report it, then mark it as
      gone — and the next `p` is measured among the survivors again.

      ## Marking presence with a Fenwick tree

      Maintain a Fenwick tree (`BIT`) where index `i` stores `1` if the
      original element `i` is still present, `0` if it has been removed. Then:

      - `sum(i)` = number of survivors among positions `1..i`;
      - the `p`-th remaining element is the smallest index `i` with
        `sum(i) >= p` (**kth order statistic**).

      To locate that `i`:

      - **binary search** on `i` using `sum(mid)` — `O(log^2 n)`;
      - or walk the tree from the top in `O(log n)` (Fenwick "find kth").

      After locating it, output the original value `x[i]` and set `i` inactive
      with `add(i, -1)`.

      **Time:** `O(n log n)` (binary-search kth variant `O(n log^2 n)`,
      still fine). **Space:** `O(n)`. The same "mark presence + find kth
      active" idea also solves order-statistic problems like Josephus queries.

      :::tip
      **Interview tip:** "remove elements at dynamic positions, reporting
      them" decouples into: **(1)** a presence bit array, **(2)** a way to
      find the kth active index, **(3)** a way to flip a bit. Any structure
      that does step 2 in `O(log n)` — a Fenwick tree with binary search, the
      Fenwick kth-descent, or a segment tree — instantly turns the naive
      `O(n^2)` into `O(n log n)`. This "k-th remaining" pattern is the core of
      many deletion and order-statistic problems.
      :::

      # The Problem

      You are given a list consisting of `n` integers. Your task is to remove
      elements from the list at given positions, and report the removed
      elements.

      During the process, the elements are numbered `1, 2, ..., k` where `k`
      is the current size of the list.

      ## Input

      The first input line has an integer `n`: the initial size of the list.

      The second line has `n` integers `x_1, x_2, ..., x_n`: the contents of
      the list.

      The last line has `n` integers `p_1, p_2, ..., p_n`: the positions of the
      elements to be removed.

      **Constraints**

      - `1 <= n <= 2 * 10^5`
      - `1 <= x_i <= 10^9`
      - `1 <= p_i <= n - i + 1`

      ## Output

      Print the elements in the order they are removed.

      ## Example

      Input:

      ```
      5
      2 6 1 4 2
      3 1 3 1 1
      ```

      Output:

      ```
      1 2 2 6 4
      ```

      Explanation: The contents of the list are `[2,6,1,4,2]`, `[2,6,4,2]`,
      `[6,4,2]`, `[6,4]`, `[4]` and `[]`.

      ### Solution — progressive tiers

      **① Brute force — erase directly from a vector, O(n^2)**

      Keep a `std::vector`, and for each position `p` erase
      `v.begin() + (p - 1)`, printing the erased value. `erase` shifts all
      later elements, so each removal is `O(n)` and the total is `O(n^2)`.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main() {
          ios::sync_with_stdio(false); cin.tie(0);
          int n; cin >> n;
          vector<long long> v(n);
          for (auto &x : v) cin >> x;
          for (int t = 0; t < n; t++) {
              int p; cin >> p;
              auto it = v.begin() + (p - 1);
              cout << *it << " ";
              v.erase(it);
          }
          cout << "\n";
          return 0;
      }
      ```

      *`O(n^2)` — with `n = 2*10^5` that's ~`2 * 10^10` shifts. Too slow.*

      **② Optimization — Fenwick tree + binary search kth, O(n log n)**

      Keep a BIT where `1` means "still present". For each position `p`, binary
      search the smallest index `i` with `prefix(i) >= p`, report `x[i]`, then
      `add(i, -1)`. This is the optimal tier.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      using ll = long long;

      int main() {
          ios::sync_with_stdio(false); cin.tie(0);
          int n; cin >> n;
          vector<ll> x(n + 1);
          for (int i = 1; i <= n; i++) cin >> x[i];

          vector<int> bit(n + 1, 0);           // presence bits: 1 = still present
          auto add = [&](int i, int v) { for (; i <= n; i += i & -i) bit[i] += v; };
          auto sum = [&](int i) { int s = 0; for (; i > 0; i -= i & -i) s += bit[i]; return s; };
          for (int i = 1; i <= n; i++) add(i, 1);

          for (int t = 0; t < n; t++) {
              int p; cin >> p;                 // p-th remaining element (1-based)
              int lo = 1, hi = n;
              while (lo < hi) {                // smallest index with prefix >= p
                  int mid = (lo + hi) / 2;
                  if (sum(mid) >= p) hi = mid; else lo = mid + 1;
              }
              cout << x[lo] << " ";            // map active index back to original value
              add(lo, -1);                     // mark removed
          }
          cout << "\n";
          return 0;
      }
      ```

      *`O(n log^2 n)` with binary search (or `O(n log n)` with a Fenwick kth
      descent). Correct for `n = 2*10^5`.*

      **③ Further optimization — Fenwick kth descent, O(n log n)**

      Replace the `O(log n)` binary search inside a `O(log n)` prefix query
      (`O(log^2 n)`) with a single top-down walk over the BIT that finds the
      kth 1 in `O(log n)` — the classic "Fenwick lower_bound". Same structure,
      one fewer log factor.

      **④ Alternative — segment tree over counts**

      A segment tree where each node stores the *count of present elements*
      in its segment also answers "kth present index": descend to the leaf
      that contains the `p`-th `1` by comparing against the left child's
      count, then set it to `0` with a point update. `O(log n)` per removal —
      a fine alternative to the BIT, equally simple to reason about.

      # Code logic

      Focus on **②**:

      - **Presence bits.** `bit` starts with a `1` at every position (`add(i,
        1)` for all `i`). Removing position `i` flips it off with `add(i, -1)`.
        `sum(i)` is therefore exactly the number of survivors among the first
        `i` original slots.

      - **Finding the `p`-th remaining.** We need the smallest original index
        `i` where the number of survivors up to `i` is `>= p`. That predicate
        is monotone (prefix counts only grow with `i`), so binary search on
        `i` works: narrow `[lo, hi]` while `sum(mid) >= p`.

      - **Mapping index → value.** Original element values are stored in `x`
        (1-indexed). The found active index `lo` maps straight back to its
        original value `x[lo]` — we never physically delete from a container,
        we just stop counting that slot.

      - **State carries over.** Because we only toggle bits, subsequent
        positions are measured against the updated "still present" set, exactly
        like shrinking the real list.

      This is `O(n log^2 n)`; a Fenwick "find kth" descent (**③**) drops it
      to `O(n log n)`.
