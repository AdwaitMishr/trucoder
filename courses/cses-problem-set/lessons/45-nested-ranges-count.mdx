      # Nested Ranges Count

      **The technique: sort + Fenwick sweep counts containment per range.** This is the
      *counting* upgrade of Nested Ranges Check. There we only asked *whether* one range
      contains another or is contained. Here we must say **how many** ranges each range
      contains, and **how many** ranges contain it — two integers per range.

      The one-pass `maxR/minR` sweep from the *check* problem can only produce a yes/no.
      To count, we need a running *distribution* of the right endpoints we've already
      seen, and a way to ask "how many of them are to the left of (or equal to) a given
      value?" in logarithmic time. That is exactly a **Fenwick tree (BIT)** over the
      compressed right endpoints.

      If we sweep by `L` ascending (and `R` descending for equal `L`), then for the
      current range every previously seen range starts no later than it — so the count of
      earlier ranges whose right endpoint `≥ myR` is precisely **how many ranges contain
      me**. The mirroring sweep (`L` descending, `R` ascending), asking how many earlier
      ranges end at or before `myR`, gives **how many ranges I contain**.

      **When you reach for it:** any "count how many intervals contain / are contained /
      overlap each interval" query. The two ingredients — a well-chosen sort order and a
      Fenwick counting prefix sums over compressed coordinates — recur constantly in
      interval statistics and offline range-counting sweeps.

      **Worked mini-example.** Ranges `[1,6]`, `[2,4]`, `[3,6]`. Sort `L` asc / `R` desc:
      `[1,6]`, `[2,4]`, `[3,6]`.

      - `[1,6]`: no earlier ranges → 0 ranges contain it.
      - `[2,4]`: earlier `[1,6]` has `4 ≤ 6` → 1 range contains it.
      - `[3,6]`: earlier `[1,6]` has `6 ≤ 6` → 1 range contains it.

      **Complexity.** Two sorts + `O(log n)` per range per sweep → **O(n log n)** time,
      **O(n)** space.

      :::tip
      **Interview tip:** The jump from *check* to *count* is a classic escalation: a
      running extremum (maxR/minR) answers booleans, but *counting* forces a dynamic
      multiset, so reach for a Fenwick/segment tree over compressed values. Call out the
      two key decisions aloud: (1) tie-break equal `L` by putting the wider range first,
      and (2) only query the tree **before** inserting the current range, so a range never
      counts itself.
      :::

      # Question — Nested Ranges Count

      Given `n` ranges, count for each range **how many other ranges it contains** and
      **how many other ranges contain it**.

      Range `[a,b]` contains range `[c,d]` if `a ≤ c` and `d ≤ b`.

      **Constraints:** `1 ≤ n ≤ 2 * 10^5`, `1 ≤ x < y ≤ 10^9`. No range appears more
      than once.

      **Input:** the first line has `n`; then `n` lines, each with `x y` (the range
      `[x,y]`).
      **Output:** two lines of `n` integers each, in the input order.
      - Line 1: for each range (in input order), how many other ranges it contains.
      - Line 2: for each range (in input order), how many other ranges contain it.

      Sample input:

      ```
      4
      1 6
      2 4
      4 8
      3 6
      ```

      Sample output:

      ```
      2 0 0 0
      0 1 0 1
      ```

      # Solution — progressive tiers

      All versions below are *correct*; they differ only in how fast the per-range count
      is computed.

      **① Brute force — O(n²)**

      For each range, loop over every other range and count the two containment
      inequalities. Trivially correct, `O(n²)` — about 4·10¹⁰ comparisons at
      `n = 2·10^5`, far over the 1-second budget.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main() {
          int n; cin >> n;
          vector<int> a(n), b(n);
          for (int i = 0; i < n; i++) cin >> a[i] >> b[i];
          vector<int> contains(n, 0), contained(n, 0);
          for (int i = 0; i < n; i++)
              for (int j = 0; j < n; j++) {
                  if (i == j) continue;
                  if (a[i] <= a[j] && b[j] <= b[i]) contains[i]++;      // i contains j
                  if (a[j] <= a[i] && b[i] <= b[j]) contained[i]++;    // j contains i
              }
          for (int i = 0; i < n; i++) cout << contains[i] << (i + 1 == n ? '\n' : ' ');
          for (int i = 0; i < n; i++) cout << contained[i] << (i + 1 == n ? '\n' : ' ');
      }
      ```

      Time: **O(n²)**. Space: **O(n)**.

      **② Optimization — coordinate compress + Fenwick sweep, O(n log n)**

      Two linear sweeps, each backed by a Fenwick tree counting earlier right endpoints.

      - **`contained` sweep.** Sort `L` asc, `R` desc; sweep left to right. Before
        inserting the current range, every previously inserted range starts no later than
        it, so the number that contain it = the number of earlier ranges with `R ≥ myR` =
        `(already inserted) − (those with R < myR)` = `total − BIT.sum(rank(myR) − 1)`.
      - **`contains` sweep.** Sort `L` desc, `R` asc; sweep. Every previously inserted
        range starts no earlier than the current one, so the number it contains = number
        of earlier ranges with `R ≤ myR` = `BIT.sum(rank(myR))`.

      Right endpoints can be up to `10^9`, so compress them to ranks `1..m` first.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      struct R { int l, r, id; };
      struct Fenwick {
          int n; vector<int> bit;
          Fenwick(int n) : n(n), bit(n + 1, 0) {}
          void add(int i, int v) { for (; i <= n; i += i & -i) bit[i] += v; }
          int sum(int i) { int s = 0; for (; i > 0; i -= i & -i) s += bit[i]; return s; }
      };
      int main() {
          int n; cin >> n;
          vector<R> a(n);
          vector<int> xs; xs.reserve(n);
          for (int i = 0; i < n; i++) { cin >> a[i].l >> a[i].r; a[i].id = i; xs.push_back(a[i].r); }
          sort(xs.begin(), xs.end()); xs.erase(unique(xs.begin(), xs.end()), xs.end());
          auto rankOf = [&](int v) {
              return int(lower_bound(xs.begin(), xs.end(), v) - xs.begin()) + 1; };
          vector<int> contains(n, 0), contained(n, 0);
          int m = xs.size();

          sort(a.begin(), a.end(), [](const R& x, const R& y) {
              if (x.l != y.l) return x.l < y.l; return x.r > y.r; }); // L asc, R desc
          Fenwick f1(m); int total = 0;
          for (R& x : a) {
              int rk = rankOf(x.r);
              contained[x.id] = total - f1.sum(rk - 1);   // earlier with R >= mine
              f1.add(rk, 1); total++;
          }

          sort(a.begin(), a.end(), [](const R& x, const R& y) {
              if (x.l != y.l) return x.l > y.l; return x.r < y.r; }); // L desc, R asc
          Fenwick f2(m);
          for (R& x : a) {
              int rk = rankOf(x.r);
              contains[x.id] = f2.sum(rk);                // earlier with R <= mine
              f2.add(rk, 1);
          }

          for (int i = 0; i < n; i++) cout << contains[i] << (i + 1 == n ? '\n' : ' ');
          for (int i = 0; i < n; i++) cout << contained[i] << (i + 1 == n ? '\n' : ' ');
      }
      ```

      Time: **O(n log n)**. Space: **O(n)**.

      **③ Further optimization — single BIT, both answers in one sweep, O(n log n)**

      Instead of two sorts and two BITs, you can keep *one* BIT and one sort `(L asc,
      R desc)`, computing the `contains` answer with a second, separate structure or by
      processing a reversed pass with a re-used BIT. The constant factor / clarity gain is
      marginal; the two-pass `②` is more readable. Both are `O(n log n)`.

      Time: **O(n log n)**. Space: **O(n)**.

      **④ Alternative — segment tree over compressed R, O(n log n)**

      A **segment tree** storing the count of inserted right endpoints supports the same
      two operations — range-sum "how many `R` lie in `[value, ∞)`" and "how many `R` lie
      in `(−∞, value]`" — in `O(log n)`. Semantically identical to the Fenwick sweep; you
      simply query an interval instead of a prefix (Fenwick's prefix queries already
      cover both once you use the `total −` trick for the suffix side). Choose a Fenwick
      for its smaller constant and simpler code; a segment tree is the drop-in if you
      later need richer interval updates.

      Time: **O(n log n)**. Space: **O(n)**.

      # Code-logic

      Walk through the **② optimization** line by line (the Fenwick version).

      - `xs` collects every right endpoint; after `sort` + `unique`, `rankOf(v)` maps the
        raw `x..10^9` values onto a dense `1..m` index space so the BIT can be small and
        direct. This is the **coordinate compression** step.
      - **`contained` pass** — sort `L` asc / `R` desc, use `f1`:
        - `total` = how many ranges have been inserted so far (all start at or before the
          current `L`).
        - `f1.sum(rk - 1)` = how many inserted ranges have `R < myR`. Subtracting from
          `total` leaves how many inserted ranges have `R ≥ myR` — each of those starts no
          later than me *and* ends at or beyond me, i.e. each contains me.
        - `f1.add(rk, 1)` **after** querying → the current range never counts itself.
        - The `R` desc tie-break for equal `L` puts wider same-`L` ranges first, so a
          range is never "contained" by an equal-`L`-equal-`R` phantom (and inputs have no
          duplicate ranges).
      - **`contains` pass** — sort `L` desc / `R` asc, use `f2`:
        - Every inserted range starts at or beyond the current `L`. `f2.sum(rk)` counts
          how many of them have `R ≤ myR`; each is fully inside the current range → that's
          **how many the current range contains**.
        - Query-before-insert again prevents self-counting.
      - Both results land in `contains` / `contained` indexed by `id`, so order is
        restored for output.

      Total: two `O(n log n)` sorts and `O(n log n)` BIT work → **O(n log n)**.
