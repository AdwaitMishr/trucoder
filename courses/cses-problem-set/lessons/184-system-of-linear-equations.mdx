      # System of Linear Equations — Gaussian elimination over a modular field

      You are handed `n` equations in `m` unknowns, but every coefficient lives
      **modulo `10^9+7`**. You must find *any* solution vector `x`, or report
      that none exists.

      The workhorse is **Gaussian elimination**, the same algorithm you learn in
      a linear-algebra class — but adapted to a *finite field* instead of the
      real numbers.

      ## What "solving over a field" means

      A **field** is a set with `+` and `×` where every non-zero element has a
      multiplicative inverse. The integers modulo a prime `p`, written `Z_p`,
      form a field: every `a ≠ 0 (mod p)` has an inverse `a^−1`, computable by
      Fermat's little theorem as `a^(p−2) mod p`. Because division is always
      possible, the naive classroom algorithm works unchanged:

      - We may **swap** two rows (re-order equations).
      - We may **multiply** a row by any non-zero scalar (scale an equation).
      - We may **add** a multiple of one row to another (combine equations).

      None of these changes the *solution set*. Repeatedly applying them turns
      the augmented matrix `[A | b]` into **reduced row-echelon form (RREF)**:
      every pivot column has a single `1` and zeros everywhere else.

      ## Reading the answer off RREF

      - A row of the form `0 0 … 0 | b` with `b ≠ 0` is an impossible equation
        `0 = b` → **no solution**, print `-1`.
      - A column with a leading `1` is a **pivot variable** — its value is the
        `b` entry in that row.
      - A column without a leading `1` is a **free variable** — set it to `0`.
        With more variables than independent equations there are infinitely
        many solutions; any one of them is accepted.

      **Complexity.** Each pivot step normalises one row and sweeps one column,
      costing `O(n·m)`; there are at most `min(n,m)` pivots. Total `O(n·m·min(n,m))`
      `≈ O(n^3)` time, `O(n·m)` space. For `n,m ≤ 500` that is comfortably fast.

      :::tip
      **Interview tip:** "solve a linear system modulo a prime" is the archetypal
      linear-algebra interview problem — the interviewer wants to see that you
      can (1) spot it is a field, (2) write a modular inverse with fast
      exponentiation, and (3) do elimination without floating-point error.
      It also appears as a subroutine in things like Xor-basis and
      polynomial-interpolation problems.
      :::

      # Question — System of Linear Equations

      You are given `n·(m+1)` coefficients `a_{i,j}` and `b_i` which form the
      following `n` linear equations (all arithmetic mod `10^9+7`):

      - `a_{1,1}·x_1 + … + a_{1,m}·x_m = b_1`
      - `a_{2,1}·x_1 + … + a_{2,m}·x_m = b_2`
      - …
      - `a_{n,1}·x_1 + … + a_{n,m}·x_m = b_n`

      Your task is to find **any** `m` integers `x_1, …, x_m` that satisfy the
      given equations.

      **Input:** The first line has two integers `n` and `m`. The next `n` lines
      each have `m+1` integers `a_{i,1}, …, a_{i,m}, b_i`.

      **Output:** Print `m` integers `x_1, …, x_m` (with `0 ≤ x_i < 10^9+7`) that
      satisfy the equations. You can print any valid solution. If no solution
      exists, print only `-1`.

      **Constraints**

      - `1 ≤ n, m ≤ 500`
      - `0 ≤ a_{i,j}, b_i < 10^9 + 7`

      **Example**

      Input:

      ```
      3 3
      2 0 1 7
      1 2 0 0
      1 3 1 2
      ```

      Output:

      ```
      2 1000000006 3
      ```

      (That is `(x1,x2,x3) = (2, −1, 3)`: the second coordinate is written
      `−1 ≡ 1000000006 (mod 10^9+7)`.)

      ### Solution — progressive tiers

      **① Brute force — enumerate candidates, O(p^m)**

      Since every `x_i` lies in `[0, p)`, try every one of the `p^m` vectors and
      check all `n` equations. Correct but hopeless for `p = 10^9+7`.

      ```cpp
      // for illustration only — p^m candidates
      long long p = 1000000007LL;
      for (long long mask = 0; ; mask++) {   // pretending m small
          vector<long long> x(m);
          // fill x from mask digits base p ...
          bool ok = true;
          for (int i = 0; i < n; i++) {
              long long s = 0;
              for (int j = 0; j < m; j++) s = (s + x[j] * A[i][j]) % p;
              if (s != A[i][m]) { ok = false; break; }
          }
          if (ok) { print(x); return; }
      }
      ```

      Time `O(p^m · n)` — unusable for any realistic `m`.

      **② Optimization — Gaussian elimination in RREF, O(n·m·min(n,m))**

      Convert `[A | b]` to RREF over `Z_p`, reading the solution off directly.
      This is the intended, accepted solution.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      typedef long long ll;
      const ll MOD = 1000000007LL;

      ll modpow(ll b, ll e) {
          ll r = 1; b %= MOD;
          while (e) { if (e & 1) r = r * b % MOD; b = b * b % MOD; e >>= 1; }
          return r;
      }
      ll inv(ll a) { return modpow(a, MOD - 2); }   // Fermat, p prime

      int main() {
          ios::sync_with_stdio(false); cin.tie(0);
          int n, m;
          if (!(cin >> n >> m)) return 0;
          vector<vector<ll>> A(n, vector<ll>(m + 1));
          for (int i = 0; i < n; i++)
              for (int j = 0; j <= m; j++) cin >> A[i][j];

          vector<int> pivCol(n, -1);
          int pivRow = 0;
          for (int col = 0; col < m && pivRow < n; col++) {
              int sel = -1;
              for (int r = pivRow; r < n; r++) if (A[r][col]) { sel = r; break; }
              if (sel == -1) continue;              // free variable
              swap(A[pivRow], A[sel]);
              ll k = inv(A[pivRow][col]);
              for (int j = col; j <= m; j++) A[pivRow][j] = A[pivRow][j] * k % MOD;
              for (int r = 0; r < n; r++) {         // sweep column from all rows
                  if (r == pivRow) continue;
                  ll f = A[r][col];
                  if (!f) continue;
                  for (int j = col; j <= m; j++)
                      A[r][j] = (A[r][j] - f * A[pivRow][j] % MOD + MOD) % MOD;
              }
              pivCol[pivRow] = col;
              pivRow++;
          }
          // consistency: any zero-coefficient row with non-zero b?
          for (int r = pivRow; r < n; r++) {
              bool zero = true;
              for (int j = 0; j < m; j++) if (A[r][j]) { zero = false; break; }
              if (zero && A[r][m] != 0) { cout << -1 << "\n"; return 0; }
          }
          vector<ll> x(m, 0);
          for (int r = 0; r < pivRow; r++) x[pivCol[r]] = A[r][m];
          for (int j = 0; j < m; j++) cout << x[j] << (j + 1 == m ? "\n" : " ");
          return 0;
      }
      ```

      Time `O(n·m·min(n,m))`, space `O(n·m)`. For `n,m ≤ 500` this is instant.

      **③ Further optimization — none needed.**

      `O(n^3)` on a `500 × 500` matrix (`~1.25 × 10^8` modular operations) runs
      well inside CSES's 1 s limit. A partial-pivot-over-the-modulus trick and
      Gauss–Jordan done in place is already the tightest practical form.

      **④ Alternative — long-double Gaussian elimination (real field).**

      If the system were over the *reals* you could apply the identical
      algorithm with `long double` arithmetic and partial pivoting by largest
      absolute value (to control rounding). That is the classic floating-point
      variant — but modular arithmetic avoids rounding entirely and is what the
      judge wants here.

      # Code logic

      Focus on the `②` RREF solution:

      - **Pivot search.** For each column `col` we look for the first row `r ≥
        pivRow` whose `A[r][col]` is non-zero. Absent one, the column is *free* —
        we leave it and move to the next column (that variable will be set to
        `0`).
      - **Normalise.** `k = inv(A[pivRow][col])` multiplies the whole pivot row
        so the pivot entry becomes `1`. This needs modular inverse because the
        field has division.
      - **Sweep.** For every *other* row `r`, `f = A[r][col]` is subtracted as
        `f` copies of the pivot row, zeroing column `col` everywhere. Doing this
        for **all** rows (not just those below) yields the reduced form
        (Gauss–Jordan) and makes the solution read directly.
      - **Recording pivots.** `pivCol[pivRow] = col` remembers which column each
        pivot row controls. After the loop, `x[pivCol[r]] = A[r][m]`.
      - **Inconsistency.** Any leftover row (`r ≥ pivRow`) that is all-zero in
        the coefficients but has `A[r][m] ≠ 0` means `0 = b` — print `-1`.

      `long long` is required: products of two field elements (up to `10^9`)
      reach `10^18`, which overflows `int` but fits in 64 bits, and we reduce
      modulo `p` after every operation.

      # Walkthrough

      **Input**

      ```
      3 3
      2 0 1 7
      1 2 0 0
      1 3 1 2
      ```

      The rows are `2x+0y+z=7`, `x+2y+0z=0`, `x+3y+z=2` (mod `p`).

      Gauss–Jordan reduces the augmented matrix to RREF:

      | step | matrix `[A|b]` (rows) |
      |------|------------------------|
      | start | `[2 0 1 | 7]`, `[1 2 0 | 0]`, `[1 3 1 | 2]` |
      | pivot col 0 (row 0, ×`inv(2)`) | `[1 0 inv(2) | 7·inv(2)]` → `[1 0 500000004 | 500000004]` |
      | sweep col 0 | row1 `−= 1·row0`, row2 `−= 1·row0` |
      | … | the three pivots become isolated leading `1`s |
      | RREF | `[1 0 0 | 2]`, `[0 1 0 | 1000000006]`, `[0 0 1 | 3]` |

      Reading the last column: `x1 = 2`, `x2 = 1000000006`, `x3 = 3`.

      **Check** (mod `p`):
      - Eq1: `2·2 + 0·(−1) + 1·3 = 4 + 3 = 7` ✓
      - Eq2: `1·2 + 2·(−1) + 0·3 = 2 − 2 = 0` ✓
      - Eq3: `1·2 + 3·(−1) + 1·3 = 2 − 3 + 3 = 2` ✓

      The printed answer `2 1000000006 3` matches the sample output.
