      # Company Queries I — binary lifting for k-th ancestor

      We are asked, for many independent queries `(x, k)`, for the **k-th
      ancestor** of a node `x` (the `0`-th ancestor is `x` itself, the `1`-st is
      its parent). The challenge: up to `2 * 10^5` queries on a tree of up to
      `2 * 10^5` nodes, so climbing one parent at a time per query is too slow.

      ## Binary lifting in one line

      Precompute `up[i][j]` = the `2^j`-th ancestor of node `i`. Then to answer
      "k-th ancestor", look at the binary representation of `k` — each set bit `j`
      means "jump `2^j` steps up", and those jumps compose:

      ```
      up[i][j] = up[ up[i][j-1] ][j-1]      // 2^j = 2^(j-1) + 2^(j-1)
      ```

      Setting `up[i][0] = boss[i]` (the immediate parent), the whole table builds
      in O(n log n). A query then makes one jump per set bit of `k` — at most
      `log n` jumps → **O(log n) per query**.

      If a jump climbs past the root, we land on a sentinel (`0`); after processing
      all bits, if we reached the sentinel the answer is `-1`.

      **Total:** O((n + q) log n) time, O(n log n) space.

      :::tip
      **Interview tip:** binary lifting is the single most reusable tree
      technique for ancestor queries, LCAs (lowest common ancestor), and
      "x-th ancestor" / path-sum questions. The `up[i][j] = up[up[i][j-1]][j-1]`
      recurrence and the bit-by-bit jump are worth committing to memory; the same
      table powers LCA via "lift the deeper node, then lift both together".
      :::

      # Question — Company Queries I

      A company has `n` employees, numbered `1, 2, ..., n`. The company has a
      tree hierarchy: employee `1` is the CEO, and each other employee has a
      known boss. We are given `q` queries, each asking for a node's **k-th
      ancestor**.

      **Input**

      The first input line contains an integer `n`: the number of employees.

      The next line contains `n-1` integers: the boss of each employee `2, 3,
      ..., n`. The boss of an employee is the person they directly report to.

      The next line contains an integer `q`: the number of queries.

      After this, there are `q` lines describing the queries. Each line has two
      integers `x` and `k`: the k-th ancestor of employee `x`.

      **Output**

      For each query, print the k-th ancestor of `x`. If such an ancestor does
      not exist, print `-1`.

      **Constraints**

      - `1 <= n <= 2 * 10^5`
      - `1 <= q <= 2 * 10^5`
      - `1 <= x <= n`

      **Example**

      Input:

      ```
      5
      1 1 2 3
      3
      1 1
      2 0
      4 1
      ```

      Output:

      ```
      -1
      2
      2
      ```

      Query `1 1`: 1 is the CEO, it has no 1st ancestor → `-1`. Query `2 0`: the
      0-th ancestor of 2 is 2. Query `4 1`: the 1st ancestor (boss) of 4 is 2.

      ### Solution

      **① Brute force — climb one parent per step, O(n) per query**

      For each query, move `x` up `k` times along `boss[]`, printing `-1` if we
      leave the root first. Correct but O(k) per query, and `k` can be ~`n` with
      up to `2 * 10^5` queries → up to `4 * 10^10` steps. Too slow.

      ```cpp
      // Illustration of the naive idea only — O(n) per query, unusable.
      // while(k--){ if(x==0){x=-1;break;} x = boss[x]; }
      ```

      **② Optimization — binary lifting, O(log n) per query, O(n log n) total time, O(n log n) space**

      Build the `up` table, then answer each query bit by bit.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      const int LOG=19;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n,q; cin >> n;
          vector<vector<int>> up(n+1, vector<int>(LOG,0));
          for(int i=2;i<=n;++i){ int b; cin>>b; up[i][0]=b; }
          for(int j=1;j<LOG;++j)
              for(int i=1;i<=n;++i)
                  up[i][j] = up[ up[i][j-1] ][j-1];
          cin >> q;
          while(q--){
              int x,k; cin >> x >> k;
              for(int j=0; k; k >>= 1, ++j)
                  if(k & 1) x = up[x][j];
              cout << (x ? x : -1) << "\n";
          }
          return 0;
      }
      ```

      `LOG = 19` covers `2^18 = 262144 > 2 * 10^5` depth, and `up[root][*] = 0`
      so any jump past the root yields the sentinel `0` → `-1`.

      **③ Further optimization** — not needed: O(log n) per query is optimal since
      the query's answer genuinely depends on `log n` bits of `k`.

      **④ Alternative — Euler tour + RMQ / HLD** — heavier machinery
      (`O(n log n)` builds, `O(log n)` queries via heavy-light decomposition or a
      position-in-Euler-tour depth lookup) that also solves the problem but brings
      complexity binary lifting doesn't need. For pure ancestor queries, binary
      lifting (②) is the intended and simplest solution.

      # Code logic

      Follow the binary-lifting solution in **②**:

      - `up[i][0]` is employee `i`'s boss. The loop
        `up[i][j] = up[up[i][j-1]][j-1]` composes two `2^(j-1)` jumps into one
        `2^j` jump; this is the entire preprocessing (O(n log n)).
      - Note the input order: `q` is read **after** the `n-1` bosses, so the table
        must be built before reading the queries.
      - Per query, iterate the bits of `k` from least significant up: whenever a
        bit is set, apply the matching `2^j` jump `x = up[x][j]`. Because the jumps
        commute (they are all upward), bit order does not matter.
      - If `x` ever becomes `0` the node climbed past the CEO: print `-1`.
      - A `0`-th ancestor query has `k = 0`, the loop body never runs, and `x` is
        printed unchanged — matching the definition that the 0-th ancestor is the
        node itself.
