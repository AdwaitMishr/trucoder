      ## Greedy partitioning by target

      This problem asks: can the numbers `1,2,...,n` be split into **two
      sets of equal sum**, and if so, print such a split.

      Let `S = 1 + 2 + ... + n = n(n + 1) / 2`. For two sets to have equal
      sums, each must sum to exactly `S / 2`, so **`S` must be even** — that
      is the *only* feasibility condition. If `S` is odd, the answer is
      `"NO"` immediately.

      When `S` is even, build the split greedily:

      1. Set `target = S / 2` — the amount set A still needs.
      2. Walk downwards from `i = n` down to `1`:
         - if `i <= target`, put `i` in set A and subtract it from `target`;
         - otherwise put `i` in set B.

      Why does taking the largest remaining number that still fits always
      work? By picking big numbers first, we leave the small ones (which are
      flexible) to fill the leftover gaps. Since every number from `1` to
      `n` is available and they are consecutive, the greedy never strands a
      value it cannot place — whenever the sum is even, this algorithm is
      guaranteed to reach `target = 0` and fill A with exactly `S / 2`.

      *Worked mini-example, n = 4:* `S = 10` (even), `target = 5`.
      Start `i = 4`: `4 <= 5` → A gets 4, `target = 1`. `i = 3`: `3 > 1` →
      B. `i = 2`: `2 > 1` → B. `i = 1`: `1 <= 1` → A gets 1, `target = 0`.
      Sets: A = {1, 4} (sum 5), B = {2, 3} (sum 5). ✓

      **Time complexity:** `O(n)`. **Space:** `O(n)` to store the two sets.

      :::tip
      **Interview tip:** "Greedily consume the largest item that fits, so the
      small items remain as flexible filler" is the same intuition behind
      partition / balancing tasks (e.g. dividing workload), coin-change-style
      constructions, and scheduling. Recognising *just one arithmetic
      feasibility check then a constructive greedy pass* saves a lot of time.
      :::

      ## Question

      Your task is to divide the numbers `1,2,...,n` into two sets of equal
      sum.

      **Input**

      The only input line contains an integer `n`.

      **Output**

      Print `"YES"` if the division is possible, and `"NO"` otherwise.
      After this, if the division is possible, print an example of how to
      create the sets. First, print the number of elements in the first set
      followed by the elements themselves in a separate line, and then,
      print the second set in a similar way.

      **Constraints**

      - `1 <= n <= 10^6`

      **Example 1**

      Input:

      ```
      7
      ```

      Output:

      ```
      YES
      4
      1 2 4 7
      3
      3 5 6
      ```

      **Example 2**

      Input:

      ```
      6
      ```

      Output:

      ```
      NO
      ```

      (Any valid equal-sum split is accepted.)

      ### Solution

      **① Brute force — O(n³) time, O(n²) space (subset-sum dynamic programming).**

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      string solve(long long n) {
          long long sum = n * (n + 1) / 2;
          if (sum % 2 != 0) return "NO";
          long long target = sum / 2;

          // dp[i][s] = can a subset of 1..i sum to s
          vector<vector<bool>> dp(n + 1, vector<bool>(target + 1, false));
          dp[0][0] = true;
          for (long long i = 1; i <= n; i++) {
              for (long long s = 0; s <= target; s++)
                  dp[i][s] = dp[i - 1][s] || (s >= i && dp[i - 1][s - i]);
          }
          if (!dp[n][target]) return "NO";

          vector<bool> inA(n + 1, false);
          long long s = target;
          for (long long i = n; i >= 1; i--) {
              if (s >= i && dp[i - 1][s - i]) { inA[i] = true; s -= i; }
          }

          vector<long long> a, b;
          for (long long i = 1; i <= n; i++) (inA[i] ? a : b).push_back(i);

          string res = "YES\n";
          res += to_string(a.size()) + "\n";
          for (size_t i = 0; i < a.size(); i++)
              res += to_string(a[i]) + (i + 1 < a.size() ? " " : "");
          res += "\n" + to_string(b.size()) + "\n";
          for (size_t i = 0; i < b.size(); i++)
              res += to_string(b[i]) + (i + 1 < b.size() ? " " : "");
          return res;
      }
      ```

      A textbook "does any subset sum to `S/2`" DP, with backtracking to recover one
      subset. Perfectly correct, but `target = S/2 ≈ n²/4`, so the table has `n · n²/4`
      cells — `O(n³)` time and `O(n²)` space. For `n = 10^6` that is about `10^18` cells,
      impossible.

      **② Optimization — O(n) time, O(n) space (greedy from the largest).**

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      string solve(long long n) {
          long long sum = n * (n + 1) / 2;
          if (sum % 2 != 0) return "NO";

          long long target = sum / 2;
          vector<long long> a, b;
          for (long long i = n; i >= 1; i--) {
              if (i <= target) { a.push_back(i); target -= i; }
              else b.push_back(i);
          }

          sort(a.begin(), a.end());
          sort(b.begin(), b.end());

          string res = "YES\n";
          res += to_string(a.size()) + "\n";
          for (size_t i = 0; i < a.size(); i++)
              res += to_string(a[i]) + (i + 1 < a.size() ? " " : "");
          res += "\n" + to_string(b.size()) + "\n";
          for (size_t i = 0; i < b.size(); i++)
              res += to_string(b[i]) + (i + 1 < b.size() ? " " : "");
          return res;
      }
      ```

      Walk from `n` down to `1`, always putting the current number into set A if it
      still fits under the remaining `target`. Because the leftover small numbers are
      flexible, the greedy always reaches `target = 0` exactly when `S` is even. One
      pass → `O(n)` time, `O(n)` space.

      **④ Alternative algorithm — O(n) time, O(n) space (periodic 4-block construction).**

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      string solve(long long n) {
          long long sum = n * (n + 1) / 2;
          if (sum % 2 != 0) return "NO";

          vector<long long> a, b;
          if (n % 4 == 3) { a = {1, 2}; b = {3}; }        // leading triple traded evenly
          for (long long i = (n % 4 == 3 ? 4 : 1); i <= n; i += 4) {
              a.push_back(i); a.push_back(i + 3);
              b.push_back(i + 1); b.push_back(i + 2);
          }

          sort(a.begin(), a.end());
          sort(b.begin(), b.end());

          string res = "YES\n";
          res += to_string(a.size()) + "\n";
          for (size_t i = 0; i < a.size(); i++)
              res += to_string(a[i]) + (i + 1 < a.size() ? " " : "");
          res += "\n" + to_string(b.size()) + "\n";
          for (size_t i = 0; i < b.size(); i++)
              res += to_string(b[i]) + (i + 1 < b.size() ? " " : "");
          return res;
      }
      ```

      A different, fully deterministic construction. When `n % 4 == 3` the leading
      triple `{1,2,3}` is split as `{1,2}` vs `{3}` (both sum 3); when `n % 4 == 0`
      there is no leading triple. Then every block of four consecutive numbers
      `{i, i+1, i+2, i+3}` is split `{i, i+3}` vs `{i+1, i+2}` — each side gains
      `2i + 3`, so every block balances itself. Also `O(n)`, but by periodic pattern
      instead of greedy.

      ## Code logic

      The algorithm first validates feasibility with a single arithmetic
      test: `S = n(n+1)/2` must be even, otherwise it returns `"NO"` at once.

      When feasible, `target` starts at `S/2` and a downward loop assigns
      numbers. Every `i <= target` is taken into set A, shrinking `target`;
      every other `i` goes to set B. This builds A *from the largest value
      down*, so the remaining target is always small enough to finish with
      the small remaining numbers. By construction A sums to exactly `S/2`,
      so B (the complement) sums to `S - S/2 = S/2` too.

      The two sets are sorted ascending and rendered as a multi-line string
      (set size on one line, elements on the next), matching the required
      `"YES"` output layout.
