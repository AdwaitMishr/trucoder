      # XOR Pyramid — compute an entire row

      Like the previous lesson, build the triangular **XOR pyramid** with base
      `a[0..n-1]` and recurrence `dp[l][i] = dp[l-1][i] ^ dp[l-1][i+1]`. This
      time we do **not** ask for one cell — we ask for the **entire row at level
      `k`**: every value `dp[k][0], dp[k][1], …, dp[k][n-1-k]`.

      The mod-2 identity from the previous lesson still holds cell-by-cell:

          dp[k][i] = XOR over submasks j of k of a[i+j]

      (only the `j` with `(j & ~k) == 0` survive, since their binomial
      coefficient `C(k,j)` is odd). So the row is a *sliding* XOR over the base,
      where the distance pattern is fixed by the set bits of `k`.

      **The stride identity that makes a row cheap.** The transformation
      `(f a)[i] = a[i] ^ a[i+1]` (advance one level) is linear, and squaring it
      collapses the middle term:

          f²(a)[i] = (a[i]^a[i+1]) ^ (a[i+1]^a[i+2]) = a[i] ^ a[i+2]

      In general `f^(2^b)` just XORs the element `2^b` positions away, because
      `2^b` has a single set bit (its only submasks are `0` and `2^b`). So a row
      at level `k` is obtained by, for each set bit `b` of `k`, replacing every
      element with `element ^ element-at-distance-2^b`. That is **binary
      lifting**: `O(popcount(k))` XOR-pass-FULL-ARRAY steps instead of `k`
      shrinking passes.

      :::tip
      **Interview tip:** the xor-pyramid "stride-doubling" trick — `f^(2^b)` is
      just the XOR of the element `2^b` away, because a single-bit exponent has
      only two submasks — is binary lifting in disguise. The same reasoning
      (collapse a repeated XOR into distance-based XORs) generalises to repeated
      convolution-with-binomial-parity shapes and is a favourite follow-up on
      "repeat this per-index operation k times without O(k·n)" interview turns.
      :::

      # Question — XOR Pyramid Row

      You are given an array `a[0..n-1]` and a level `k`. Consider the triangular
      XOR pyramid `dp[0][i] = a[i]`, `dp[l][i] = dp[l-1][i] ^ dp[l-1][i+1]`.

      Print the **entire row** at level `k`: the `n - k` values
      `dp[k][0], dp[k][1], …, dp[k][n-1-k]`, space-separated.

      **Input.** The first line has two integers `n` and `k`. The second line
      has `n` integers `a[0..n-1]`.

      **Output.** Print `n - k` integers: the row `dp[k][0 .. n-1-k]`.

      **Constraints**
      - `1 ≤ n ≤ 2·10^5`
      - `0 ≤ k < n`
      - `0 ≤ a[i] < 2^30`

      **Example**
      ```
      Input:
      5 2
      1 2 3 4 5

      Output:
      2 6 6
      ```
      Explanation: `dp[0] = [1,2,3,4,5]`, `dp[1] = [1^2,2^3,3^4,4^5] =
      [3,1,7,1]`, `dp[2] = [3^1,1^7,7^1] = [2,6,6]`. (Identity check:
      `dp[2][i] = a[i] ^ a[i+2]`.)

      ### Solution — progressive tiers

      **① Brute force — peel one layer at a time, O(n·k)**

      Maintain the current row and, `k` times, replace it by the adjacent-XOR
      of consecutive elements (each pass shrinks the row by one).

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n,k; if(!(cin>>n>>k)) return 0;
          vector<int> a(n);
          for(auto &v:a) cin>>v;
          for(int step=0; step<k; step++){
              for(int i=0;i<n-1-step;i++) a[i] = a[i] ^ a[i+1];
              a.resize(n-1-step);
          }
          for(int i=0;i<n-k;i++) cout << a[i] << " \n"[i==n-k-1];
          return 0;
      }
      ```

      **O(n·k)** time, **O(1)** extra space. With `n = k = 2·10^5` that is
      ~4·10^10 XORs — far past the limit. Correct but unusable at scale.

      **② Optimization — stride doubling (binary lifting), O(n·popcount(k)) (submission)**

      For each set bit `b` of `k`, XOR every element with the element `2^b`
      positions to its right. Process bits in increasing order so each new
      stride is applied on top of the accumulated submasks.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n,k; if(!(cin>>n>>k)) return 0;
          int len = n;
          vector<int> a(n);
          for(int i=0;i<len;i++) cin>>a[i];
          for(int b=0; (1LL<<b)<=k; b++){
              int d = 1 << b;                 // distance = 2^b
              if(!(k & d)) continue;          // bit not set in k
              for(int i=0; i + d < len; i++)  a[i] ^= a[i + d];
              len -= d;                       // row shortens by the stride
          }
          for(int i=0;i<len;i++) cout << a[i] << " \n"[i==len-1];
          return 0;
      }
      ```

      **O(n·popcount(k)) ≤ O(n·18)** time (for `k < n ≤ 2·10^5`,
      `popcount(k) ≤ 18`), **O(1)** extra space. This is the submission: each
      set bit of `k` costs one full O(len) XOR pass, and the row shrinks as we go.
  - type: markdown
    content: |
      ### Solution — ③ further optimization / alternative

      The stride-doubling pass is already optimal in the sense that it needs one
      pass over the (shrinking) row per set bit of `k`; since each set bit
      genuinely forces XORing at that distance, `Ω(n·popcount(k))` is a lower
      bound and the direct algorithm matches it. No faster general method exists
      for arbitrary `k` and `n`.

      A *different* viewpoint worth noting: the whole row is the convolution of
      the base with the Sierpinski-parity pattern, and the layer count `k = 2^b`
      (a single set bit) collapses to `dp[k][i] = a[i] ^ a[i+2^b]` — the exact
      primitive one pass above performs. Simulating that in a matrix
      (row times Pascal-parity) is the same `O(n·popcount(k))` work; binary
      lifting is the clean scalar formulation.

      # Code-logic

      - **`a[i] ^= a[i+d]` is the stride kernel.** `f^(2^b)` moves each element
        by distance `2^b`; XORing element `i` with `i+d` applies that primitive in
        place. Bits processed low-to-high compound correctly because the next
        stride's `f^(2^{b+1})` works on the already-XORed row.
      - **`len` tracks the live row width.** Term `i+d` must stay in range; the
        row loses `d` usable entries after applying stride `d`. This mirrors the
        true row length `n - k` at the end.
      - **`(1LL<<b) <= k` bounds the loop** — strides beyond `k`'s top bit are
        skipped via the `k & d` guard.
      - **Correctness for `k = 0`:** no bits set, loop never runs, we print the
        base row intact (`dp[0] = a`).

      # Walkthrough

      **Input (sample):** `n = 5, k = 2`, `a = [1, 2, 3, 4, 5]`.

      `k = 2` = `10b`, set bit `b=1`, distance `d = 2`.

      Single pass (`b=1`, `d=2`, `len=5`):
      - `a[0] ^= a[2]`: `1 ^ 3 = 2`
      - `a[1] ^= a[3]`: `2 ^ 4 = 6`
      - `a[2] ^= a[4]`: `3 ^ 5 = 6`
      - `a[3]`, `a[4]`: out of range (`i+d < 5` blocks them)
      - `len = 5 - 2 = 3`

      Output: `[a[0], a[1], a[2]] = [2, 6, 6]` — matches the expected
      **`2 6 6`** (the sample's hand-built `dp[2] = [2,6,6]`).
