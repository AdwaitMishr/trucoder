      ## Theory — a single scan ("sliding window" in its simplest form)

      You have a string and want the length of the longest run of one repeated
      character. The key insight: **adjacent characters are all that matter**.
      If `s[i]` equals `s[i-1]`, the current run grows; otherwise a new run of
      length 1 starts here.

      We keep two variables:
      - `cur` — length of the run we are currently inside;
      - `best` — the longest run seen anywhere so far.

      As we walk left to right, every time `s[i] == s[i-1]` we bump `cur` (and
      update `best`); when they differ we reset `cur = 1`. The answer is `best`
      at the end.

      **Worked mini-example.** `"ATTCGGGA"`:

      | i | char | vs prev | cur | best |
      |---|------|---------|-----|------|
      | 0 | A | — | 1 | 1 |
      | 1 | T | differs | 1 | 1 |
      | 2 | T | same | 2 | 2 |
      | 3 | C | differs | 1 | 2 |
      | 4 | G | differs | 1 | 2 |
      | 5 | G | same | 2 | 2 |
      | 6 | G | same | 3 | 3 |
      | 7 | A | differs | 1 | 3 |

      Longest repetition = `3`.

      **Complexity.** Every character is visited once: time `O(n)`, space
      `O(1)`.

      :::tip
      **Interview tip:** "Longest substring with one repeated character" (and
      its generalisation, longest substring of characters satisfying some local
      condition) is a textbook two-pointer/window scan. Build the reflex: *
      maintain a running window and a running maximum in a single pass*.
      :::

      ## The Problem

      You are given a DNA sequence: a string consisting of characters `A`, `C`,
      `G`, and `T`. Your task is to find the longest repetition in the
      sequence. This is a maximum-length substring containing only one type of
      character.

      **Input:** The only input line contains a string of `n` characters.

      **Output:** Print one integer: the length of the longest repetition.

      **Constraints:** `1 ≤ n ≤ 10^6`

      ### Sample

      Input:
      ```text
      ATTCGGGA
      ```

      Output:
      ```text
      3
      ```

      ### Solution

      **① Brute force — O(n²) time, O(1) space (extend from every start).**

      ```cpp
      int solve(const string& s) {
          if (s.empty()) return 0;
          int best = 1;
          for (size_t i = 0; i < s.size(); ++i) {
              int cur = 0;
              for (size_t j = i; j < s.size() && s[j] == s[i]; ++j) cur++;
              if (cur > best) best = cur;
          }
          return best;
      }
      ```

      For every starting position `i`, extend the run of equal characters as far as it
      goes and keep the maximum length. This is trivially correct — a repetition is a
      maximal contiguous block of one character — but in the worst case (a string of one
      repeated letter) it is `O(n²)`, unusable at `n = 10^6`.

      **② Optimization — O(n) time, O(1) space (single pass).**

      ```cpp
      int solve(const string& s) {
          if (s.empty()) return 0;
          int best = 1, cur = 1;
          for (size_t i = 1; i < s.size(); ++i) {
              if (s[i] == s[i - 1]) {
                  cur++;
                  if (cur > best) best = cur;
              } else {
                  cur = 1;
              }
          }
          return best;
      }
      ```

      Walk left to right holding `cur` (length of the run we are currently inside) and
      `best` (the longest run seen so far). Equal neighbours extend the run; a difference
      starts a new run of length 1. One `O(n)` pass, `O(1)` space.

      **④ Alternative algorithm — O(n) time, O(1) space (two-pointer window).**

      ```cpp
      int solve(const string& s) {
          if (s.empty()) return 0;
          int best = 1;
          size_t l = 0;
          while (l < s.size()) {
              size_t r = l;
              while (r + 1 < s.size() && s[r + 1] == s[l]) r++;
              if ((int)(r - l + 1) > best) best = (int)(r - l + 1);
              l = r + 1;
          }
          return best;
      }
      ```

      A window formulation of the same idea: fix the window start `l`, push the end `r`
      right while the character is unchanged, then jump `l` just past the finished run.
      Same `O(n)` time and `O(1)` space as tier ②, but expressed with an explicit window
      rather than running-maximum counters — a different mental model that the brute
      force above can be upgraded to.

      ## Code logic

      `solve` takes the DNA string directly. We seed `best = cur = 1`
      (a non-empty string has at least one run of length 1) and scan from the
      second character onward. When `s[i] == s[i-1]` the run extends — we bump
      `cur` and keep `best` as the running maximum. When characters differ, a
      new run begins, so `cur` resets to `1`.

      Because the answer is bounded by the string length and never exceeds an
      `int`, `int` is safe here. No extra data structure is needed — just two
      counters.

      ## Walkthrough

      **Input:** `s = "ATTCGGGA"` (the CSES sample).

      **Expected output:** `3`.

      **Actual run** (searching for the max run):

      - `cur = best = 1`.
      - `i=1` T vs A → differ → `cur = 1`.
      - `i=2` T vs T → same → `cur = 2`, `best = 2`.
      - `i=3` C vs T → differ → `cur = 1`.
      - `i=4` G vs C → differ → `cur = 1`.
      - `i=5` G vs G → same → `cur = 2`, `best = 2`.
      - `i=6` G vs G → same → `cur = 3`, `best = 3`.
      - `i=7` A vs G → differ → `cur = 1`.

      Final `best = 3`, which matches the expected output exactly.
