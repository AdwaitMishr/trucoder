      # Corner Subgrid Count — how many subgrids have all four corners black?

      This is the **counting** sibling of the previous lesson: instead of
      asking *does any* subgrid have uniform corners, count **all** subgrids
      whose four corners are black in a 0/1 grid.

      A subgrid is defined by choosing two distinct rows and two distinct
      columns; in a 0/1 grid it is *beautiful* iff all four intersection cells
      are `1`. So, mirroring the check problem:

      > **count of beautiful subgrids = Σ over row-pairs of C(shared_ones, 2)**
      >
      > where `shared_ones(r1,r2)` = number of columns where **both** rows are
      > black.

      Reasoning: for a fixed row-pair, every pair of columns that are both `1`
      in those two rows forms one beautiful subgrid, and any subset of the
      `shared_ones` common black columns combines freely with the other pair of
      rows chosen here only (each subgrid is counted at its unique row-pair).

      The entire difficulty is speed: naively counting common columns per row
      pair is O(n³), and with `n = 3000` that is `2.7·10^10` — too slow. Because
      a row is just a set of columns, store each row as a **bitset (64-bit
      words)** and compute `shared_ones` with a hardware popcount of the AND.

      :::tip
      **Interview tip:** "number of rectangles with all-four-corner property"
      reduces to choosing pairs of rows (or columns) and counting the columns
      where both are "active", then applying `C(k,2)`. Comparing the O(n³)
      column-sweep against the O(n³/64) bitset row-pair sweep — and preferring
      the bitset at `n=3000` — is a strong, concrete answer to a
      corner-counting question.
      :::

      # Question — Corner Subgrid Count

      You are given an `n × n` grid whose each square is either black or white.
      A subgrid is called **beautiful** if its height and width is at least two
      and all of its corners are black. How many beautiful subgrids are there
      within the given grid?

      **Input.** The first input line has an integer `n`: the size of the grid.
      Then there are `n` lines describing the grid: `1` means a square is black
      and `0` means it is white.

      **Output.** Print the number of beautiful subgrids.

      **Constraints** — `1 ≤ n ≤ 3000`

      **Example**
      ```
      Input:
      5
      00010
      11111
      00110
      11001
      00010

      Output:
      4
      ```

      ### Solution — progressive tiers

      **① Brute force — test every rectangle, O(n⁴)**

      Enumerate every row pair and column pair and check the four corners.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n; cin>>n;
          vector<string> g(n);
          for(int i=0;i<n;i++) cin>>g[i];
          long long ans=0;
          for(int r1=0;r1<n;r1++)
              for(int r2=r1+1;r2<n;r2++)
                  for(int c1=0;c1<n;c1++)
                      for(int c2=c1+1;c2<n;c2++)
                          if(g[r1][c1]=='1' && g[r1][c2]=='1'
                          && g[r2][c1]=='1' && g[r2][c2]=='1') ans++;
          cout<<ans<<"\n";
          return 0;
      }
      ```

      **O(n⁴)** — `n=3000` → ~8·10^13, impossible.

      **② Optimization — column sweep with C(cnt,2), O(n³)**

      For each pair of columns, count rows where both are black; each such row
      contributes one "potential" and any two of them close a rectangle.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n; if(!(cin>>n)) return 0;
          vector<string> g(n);
          for(int i=0;i<n;i++) cin>>g[i];
          long long ans=0;
          for(int c1=0;c1<n;c1++)
              for(int c2=c1+1;c2<n;c2++){
                  long long cnt=0;
                  for(int r=0;r<n;r++) if(g[r][c1]=='1' && g[r][c2]=='1') cnt++;
                  ans += cnt*(cnt-1)/2;
              }
          cout<<ans<<"\n";
          return 0;
      }
      ```

      **O(n³)** — `n=3000` → `2.7·10^10`; still too slow by ~20×.

      **③ Optimization — row-pair bitset popcount, O(n³/64) (submission)**

      Pack each row into 64-bit words and, for every row pair, count their AND.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n; if(!(cin>>n)) return 0;
          int W=(n+63)/64;
          vector<vector<unsigned long long>> rows(n, vector<unsigned long long>(W,0));
          for(int i=0;i<n;i++){
              string s; cin>>s;
              for(int j=0;j<n;j++) if(s[j]=='1') rows[i][j>>6] |= (1ULL<<(j&63));
          }
          long long ans=0;
          for(int i=0;i<n;i++)
              for(int j=i+1;j<n;j++){
                  unsigned long long c=0;
                  for(int w=0;w<W;w++) c += __builtin_popcountll(rows[i][w]&rows[j][w]);
                  ans += c*(c-1)/2;
              }
          cout << ans << "\n";
          return 0;
      }
      ```

      **O(n³/64)** time — `n=3000` → ~4·10^8 word-popcount operations, well
      within a 1 s limit. `#pragma GCC target("popcnt")` or `__builtin_popcountll`
      (as here) keeps each word-count a single instruction. This is the
      submission tier.

      # Code-logic

      - **`#pragma GCC target("popcnt")`** is the usual extra clincher here:
        it lets the compiler emit the native `popcnt` instruction so the inner
        `__builtin_popcountll` is one cycle instead of a software loop. (Your
        local `-march=native` build already gets it; omit it on generic
        targets or keep the code portable.)
      - **Row packing.** `rows[i][w]` holds bits `64w .. 64w+63`; cell `(i,j)`
        sets word `j>>6`, bit `j&63`.
      - **The AND + popcount** is exactly `shared_ones(r1,r2)`. Then
        `c*(c-1)/2` counts pairs of shared black columns — the corners of all
        subgrids spanned by that row pair.
      - **Answer width.** Σ can exceed `int`; use `long long`. Max is bounded
        by `< n⁴/8` well under 2^63.

      # Walkthrough

      **Input (sample):** `n=5`, grid:
      ```
      00010
      11111
      00110
      11001
      00010
      ```

      For each row pair let `c = shared black columns`, contribution `c(c-1)/2`:

      | rows | shared black cols | c | c(c-1)/2 |
      |------|-------------------|----|---------|
      | 1,2 | {4} | 1 | 0 |
      | 1,3 | {4} | 1 | 0 |
      | 1,4 | {} | 0 | 0 |
      | 1,5 | {4} | 1 | 0 |
      | 2,3 | {3,4} | 2 | **1** |
      | 2,4 | {1,2,5} | 3 | **3** |
      | 2,5 | {4} | 1 | 0 |
      | 3,4 | {} | 0 | 0 |
      | 3,5 | {4} | 1 | 0 |
      | 4,5 | {} | 0 | 0 |

      `ans = 1 + 3 = 4`. The compiled submission prints **4** — matches the
      expected **4**.
