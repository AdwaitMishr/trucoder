      ## Theory — left-to-right surplus balance on two lanes

      We have a `2×n` grid, every cell holds some number of coins and there are
      exactly `2n` coins total, so in the end every cell must hold exactly one
      coin. A coin moves one cell left/right/up/down per step; we want the
      minimum total moves.

      Rewrite each cell's value as its **surplus** over the target `1`:

      ```
      a[0][i] = coins(top,i) − 1,    a[1][i] = coins(bottom,i) − 1.
      ```

      A cell with `+k` has `k` coins to give away; `−k` needs `k` coins. Over
      the whole grid the surpluses sum to `0`, so everything balances out.

      **Sweep the columns left → right** carrying two running balances: `top`
      and `bot` = how much surplus from columns already passed still has to
      travel rightward on the top / bottom row (positive = excess, negative =
      deficit). Before we use column `i`, that carried surplus must cross one
      more column boundary, costing its magnitude: add `|top| + |bot|`. Then we
      merge in column `i` (`top += a[0][i]`, `bot += a[1][i]`).

      **The vertical trick.** If at this point one row has excess and the other
      a deficit (opposite signs), moving the smaller amount straight up/down
      (one step, cost 1 per coin) reduces both — and it's always at least as
      cheap as anything else, because crossing vertically is a single unit either
      way. So we settle `min(|top|,|bot|)` coins vertically right here.

      This greedy is optimal: every coin that must move right pays exactly one
      per column it crosses, and vertical settling is resolved at the first
      column where it becomes beneficial.

      :::tip
      **Interview tip:** "Distribute surplus to meet per-cell demands on a line
      (or small path)" → compute per-position surplus and **sweep once**, paying
      the carried-balance per step. The two-lane vertical option is a "swap the
      sign when it's cheap" micro-optimisation. Expect this on production-line /
      balancing / assignment-on-a-line problems.
      :::

      ## The Problem

      There is a `2×n` grid whose each cell contains some number of coins. The
      total number of coins is `2n`. Your task is to arrange the coins so that
      each cell contains exactly one coin. On each move you can choose any coin
      and move it one step left, right, up or down. What is the minimum number
      of moves if you act optimally?

      **Input.** The first input line has an integer `n`: the width of the grid.
      After this, there are two lines that describe the grid. Each line has `n`
      integers: the number of coins in each cell.

      **Output.** Print one integer: the minimum number of moves.

      **Constraints**
      - `1 ≤ n ≤ 10⁵`

      **Example**

      Input:
      ```
      4
      0 1 0 1
      2 0 1 3
      ```

      Output:
      ```
      5
      ```

      ### Solution — progressive tiers

      **① Brute force — min-cost flow, O(n²) (and worse).** Build a network with
      a node per cell, send the surplus coins to the deficit cells, cost of an
      edge = Manhattan distance, and run successive-shortest-paths min-cost flow.
      Exact but far too slow for `n ≤ 10⁵`.

      **② Optimization — O(n) greedy sweep.** Subtract `1` from every cell, then
      scan columns carrying two running surpluses, paying the carry per column
      and settling opposite signs vertically.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      typedef long long ll;
      int main(){
          ios::sync_with_stdio(false); cin.tie(0);
          int n; cin>>n;
          vector<int> a[2]; a[0].resize(n); a[1].resize(n);
          for(int r=0;r<2;r++)for(int c=0;c<n;c++){ cin>>a[r][c]; --a[r][c]; }
          ll res=0; int top=0, bot=0;
          for(int c=0;c<n;c++){
              res += abs(top)+abs(bot);       // carry one more column
              top += a[0][c]; bot += a[1][c]; // absorb this column
              if((top<0&&bot>0)||(top>0&&bot<0)){
                  int x=min(abs(top),abs(bot)); // settle cheapest vertically
                  res += x;
                  if(bot<0) bot+=x; else bot-=x;
                  if(top<0) top+=x; else top-=x;
              }
          }
          cout<<res<<"\n";
          return 0;
      }
      ```
      *Complexity: O(n) time, O(n) (or O(1) streaming) memory.*

      **③ Further optimization.** The two row-surpluses can be merged into a
      single signed balance plus the count split, but O(n) is already optimal —
      every coin can demand horizontal travel, so we must look at all `2n` cells.

      **④ Alternative — DP over columns.** Model the carried surplus on the top
      row `p` (the bottom is then implied) and pick vertical transfers greedily;
      that is the same recurrence. The direct greedy above is the cleanest
      closed form.

      ## Code logic

      `solve` — O(n) greedy. Key lines:

      1. **`--a[r][c]`** turns counts into surpluses relative to the target `1`
         (positive = extra coins, negative = needed).
      2. **`res += abs(top)+abs(bot)`** before absorbing column `c`: anything
         carried from the left is one column closer to its destination, so every
         carried coin pays exactly `1`.
      3. **`top += a[0][c]; bot += a[1][c]`** merges this column's surplus.
      4. **Opposite-sign settling**: if `top` and `bot` differ in sign, move
         `min(|top|,|bot|)` coins between the rows (cost `1` each), shrinking
         both magnitudes — vertical crossing is just as cheap here as any further
         horizontal carry, so resolving it now can never hurt.

      Interpretation: the extra coin in bottom column 1 moves **up** into the
      top cell (1 step), and the two extra bottom coins in column 4 travel
      left/down to fill the short cells in columns 2–3, all within 5 total
      steps.
