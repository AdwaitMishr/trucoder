      # XOR of All Subarrays — count the odd-parity subarrays per bit

      We want the **sum of the xor of every contiguous subarray**. The naive
      approach is quadratic, but a per-bit counting trick turns it linear and is a
      staple of XOR-street problems.

      ## XOR is independent bit by bit

      Recall that the xor of a subarray's value equals the *parity* (odd/even
      count) of each of its bits. So for a fixed bit `b`, the subarray's xor has
      bit `b` set iff **an odd number of the subarray's elements** have bit `b`
      set. Therefore, summing the xor over all subarrays decomposes into independent
      contributions per bit: for each bit `b`, count how many subarrays have an odd
      number of `b`-bits, and add `count · 2^b`.

      ## Counting odd subarrays with prefix parities

      Let `p[i]` be the xor of the first `i` elements (a prefix), and look only at
      bit `b` of `p[i]`. A subarray `a[l..r]` equals `p[r] ^ p[l-1]`, so its bit-`b`
      parity is `1` exactly when the two prefix parities `p[r]` and `p[l-1]` differ
      at bit `b`. If, among the `n+1` prefixes, `c0` have bit `b` = 0 and `c1` have
      bit `b` = 1, then the number of pairs with differing bit-`b` parity — hence
      the number of subarrays with odd bit-`b` count — is exactly

      ```
      c0 * c1
      ```

      Every prefix pair `(l-1, r)` corresponds to exactly one non-empty subarray,
      so no double counting occurs. Summing `c0·c1·2^b` over `b = 0..30` gives the
      answer.

      :::tip
      **Interview tip:** "sum of xor over all subarrays" (or "xor of all subarray
      sums") almost always collapses to per-bit counting with prefix parities:
      `count = c0·c1` per bit, `answer = Σ c0·c1·2^b`. If instead the problem asks
      for the **xor** of all subarray xors, use the element-appearance shortcut —
      element `a[i]` reaches the total iff `i·(n-i+1)` is odd (one subarray per
      start/end). Recognize the per-bit-parity pattern; it appears constantly.
      :::

      Time: `O(31·n)`. Space: `O(1)` beyond the array.

      # The Problem

      You are given an array of `n` integers. Let `S` be the set of all contiguous
      subarrays; compute the **sum of the xor of every subarray** in `S`.

      ## Input

      The first line contains an integer `n`. The second line contains `n`
      integers `a1, a2, …, an`.

      **Constraints:** `1 ≤ n ≤ 10^5`, `0 ≤ ai ≤ 10^9`. (With these bounds the
      answer fits in a 64-bit integer: `2^30 · n(n+1)/2 ≈ 5.4·10^18 < 2^63`.)

      ## Output

      Print one integer: the sum over all subarrays of their xor.

      ## Sample

      **Input:**
      ```
      3
      1 2 3
      ```
      **Output:**
      ```
      10
      ```
      The subarrays and their xors: `[1]=1`, `[2]=2`, `[3]=3`, `[1,2]=3`,
      `[2,3]=1`, `[1,2,3]=0`. Sum `= 1+2+3+3+1+0 = 10`.

      ### Solution — progressive tiers

      **① Brute force — O(n² · 31)**

      For every starting point, extend the right end while keeping the running xor,
      and accumulate.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      typedef long long ll;
      int main(){
          ios::sync_with_stdio(false); cin.tie(0);
          int n; cin >> n; vector<int> a(n);
          for (int &x : a) cin >> x;
          ll ans = 0;
          for (int l = 0; l < n; ++l){
              int cur = 0;
              for (int r = l; r < n; ++r){
                  cur ^= a[r];
                  ans += cur;
              }
          }
          cout << ans << "\n";
          return 0;
      }
      ```

      *Correct, but `n(n+1)/2 ≈ 5·10^9` subarrays at `n = 10^5` — too slow.*

      **② Optimization — per-bit parity counting, O(31·n) (optimal)**

      For each bit, count prefix parities and accumulate `c0·c1·2^b`.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      typedef long long ll;
      int main(){
          ios::sync_with_stdio(false); cin.tie(0);
          int n; cin >> n; vector<int> a(n);
          for (int &x : a) cin >> x;
          ll ans = 0;
          for (int b = 0; b <= 30; ++b){
              int parity = 0; ll c0 = 1, c1 = 0;   // prefix[0] has parity 0
              for (int i = 0; i < n; ++i){
                  parity ^= ((a[i] >> b) & 1);     // parity of first i+1 bits
                  if (parity == 0) ++c0; else ++c1;
              }
              ans += c0 * c1 * (1LL << b);
          }
          cout << ans << "\n";
          return 0;
      }
      ```

      *`O(31·n)` time, `O(1)` space — the tier we compile and verify.*

      **③ Further optimization — none needed**

      Every input must be read and there are only 31 relevant bits, so `O(31·n)`
      is optimal.

      **④ Alternative algorithm — XOR of all subarray xors (closed form)**

      If the goal were the **xor** (not sum) of every subarray's xor, there is an
      even simpler formula: a subarray containing position `i` (1-indexed) has
      `i·(n-i+1)` choices, so element `a[i]` contributes to the total xor iff that
      count is **odd**:

      ```cpp
      int ans = 0;
      for (int i = 1; i <= n; ++i)
          if ((i * (n - i + 1)) & 1) ans ^= a[i - 1];
      cout << ans << "\n";
      ```

      *`O(n)`. A useful companion formula when the problem flips "sum" to "xor".*

      # Code logic

      - **`parity` tracks the running bit-parity.** It is xored with bit `b` of
        each element, so after `i` elements it equals bit `b` of the prefix `p[i]`.
        `c0`/`c1` count the prefixes (starting with `p0 = 0`, parity 0) of each bit
        parity.
      - **`ans += c0 * c1 * (1LL << b)`.** `c0·c1` counts the prefix pairs of
        *different* parity at bit `b` — precisely the subarrays with an odd number
        of `b`-bits. Each such subarray adds `2^b` to the total.
      - **Bits `0..30` suffice** because `ai ≤ 10^9 < 2^30`; bit 30 is covered by
        the `b <= 30` bound and never becomes set, contributing `0`.

      # Walkthrough

      Sample: `n = 3`, array `1 2 3` = `001₂, 010₂, 011₂`.

      Bit 0 (LSB): element bits `[1, 0, 1]`. Prefix parities: `p0=0, p1=1, p2=1,
      p3=0`. `c0=2, c1=2` → `2·2 = 4` subarrays with odd bit-0 count →
      `4 · 1 = 4`.

      Bit 1: element bits `[0, 1, 1]`. Prefix parities: `p0=0, p1=0, p2=1, p3=0`.
      `c0=3, c1=1` → `3·1 = 3` subarrays → `3 · 2 = 6`.

      Bit 2 and above: no element has those bits set → contribute 0.

      Total `4 + 6 = 10`, matching the sample's direct sum.
