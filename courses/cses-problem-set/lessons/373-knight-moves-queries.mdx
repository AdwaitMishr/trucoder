      ## Theory — an O(1) closed form for knight distance

      A knight on an **infinite** board jumps between squares differing by
      `(±1, ±2)` or `(±2, ±1)`. For a single query, breadth-first search from the
      target is possible in principle, but the coordinates reach `10^9` and there
      are up to `10^5` queries, so BFS is hopeless. The key is that the infinite
      board has a **closed-form** knight-distance function.

      After subtracting the target `(1,1)` and taking absolute values, we must
      solve: minimum number of knight moves from `(0,0)` to a point `(X, Y)` with
      `X, Y ≥ 0`. WLOG assume `x ≤ y` (reflect across the diagonal; symmetry
      preserves distances).

      Two facts (easiest confirmed by a small BFS) anchor the formula:

      - `(0,1)` needs **3** moves — a knight cannot land on the square diagonally
        adjacent to it, and two moves are not enough.
      - `(2,2)` needs **4** moves; `(0,0)` needs 0.

      For every other point the distance is

      ```
      d = max( ceil(y/2), ceil((x+y)/3) )
      if (d is odd) != ((x+y) is odd):  d += 1
      ```

      **Why it works.** Each move changes `x + y` by `±3` or `±1` in magnitude,
      but the *parity* of `x + y` flips every move (a knight stays on the same
      colour as the start after an even number of moves). So the answer must have
      the same parity as `x + y`. Every move adds at most `2` to `max(x,y)`, so
      `ceil(y/2)` moves are needed; and each move changes `x + y` by at most `3`,
      so `ceil((x+y)/3)` moves are needed. The max of these two bounds, adjusted
      to the correct parity, is exactly attainable — two independent lower bounds
      that the reachability structure of the knight saturates.

      :::tip
      **Interview tip:** Distance on an infinite board often has a closed form.
      Find lower bounds from per-move "budget" (how far one move can change each
      coordinate), check parity, and nudge the bound up until it has the right
      parity and is actually reachable. Two or three exceptional small squares
      usually remain and are hard-coded.
      :::

      ## The Problem

      There is a knight on an infinite chessboard. The rows and columns are
      1-indexed. Process queries of the form: when the knight starts at position
      `(x, y)`, what is the minimum number of knight moves needed to reach the
      top-left corner `(1,1)`.

      **Input.** The first line has an integer `n`: the number of queries. Each of
      the following `n` lines has two integers `x` and `y`: the knight position.

      **Output.** For each query, print the minimum number of moves.

      **Constraints**
      - `1 ≤ n ≤ 10^5`
      - `1 ≤ x, y ≤ 10^9`

      **Sample**

      Input:
      ```
      4
      1 1
      2 3
      4 1
      42 1337
      ```

      Output:
      ```
      0
      1
      3
      669
      ```

      ### Solution — progressive tiers

      **① Brute force — BFS per query.** For each query run a BFS from the
      corner until the target square is reached. On a truly infinite board this
      never terminates for far targets, and even a bounded BFS is far too slow
      with `10^5` queries at coordinates up to `10^9`.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          int n; cin >> n;
          int dx[8]={1,1,-1,-1,2,2,-2,-2}, dy[8]={2,-2,2,-2,1,-1,1,-1};
          while(n--){
              int X, Y; cin >> X >> Y;
              // BFS on the quadrant [0..X]x[0..Y]
              vector<vector<int>> dist(X+1, vector<int>(Y+1, -1));
              queue<pair<int,int>> q; q.push({0,0}); dist[0][0]=0;
              while(!q.empty()){
                  auto [a,b]=q.front(); q.pop();
                  if(a==X && b==Y) break;
                  for(int d=0; d<8; d++){
                      int na=a+dx[d], nb=b+dy[d];
                      if(na<0||nb<0||na>X||nb>Y||dist[na][nb]!=-1) continue;
                      dist[na][nb]=dist[a][b]+1; q.push({na,nb});
                  }
              }
              cout << dist[X][Y] << "\n";
          }
      }
      ```
      *Complexity: O(X·Y) per query — unusable when X, Y are up to 10^9.*

      **② Optimization — O(1) per query.** Symmetrize, special-case the two
      exceptional squares, then apply the closed form.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      typedef long long ll;
      ll knightDist(ll X, ll Y){
          ll x = min(X,Y), y = max(X,Y);      // 0 <= x <= y
          if (x==0 && y==1) return 3;         // diagonally-adjacent square
          if (x==2 && y==2) return 4;         // the other exceptional square
          ll d = max((y+1)/2, (x+y+2)/3);     // ceil(y/2), ceil((x+y)/3)
          if ((d & 1) != ((x+y) & 1)) d++;    // parity correction
          return d;
      }
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n; cin >> n;
          while(n--){
              ll X, Y; cin >> X >> Y;
              cout << knightDist(X-1, Y-1) << "\n";
          }
      }
      ```
      *Complexity: O(1) per query — handles 10^5 queries at 10^9 instantly.*

      **③ Further optimization — none.** The closed form is a constant number of
      operations; no asymptotic improvement exists beyond O(1).

      **④ Alternative — bounded BFS with a cache.** Because the distance grows
      linearly beyond a small radius, one can run a BFS on a fixed moderate region
      (say all squares within a few hundred of the corner) and derive every answer
      from it. This is the *practical* "search" method when a board is large but
      bounded, and a good fallback if you forget the formula — but it is not
      needed here and is asymptotically worse for many queries.

      ## Code logic

      `solve` — O(1) knight distance. Key lines:

      1. **`knightDist(X,Y)`.** The input is already the offset from the corner
         (`knightDist(X-1, Y-1)`). First `x = min, y = max` uses the board's
         4-fold symmetry so only `0 ≤ x ≤ y` must be handled.
      2. **Special cases.** `(0,1)` and `(2,2)` violate the general bound and are
         returned explicitly; `(0,0) → 0` falls through the formula.
      3. **Lower bounds.** `(y+1)/2 = ceil(y/2)` and `(x+y+2)/3 = ceil((x+y)/3)`.
         The larger of the two is the answer before parity.
      4. **Parity.** `x + y` flips parity each move, so the answer must have the
         same parity as `x + y`. If the bound has the wrong parity we add one
         move.
