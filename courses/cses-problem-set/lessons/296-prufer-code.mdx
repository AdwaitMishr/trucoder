      ## Theory — the Prüfer sequence, a compact tree fingerprint

      Any labeled tree on `n ≥ 2` vertices can be shrunk to a sequence of only
      `n-2` numbers, and — crucially — that sequence **uniquely** identifies the
      tree. This is the **Prüfer sequence** (Cayley's theorem:
      there are exactly `n^(n-2)` labeled trees on `n` vertices, and each Prüfer
      sequence corresponds to exactly one of them).

      **Encoding (tree → sequence).** While more than two vertices remain:
      take the current *leaf with the smallest label*, remove it, and append its
      (single) neighbor to the sequence. After `n-2` rounds two vertices remain
      and we stop. Note the sequence *never* contains the last two vertices.

      **Decoding (sequence → tree) — the greedy inverse.** Give every label a
      "degree" equal to `1 + (number of times it appears in the sequence)`.
      Repeatedly:
      1. Pick the smallest label whose degree is `1` (a leaf).
      2. Attach it to the next symbol in the sequence by an edge.
      3. Decrease both degrees by `1`.
      Finally, connect the last two remaining degree-1 vertices. The n-1 edges
      produced form the unique tree.

      **Why decoding works.** The count `1 + frequency` is exactly the number of
      edges incident in the reconstructed tree: a vertex appears in the sequence
      once per time it "loses" a leaf neighbor during encoding. The smallest
      leaf is always safe to join to the next sequence symbol because there is
      no other leaf smaller than it to "steal" that edge.

      **Complexity.** Naive per-step scanning is `O(n²)`; keeping leaves in a
      min-heap / ordered set gives `O(n log n)`. Because each vertex enters the
      structure once.

      :::tip
      **Interview tip:** Prüfer sequences turn "count labeled trees" into a
      simple counting argument (Cayley `n^(n-2)`) and are great for problems
      that ask "build a tree satisfying some degree / label constraints". Decode
      is the classic entry point. The key nuance interviewers probe: **degree =
      1 + frequency**, and the two final vertices are never in the sequence.
      :::

      ## The Problem

      A labeled tree on `n` vertices (`1 … n`) is given by its **Prüfer
      sequence**: `n-2` integers `p[1] … p[n-2]`. Reconstruct any tree whose
      Prüfer sequence matches this input — since the mapping is a bijection, the
      tree is unique.

      Your task is to print the `n-1` edges of that tree. The edges can be
      printed in any order.

      **Input.** The first line has `n`. The second line has the `n-2` integers
      of the Prüfer sequence. (For `n = 2` the second line is empty.)

      **Output.** Print `n-1` lines, each with two integers `a b` meaning the
      edge between vertices `a` and `b`.

      **Constraints** `2 ≤ n ≤ 2·10^5`.

      **Sample**
      ```
      Input:
      5
      2 3 1

      Output:
      4 2
      2 3
      3 1
      1 5
      ```
      Explanation: the four edges `(4,2), (2,3), (3,1), (1,5)` form a path
      `4–2–3–1–5`; its Prüfer sequence is indeed `2 3 1`.

      ### Solution — progressive tiers

      **① Brute force — O(n²).** Decode by simulation: keep a `deg[]` value for
      each vertex (`1 + frequency`), and at every step *scan all labels* to find
      the smallest one with `deg == 1`, attach it, and decrement. The scan is
      the bottleneck: `n-2` steps, each `O(n)`.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n; cin>>n;
          vector<int> code(n-2), deg(n+1,1);
          for(int i=0;i<n-2;i++){ cin>>code[i]; deg[code[i]]++; }
          vector<pair<int,int>> edges;
          for(int i=0;i<n-2;i++){
              int leaf=-1;
              for(int v=1;v<=n;v++) if(deg[v]==1){ leaf=v; break; }  // O(n) each step
              edges.push_back({leaf, code[i]});
              deg[leaf]--; deg[code[i]]--;
          }
          int a=-1,b=-1;
          for(int v=1;v<=n;v++) if(deg[v]==1){ if(a==-1) a=v; else b=v; }
          edges.push_back({a,b});
          for(auto [u,v]: edges) cout<<u<<" "<<v<<"\n";
      }
      ```

      **② Optimization — min-heap of leaves, O(n log n) (submission).** Only the
      leaves are ever candidates, and we always take the *smallest* one. Keep
      current leaves in an ordered container; in C++ `std::set` (or a priority
      queue) gives `O(log n)` per operation and `O(n log n)` overall. Every
      vertex enters and leaves exactly once.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n; cin>>n;
          vector<int> code(n-2), deg(n+1,1);
          for(int i=0;i<n-2;i++){ cin>>code[i]; deg[code[i]]++; }
          set<int> leaves;
          for(int v=1;v<=n;v++) if(deg[v]==1) leaves.insert(v);
          vector<pair<int,int>> edges;
          for(int x: code){
              int leaf = *leaves.begin(); leaves.erase(leaves.begin());
              edges.push_back({leaf, x});
              deg[leaf]--; deg[x]--;
              if(deg[x]==1) leaves.insert(x);
          }
          int a=*leaves.begin(), b=*leaves.rbegin();
          edges.push_back({a,b});
          for(auto [u,v]: edges) cout<<u<<" "<<v<<"\n";
      }
      ```

      **③ Note — a linear `O(n)` decode exists.** A classic refinement replaces
      the ordered set by tracking, for each possible degree, the smallest label
      with that degree (bucket + running pointer). It stays `O(n log n)` here for
      simplicity — the set version is the clear, correct, submission-ready answer.

      **④ Alternative — encode as a verification tool, O(n log n).** Rather than
      a *different* decoding algorithm, the most useful companion is the inverse:
      encode a tree back to its sequence. Verifying that `encode(decode(input))
      == input` cross-checks both routines. Encode: repeatedly remove the
      smallest leaf, emitting its neighbor, using the same degree bookkeeping.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n; cin>>n;
          vector<set<int>> adj(n+1);   // adjacency as sets for fast leaf/min ops
          for(int i=0;i<n-1;i++){ int u,v; cin>>u>>v; adj[u].insert(v); adj[v].insert(u); }
          set<int> bySize;             // leaves ordered by label
          for(int v=1;v<=n;v++) if(adj[v].size()==1) bySize.insert(v);
          vector<int> code;
          while(bySize.size()>1){
              int leaf=*bySize.begin(); bySize.erase(bySize.begin());
              int nb=*adj[leaf].begin();
              code.push_back(nb);
              adj[leaf].clear();
              adj[nb].erase(leaf);
              if(adj[nb].size()==1) bySize.insert(nb);
          }
          for(int i=0;i<n-2;i++) cout<<code[i]<<" "; cout<<"\n";
      }
      ```

      ## Code logic

      The submission (②) decodes in three short passes.

      1. **Degrees.** Start every `deg[v] = 1`; for each sequence symbol `x`,
         `deg[x]++`. So `deg[v] = 1 + frequency(v)`.
      2. **Seed the leaf set** with all labels whose degree is 1.
      3. **Main loop** over each symbol `x`:
         - take the smallest leaf `leaf = *leaves.begin()`,
         - emit edge `(leaf, x)`,
         - `deg[leaf]--` (it is consumed forever — never re-inserted),
         - `deg[x]--`; if `x` now has degree 1 it becomes a leaf → insert it.
      4. **Final pair.** After the loop two leaves remain in the set — their edge
         closes the tree. `a=*begin(), b=*rbegin()`.

      The invariant that keeps this greedy correct: every leaf's *only* future
      connection is the next unprocessed sequence symbol, and taking the smallest
      leaf is always valid because labels are independent of edge order.

      ## Walkthrough

      **Input (sample):** `n = 5`, code `= 2 3 1`.

      1. **Degrees:** all start 1, then `deg[2]++`, `deg[3]++`, `deg[1]++` →
         `deg = [1:2, 2:2, 3:2, 4:1, 5:1]`. Leaves `= {4,5}`.
      2. **Step 1 (`x=2`):** smallest leaf 4 → edge `(4,2)`. `deg[4]=0`,
         `deg[2]=1` → insert 2. Leaves `{2,5}`.
      3. **Step 2 (`x=3`):** smallest leaf 2 → edge `(2,3)`. `deg[2]=0`,
         `deg[3]=1` → insert 3. Leaves `{3,5}`.
      4. **Step 3 (`x=1`):** smallest leaf 3 → edge `(3,1)`. `deg[3]=0`,
         `deg[1]=1` → insert 1. Leaves `{1,5}`.
      5. **Final:** connect 1 and 5 → edge `(1,5)`.

      **Edges printed:** `(4,2), (2,3), (3,1), (1,5)` — exactly the sample
      output. **Actual vs expected:** identical.

      Sanity check by re-encoding: leaves in the tree are 4 and 5; smallest leaf
      4 → neighbor 2 → emit 2; 5 → neighbor 1? not smallest yet — smallest leaf
      2 → neighbor 3 → emit 3; then 3 → 1 → emit 1. Sequence `2 3 1` ✓.
