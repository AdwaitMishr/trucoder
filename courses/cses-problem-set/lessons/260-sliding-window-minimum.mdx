      # Sliding Window Minimum — the minimum of every k-length window

      Given `n` numbers and a window length `k`, report the **minimum value of
      each contiguous window of length `k`**. This is the classic *"sliding
      window minimum / maximum"* problem, and the canonical tool is a
      **monotonic deque**.

      `sum` from the previous lesson had a cheap answer because subtraction
      *inverts* addition. Minimum has **no inverse** — you cannot "remove" the
      leaving value from a running minimum. Yet we can still do O(n) by keeping
      a *candidate list* of elements that could ever be the minimum again, in
      an order that makes both ends usable.

      ## When you reach for a monotonic deque

      Maintain a **deque of indices**, not values, with one golden invariant:
      **the values they point at are strictly increasing from front to back**.
      With that property,

      - the **front** is always the index of the current window's minimum, and
      - any value that is beaten by the newly arriving element can be **thrown
        away from the back forever** (an older, larger element survives only
        until a smaller one arrives).

      Every element is pushed once and popped at most once, so the total work is
      linear even though each window "knows" its minimum instantly.

      ## The three rules, per step

      1. **Pop back while `a[back] >= a[i]`.** `a[i]` is newer and (weakly)
         smaller, so the old ones can never be the min again — they die.
      2. **Push `i`.**
      3. **Pop front while `front <= i - k`.** Those indices have slid out of
         the window; they're stale.

      Now `a[front]` is the window minimum. Because every index enters and
      leaves the deque exactly once, the whole scan is `O(n)`.

      ## Worked mini-example

      `a = [1, 3, -1, -3, 5, 3, 6, 7]`, `k = 3`. The deque (as indices) after
      each full window and the reported minimum:

      | i | a[i] | deque (values) | window min |
      |---|------|----------------|-----------|
      | 0 | 1 | [1] | – |
      | 1 | 3 | [1,3] | – |
      | 2 | -1 | [-1] | -1 |
      | 3 | -3 | [-3] | -3 |
      | 4 | 5 | [-3,5] | -3 |
      | 5 | 3 | [-3,3] | -3 |
      | 6 | 6 | [3,6] | 3 |
      | 7 | 7 | [3,7] | 3 |

      Result: `-1 -3 -3 -3 3 3`.

      :::tip
      **Interview tip:** "minimum/maximum over every window of size k" scaffolds
      into the same deque pattern as *"BST/MinStack with getMin"* — you throw
      away dominated elements once. The expected answer is `O(n)` with a
      monotonic deque; a heap or multiset gives `O(n log k)` and is accepted but
      a band below what interviewers want to hear. Note the comparison operator
      flips if you want the *max* instead.
      :::

      # The Problem

      Given an array of `n` integers and a window length `k`, print the minimum
      value of each contiguous window of length `k`, from the window starting at
      position `1` to the window starting at position `n - k + 1`.

      ## Input

      The first line has two integers `n` and `k`. The second line has `n`
      integers `a_1, a_2, …, a_n` (each `abs(a_i) <= 10^9`).

      **Constraints:** `1 <= k <= n <= 2 * 10^5`

      ## Output

      Print `n - k + 1` integers separated by spaces: the minimum value of each
      window in left-to-right order.

      ## Sample

      **Input:**
      ```
      8 3
      1 3 -1 -3 5 3 6 7
      ```
      **Output:**
      ```
      -1 -3 -3 -3 3 3
      ```

      ### Solution — progressive tiers

      **① Brute force — O(nk)**

      For each window compute `min` over its `k` elements directly.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      typedef long long ll;
      int main(){
          ios::sync_with_stdio(false); cin.tie(0);
          int n,k; cin>>n>>k;
          vector<ll> a(n);
          for(int i=0;i<n;i++) cin>>a[i];
          for(int i=0;i<n-k+1;i++){
              ll m=LLONG_MAX;
              for(int j=i;j<i+k;j++) m=min(m,a[j]);
              cout<<m<<(i==n-k?"\n":" ");
          }
          return 0;
      }
      ```

      *`O(nk)` time — up to `4 * 10^10` comparisons. Too slow.*

      **② Optimization — monotonic deque, O(n) time, O(k) space (optimal)**

      Maintain the increasing-index deque; the front holds the index of the
      current window minimum. This is the tier we compile and verify.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(0);
          int n,k; cin>>n>>k;
          vector<long long> a(n);
          for(int i=0;i<n;i++) cin>>a[i];
          deque<int> dq;                    // indices, values increasing
          bool first=true;
          for(int i=0;i<n;i++){
              while(!dq.empty() && a[dq.back()] >= a[i]) dq.pop_back();
              dq.push_back(i);
              while(!dq.empty() && dq.front() <= i-k) dq.pop_front();
              if(i>=k-1){
                  if(first){ cout<<a[dq.front()]; first=false; }
                  else cout<<" "<<a[dq.front()];
              }
          }
          cout<<"\n";
          return 0;
      }
      ```

      *`O(n)` time (each index pushed/popped once), `O(k)` space.*

      **③ Alternative — multiset window, O(n log k) time**

      Keep the active window in a `std::multiset`; the window minimum is its
      smallest element (`*begin()`). Window update is O(log k) per slide.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(0);
          int n,k; cin>>n>>k;
          vector<long long> a(n);
          for(int i=0;i<n;i++) cin>>a[i];
          multiset<long long> s;
          for(int i=0;i<n;i++){
              s.insert(a[i]);
              if(i>=k) s.erase(s.find(a[i-k]));
              if(i>=k-1) cout<<*s.begin()<<(i==n-1?"\n":" ");
          }
          return 0;
      }
      ```

      *`O(n log k)` time, `O(k)` space. Slower than the deque but trivially
      simple; a useful fallback that stays correct.*

      # Code logic

      - **Increasing order = front is min.** We pop-back anything `>= a[i]`,
        so the deque's values are strictly increasing, front→back. The smallest
        is always at `front`.
      - **`>=` (not `>`) for the pop-back.** Discarding equal values keeps the
        deque shorter — an equal-but-older element can never beat the newer one,
        and using `>=` guarantees each index is processed exactly once.
      - **Popping stale fronts.** `dq.front() <= i - k` means the index has left
        the current window; it is dequeued when we slide.
      - **Answer only once a window is full.** `i >= k-1` gates the printout; the
        front of the deque at that moment is the window's minimum index. At the
        end the empty-pop condition (`i-k`) exactly matches `i - (i-k) = k` dead
        elements, keeping the deque's live span = the window.

      # Walkthrough

      Sample: `n = 8, k = 3`, `a = [1, 3, -1, -3, 5, 3, 6, 7]`. Expected output
      `-1 -3 -3 -3 3 3`.

      Using tier ② (deque holds indices; we show values):

      - `i=0` (1): push → deque `[1]`. not full.
      - `i=1` (3): 3 >= 1? no → push → `[1,3]`. not full.
      - `i=2` (-1): pop 3 (`-1 <= 3`), pop 1 (`-1 <= 1`) → push → `[-1]`. full →
        front `-1`. **print -1**.
      - `i=3` (-3): pop -1 → `[-3]`. full → **print -3**.
      - `i=4` (5): push → `[-3,5]`. full → front -3. **print -3**.
      - `i=5` (3): pop 5 → `[-3,3]`. full → **print -3**.
      - `i=6` (6): pop front -3 (index 3 <= 3, stale) → deque indices `[5,6]`,
        values `[3,6]`. full → front 3. **print 3**.
      - `i=7` (7): no pop-back (6 < 7) → push index 7 → `[5,6,7]`; no stale
        front (5 > 4). front index 5, value 3. **print 3**.

      Printed: `-1 -3 -3 -3 3 3` — matches expected. At the end the deque keeps
      indices `[5,6,7]`; only stale indices are ever dequeued, and each index
      enters and leaves exactly once, sustaining the `O(n)` bound.
