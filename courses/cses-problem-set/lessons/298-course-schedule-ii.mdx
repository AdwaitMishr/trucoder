      ## Theory — reconstructing an actual topological order

      A topological order is an ordering of vertices where every edge points
      *forward*. The classic "Course Schedule" problem asks only whether such an
      order exists. **Course Schedule II** goes further: it must **produce** one
      concrete order — or cleanly report that a cycle makes it impossible. The
      same Kahn's-algorithm idea that decides existence is also the way to
      *materialise* the order.

      **Kahn's algorithm as a builder.** Every vertex with in-degree 0 has no
      prerequisites and may be placed right now. Place it, "delete" its outgoing
      edges (decrement neighbours' in-degrees), and repeat. The sequence in which
      vertices reach in-degree 0 and are popped **is** the topological order.
      If the graph has a cycle, the vertices on it never drop to in-degree 0, so
      we finish with fewer than `n` placed → **IMPOSSIBLE**.

      **Why it is always a valid schedule.** When a vertex is popped, every
      edge into it has already been "deleted" by its tail, meaning every
      prerequisite was placed earlier. So the popped order satisfies every
      constraint. Ties among ready vertices are broken by queue/enumeration
      order — any tie-break yields a valid order.

      **Complexity.** Each vertex is pushed once, each edge is relaxed once →
      `O(n + m)` time and `O(n + m)` space. This is also exactly why the DFS
      alternative uses a finish-time stack: both techniques linearise a DAG, one
      from the sources, one from the sinks.

      :::tip
      **Interview tip:** "Return any valid ordering" is the follow-up to the
      boolean reachability question. Kahn's queue *is* the reconstructed order —
      there is no separate reconstruction phase. A frequent extension asks for
      the **lexicographically smallest** valid order; swapping the queue for a
      min-heap gives that in `O((n+m) log n)`. The impossibility test (placed
      count `< n` ⇒ cycle) is the sentence interviewers want to hear verbatim.
      :::

      ## The Problem

      There are `n` courses, numbered `1 … n`. Some courses depend on others: a
      prerequisite line `a b` means course `a` must be completed **before**
      course `b`. You must output **one valid order** in which a student can take
      all `n` courses, or report that it is impossible.

      **Input.** The first line has `n` and `m` (number of courses and
      prerequisite pairs). Then `m` lines each have two integers `a b` — course
      `a` before course `b`.

      **Output.** Print the `n` labels of a valid order, space-separated. If more
      than one valid order exists, print any. If no order is possible (a cycle in
      the dependencies), print `IMPOSSIBLE`.

      **Constraints** `1 ≤ n ≤ 2·10^5`, `1 ≤ m ≤ 2·10^5`.

      **Sample**
      ```
      Input:
      5 4
      1 2
      1 3
      3 4
      2 5

      Output:
      1 2 3 5 4
      ```
      Explanation: 1 is a prerequisite of 2 and 3; of those, 2 must precede 5
      and 3 must precede 4. One valid order is `1 2 3 5 4`.

      ### Solution — progressive tiers

      **① Brute force — O(n·(n+m)).** Repeatedly scan for *any* course whose
      prerequisites are all already placed, place it, and cross off the
      constraints it unlocks. Each of the `n` placements re-scans all
      `m` constraints → quadratic and quadratic-ish.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n,m; cin>>n>>m;
          vector<pair<int,int>> edges(m);
          vector<vector<int>> pre(n+1);
          for(int i=0;i<m;i++){ int a,b; cin>>a>>b; edges[i]={a,b}; pre[b].push_back(a); }
          vector<bool> done(n+1,false), placed(n+1,false);
          vector<int> order;
          for(int step=0; step<n; step++){
              int pick=-1;
              for(int v=1; v<=n && pick==-1; v++){
                  if(placed[v]) continue;
                  bool ok=true;
                  for(int p: pre[v]) if(!placed[p]){ ok=false; break; }
                  if(ok) pick=v;
              }
              if(pick==-1){ cout<<"IMPOSSIBLE\n"; return 0; }
              placed[pick]=true; order.push_back(pick);
          }
          for(int v: order) cout<<v<<" "; cout<<"\n";
      }
      ```

      **② Optimization — Kahn's algorithm, O(n+m) (submission).** Track in-degree;
      keep ready (in-degree 0) courses in a queue; pop one, append to the order,
      decrement neighbours, enqueue those reaching 0. Each operation is O(1), and
      `placed < n` at the end means a cycle.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n,m; cin>>n>>m;
          vector<vector<int>> adj(n+1);
          vector<int> indeg(n+1,0);
          for(int i=0;i<m;i++){ int a,b; cin>>a>>b; adj[a].push_back(b); indeg[b]++; }
          queue<int> q;
          for(int v=1; v<=n; v++) if(indeg[v]==0) q.push(v);
          vector<int> order;
          while(!q.empty()){
              int u=q.front(); q.pop();
              order.push_back(u);
              for(int to: adj[u]) if(--indeg[to]==0) q.push(to);
          }
          if((int)order.size()<n){ cout<<"IMPOSSIBLE\n"; return 0; }
          for(int v: order) cout<<v<<" ";
          cout<<"\n";
      }
      ```

      **③ Further optimization — lexicographically smallest order, O((n+m) log n).**
      Replace the FIFO queue with a **min-heap**: it always hands us the smallest
      currently-ready label, so the reconstructed order is the lexicographically
      smallest valid one. Same impossibility test.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n,m; cin>>n>>m;
          vector<vector<int>> adj(n+1);
          vector<int> indeg(n+1,0);
          for(int i=0;i<m;i++){ int a,b; cin>>a>>b; adj[a].push_back(b); indeg[b]++; }
          priority_queue<int, vector<int>, greater<>> pq;
          for(int v=1; v<=n; v++) if(indeg[v]==0) pq.push(v);
          vector<int> order;
          while(!pq.empty()){
              int u=pq.top(); pq.pop();
              order.push_back(u);
              for(int to: adj[u]) if(--indeg[to]==0) pq.push(to);
          }
          if((int)order.size()<n){ cout<<"IMPOSSIBLE\n"; return 0; }
          for(int v: order) cout<<v<<" "; cout<<"\n";
      }
      ```

      **④ Alternative — DFS with a finish-time stack, O(n+m).** Depth-first search
      with three-colour states (unvisited / on-stack / done). A back edge to a
      node still on the stack ⇒ cycle. Otherwise push each finished node onto a
      stack; popping it gives a topological order. This visits from the *sinks*
      side and is the other canonical reconstruction.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      vector<vector<int>> adj;
      vector<int> state;   // 0 unvisited, 1 on-stack, 2 done
      vector<int> fin;
      bool cyc = false;
      void dfs(int v){
          state[v]=1;
          for(int to: adj[v]){
              if(state[to]==0) dfs(to);
              else if(state[to]==1) cyc=true;
          }
          state[v]=2; fin.push_back(v);
      }
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n,m; cin>>n>>m;
          adj.assign(n+1,{});
          for(int i=0;i<m;i++){ int a,b; cin>>a>>b; adj[a].push_back(b); }
          state.assign(n+1,0);
          for(int v=1; v<=n; v++) if(state[v]==0) dfs(v);
          if(cyc){ cout<<"IMPOSSIBLE\n"; return 0; }
          for(int i=n-1;i>=0;i--) cout<<fin[i]<<" "; cout<<"\n";
      }
      ```

      ## Code logic

      The submission (② ) reconstructs the order inside the drive loop itself.

      1. **Adjacency + in-degree.** For each `a b` store `a → b` in `adj[a]` and
         `indeg[b]++`.
      2. **Seed the queue** with every `indeg == 0` vertex — these are "no
         prerequisites, take first".
      3. **Loop:** pop `u`, append to `order` (this *is* the reconstruction), then
         for each `to` in `adj[u]` decrement `indeg[to]`; the moment it hits 0,
         `to` becomes ready and is enqueued.
      4. **Post-condition:** if fewer than `n` were placed, the unplaced set is a
         directed cycle (every one has a prerequisite still inside it) →
         `IMPOSSIBLE`.

      The DFS alternative (④ ) mirrors it: "done time in decreasing order" equals
      a topological order, and a node pointed to by a node still on the stack is a
      cycle.

      ## Walkthrough

      **Input (sample):** `n = 5`, edges `1→2, 1→3, 3→4, 2→5`.

      1. **In-degrees:** `indeg = [1:0, 2:1, 3:1, 4:1, 5:1]`. Queue `= {1}`.
      2. **Pop 1** → order `[1]`. Relax `1→2` (`indeg[2]→0`, enqueue), `1→3`
         (`indeg[3]→0`, enqueue). Queue `= {2, 3}`.
      3. **Pop 2** → order `[1,2]`. Relax `2→5` (`indeg[5]→0`, enqueue).
         Queue `= {3, 5}`.
      4. **Pop 3** → order `[1,2,3]`. Relax `3→4` (`indeg[4]→0`, enqueue).
         Queue `= {5, 4}`.
      5. **Pop 5** → order `[1,2,3,5]`. **Pop 4** → order `[1,2,3,5,4]`.

      **Order:** `1 2 3 5 4` — exactly the sample output.

      **Actual vs expected:** identical ✓. (The min-heap variant ③ would instead
      return `1 2 3 4 5`, also valid.)

      **Cycle check:** for `n=3`, edges `1→2, 2→3, 3→1`, the algorithm places only
      `1` then stalls with `2,3` still unplaced → prints `IMPOSSIBLE`.
