      # Josephus Problem II

      **The technique: order-statistics for k-th removal.** This is the full Josephus
      generalization: at every round we **skip `k` children** and then remove the next,
      and `k` can be huge (up to `10^9`) while `n` can be `2 * 10^5`. Because the step is
      arbitrary, the fixed-step tricks of Josephus Problem I (queue, simple linked list)
      no longer stay cheap. We need a data structure that can answer one question
      repeatedly:

      > *Among the children still in the circle, who is at rank `r`?* — and — *then remove
      > them.*

      That is an **order-statistics query**: find the `k`-th smallest element and delete
      it, both in `O(log n)`. A **Fenwick tree** (BIT) does exactly this: it stores a `1`
      per live child, and a binary search over prefix sums locates the child standing at
      any given rank. (A balanced BST / policy-based tree, or a segment tree, does the
      same job.) This single idea — *index the survivors, locate by rank, delete* — is
      the whole problem.

      **When you reach for it:** counting-out and elimination-order problems with a
      variable/large step, and more broadly any bulk "k-th smallest plus delete" workload
      that queues (FIFO) or arrays can't answer cheaply. You'll meet the same
      k-th-removal pattern in order-by-value queries, inversion counting, and offline
      "next greater" style sweeps.

      **Worked mini-example (`n = 7, k = 2`).** Children `1..7`; skip 2, remove the 3rd
      child each round, restarting the count right after the removed child.

      - Skip `1, 2`, remove `3` → `1 2 4 5 6 7`.
      - Skip `4, 5`, remove `6` → `1 2 4 5 7`.
      - Skip `7, 1`, remove `2` → `1 4 5 7`.
      - Skip `4, 5`, remove `7` → `1 4 5`.
      - Skip `1, 4`, remove `5` → `1 4`.
      - Skip `1, 4`, remove `1` → `4`.
      - Remove `4`.

      Order: `3 6 2 7 5 1 4`.

      **Complexity.** Each removal answers a rank query + a single update, both
      `O(log n)` → **O(n log n)** time and **O(n)** space.

      :::tip
      **Interview tip:** The key phrase interviewers listen for is *ordering of the live
      set* — a Fenwick `kth` (binary search over prefix sums) or a policy-based tree
      solves it; a plain `std::set` cannot (no k-th element access). Nail the wrap-around
      bookkeeping: compute `r = (current_pos + k) % remaining`, locate rank `r+1`, and
      set `pos` to where the next child lives after deletion. Practise it for `k=10^9` so
      you remember to keep the running position in `long long`.
      :::

      # Question — Josephus Problem II

      Consider a game where there are `n` children (numbered `1, 2, ..., n`) in a
      circle. During the game, we repeatedly **skip `k` children** and then remove the
      next child, until none are left. In which order are the children removed?

      **Constraints:** `1 ≤ n ≤ 2 * 10^5`, `0 ≤ k ≤ 10^9`.

      **Input:** the only input line has two integers `n` and `k`.
      **Output:** print `n` integers — the removal order.

      Sample input:

      ```
      7 2
      ```

      Sample output:

      ```
      3 6 2 7 5 1 4
      ```

      # Solution — progressive tiers

      Every version below yields the same correct removal order; the difference is how
      fast a *rank query + delete* is.

      **① Brute force — O(n²)**

      Keep a `vector` of live children. Each round, advance the counting position by `k`
      modulo the current size and `erase` that child. `erase` shifts the rest of the
      array, so a round is `O(remaining)` → `O(n²)` total. Correct for small `n`, hopeless
      for `n = 2 * 10^5` (≈ 4·10¹⁰ element shifts).

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main() {
          int n; long long k; cin >> n >> k;
          vector<int> v(n); iota(v.begin(), v.end(), 1);
          vector<int> ans;
          long long pos = 0;
          while (!v.empty()) {
              long long r = (pos + k) % (long long)v.size();   // 0-based rank to remove
              ans.push_back(v[(int)r]);
              v.erase(v.begin() + (int)r);                      // O(size) shift
              pos = (v.empty()) ? 0 : (r % (long long)v.size()); // next start
          }
          for (int i = 0; i < n; i++) cout << ans[i] << (i + 1 == n ? '\n' : ' ');
      }
      ```

      Time: **O(n²)**. Space: **O(n)**.

      **② Optimization — Fenwick tree with binary-search k-th, O(n log n)**

      Replace the array with a Fenwick tree storing `1` for each live child. To remove
      the child at 0-based rank `r`, we locate the smallest original index whose live
      prefix count reaches `r+1` (a binary search over BIT prefix sums), emit it, and set
      its cell to `0`. Rank query + update are both `O(log n)`.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      struct Fenwick {
          int n; vector<int> bit;
          Fenwick(int n) : n(n), bit(n + 1, 0) {}
          void add(int i, int v) { for (; i <= n; i += i & -i) bit[i] += v; }
          int sum(int i) { int s = 0; for (; i > 0; i -= i & -i) s += bit[i]; return s; }
          int kth(int k) {        // smallest index whose prefix sum >= k (1-based rank)
              int lo = 1, hi = n, ans = n;
              while (lo <= hi) {
                  int mid = (lo + hi) / 2;
                  if (sum(mid) >= k) { ans = mid; hi = mid - 1; } else lo = mid + 1;
              }
              return ans;
          }
      };
      int main() {
          int n; long long k; cin >> n >> k;
          Fenwick fw(n);
          for (int i = 1; i <= n; i++) fw.add(i, 1);
          vector<int> ans;
          long long pos = 0; int rem = n;
          while (rem > 0) {
              long long r = (pos + k) % rem;      // 0-based rank of the child to remove
              int idx = fw.kth((int)r + 1);       // true (1-based original) child id
              ans.push_back(idx);
              fw.add(idx, -1);                    // remove it
              pos = (rem > 1) ? (r % (rem - 1)) : 0; // next count starts here
              rem--;
          }
          for (int i = 0; i < n; i++) cout << ans[i] << (i + 1 == n ? '\n' : ' ');
      }
      ```

      Time: **O(n log n)**. Space: **O(n)**.

      **③ Further optimization — segment tree k-th, O(n log n)**

      A **segment tree** (sum over each node) answers the same "smallest index with
      prefix sum ≥ k" by walking down from the root in `O(log n)` — no binary search, one
      descent per query. Functionally identical big-O; choose it when you find the
      single walk more natural than BIT + binary search.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int n; long long k; vector<int> seg;
      void build(int p, int l, int r) {
          if (l == r) { seg[p] = 1; return; }
          int m = (l + r) / 2; build(p * 2, l, m); build(p * 2 + 1, m + 1, r);
          seg[p] = seg[p * 2] + seg[p * 2 + 1];
      }
      int kth(int p, int l, int r, int k) {   // smallest index with prefix sum >= k
          if (l == r) return l;
          if (seg[p * 2] >= k) return kth(p * 2, l, (l + r) / 2, k);
          return kth(p * 2 + 1, (l + r) / 2 + 1, r, k - seg[p * 2]);
      }
      void upd(int p, int l, int r, int i, int v) {
          if (l == r) { seg[p] = v; return; }
          int m = (l + r) / 2;
          if (i <= m) upd(p * 2, l, m, i, v); else upd(p * 2 + 1, m + 1, r, i, v);
          seg[p] = seg[p * 2] + seg[p * 2 + 1];
      }
      int main() {
          cin >> n >> k;
          seg.assign(4 * n, 0); build(1, 1, n);
          vector<int> ans; long long pos = 0; int rem = n;
          while (rem > 0) {
              long long r = (pos + k) % rem;
              int idx = kth(1, 1, n, (int)r + 1);
              ans.push_back(idx);
              upd(1, 1, n, idx, 0);
              pos = (rem > 1) ? (r % (rem - 1)) : 0;
              rem--;
          }
          for (int i = 0; i < n; i++) cout << ans[i] << (i + 1 == n ? '\n' : ' ');
      }
      ```

      Time: **O(n log n)**. Space: **O(n)**.

      **④ Alternative — policy-based ordered tree, O(n log n)**

      A **balanced order-statistics tree** (GNU policy-based data structure, or any
      custom AVL/red-black with subtree sizes) natively exposes "find the element at
      rank `k`" and "erase" in `O(log n)` each. It's the most *readable* route — you
      literally think in ranks — at the cost of a slower constant factor than a BIT.
      Both are widely accepted; pick based on clarity vs. constant-factor priority.

      ```cpp
      #include <bits/stdc++.h>
      #include <ext/pb_ds/assoc_container.hpp>
      #include <ext/pb_ds/tree_policy.hpp>
      using namespace std; using namespace __gnu_pbds;
      template<class T> using ordered_set =
          tree<T, null_type, less<T>, rb_tree_tag, tree_order_statistics_node_update>;
      int main() {
          int n; long long k; cin >> n >> k;
          ordered_set<int> s;
          for (int i = 1; i <= n; i++) s.insert(i);
          vector<int> ans;
          long long pos = 0;
          while (s.size()) {
              long long r = (pos + k) % (long long)s.size();
              int child = *s.find_by_order((int)r);   // element at rank r (0-based)
              ans.push_back(child);
              s.erase(child);
              pos = (s.size()) ? (r % (long long)s.size()) : 0;
          }
          for (int i = 0; i < n; i++) cout << ans[i] << (i + 1 == n ? '\n' : ' ');
      }
      ```

      Time: **O(n log n)**. Space: **O(n)**.

      # Code-logic

      Read the **② Fenwick** version — it is the canonical one.

      - `Fenwick fw(n)` stores a `1` per child; `for (i=1..n) fw.add(i,1)` marks all as
        live. The prefix sum `fw.sum(x)` counts how many live children are among `1..x`,
        i.e. the *rank* of child `x` (its position in the survivor order).
      - `long long pos = 0` — the live child we will count as "already the starting
        point". Because `k` can be `10^9`, `pos + k` overflows `int` → it is `long long`.
      - `long long r = (pos + k) % rem` — walking `k` survivors wraps around to a
        0-based rank `r` within the current circle; this is the child to remove (as a
        *rank*, not a fixed id).
      - `int idx = fw.kth((int)r + 1)` — convert that rank back into a concrete child
        id. `kth(t)` binary-searches the smallest index whose live-prefix count reaches
        `t`. Since rank `r` is 0-based, we ask for rank `r+1`.
      - `fw.add(idx, -1)` — kill child `idx` so future prefix sums stop counting him.
      - `pos = (r % (rem - 1))` — after the child at rank `r` leaves, the *next* child
        (the old rank `r+1`, or the front if `r+1` wrapped) now sits at that same rank in
        the shrunken circle, so the next count starts there. Guarded for `rem == 1`.
      - The loop runs exactly `n` times; every round is one `O(log n)` query plus one
        `O(log n)` update → **O(n log n)**.

      The **④ policy-based** version is the same algorithm expressed directly in ranks:
      `find_by_order(r)` *is* the k-th query and `erase(child)` *is* the delete.
