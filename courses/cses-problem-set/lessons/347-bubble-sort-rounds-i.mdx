      ## Theory — how many passes until bubble sort finishes?

      **Bubble sort** sorts an array by repeatedly sweeping left-to-right over
      adjacent pairs, swapping any pair that is out of order (`a[i] > a[i+1]`).
      One full sweep is called a **round** (or a *pass*). After enough rounds the
      array is sorted, and a subsequent round performs zero swaps.

      **The key structural question** for this problem is: *how many rounds are
      needed?* The answer has a clean formula. During one round, an element can
      move **left by at most one position** (it gets swapped past its immediate
      left neighbour at most once per sweep). So an element that must cross `k`
      strictly-larger elements currently sitting to its left needs exactly `k`
      rounds of "moving left", plus **one final round** to detect that a pass
      made zero swaps:

      ```
      rounds = 1 + max over elements i of  (#{ j < i : a[j] > a[i] })
      ```

      The term `#{j < i : a[j] > a[i]}` counts the *greater elements before
      position i* — equivalently, how far to the left element `i` must travel.
      Its maximum across the whole array is the bottleneck that decides the
      total number of rounds. (Elements that only move *right* never constrain
      the answer, because a rightward slide has no per-round speed limit.)

      :::tip
      **Interview tip:** "How many bubble-sort passes does this array need?"
      appears frequently as a warm-up that probes whether you see the
      *left-moves-one-per-pass* invariant instead of blindly simulating. The
      partner question — "how many **swaps** in total?" — is exactly the
      inversion count, a very common follow-up.
      :::

      ## The Problem

      You are given an array of `n` integers. Every round you run **one complete
      left-to-right pass** of bubble sort: for `i` from `1` to `n−1`, if
      `a[i−1] > a[i]` you swap them. The array is "done" once a full pass makes
      **no swaps**.

      Your task: find the minimum number of rounds needed to be certain the
      array is sorted — i.e. count passes until a pass performs zero swaps.

      **Input.** The first line has `n`. The second line has `n` integers
      `a[0], …, a[n−1]`.

      **Output.** One integer: the number of rounds.

      **Constraints.**
      - `1 ≤ n ≤ 2000`
      - `1 ≤ a[i] ≤ 10^9`

      **Sample.** (n = 3, `3 1 2`)

      **Input:**
      ```
      3
      3 1 2
      ```

      **Output:**
      ```
      2
      ```

      ### Solution — progressive tiers

      **① Brute force — simulate the rounds — O(n² · r).** Literally perform
      pass after pass, counting them, until a pass makes no swaps.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          int n; if(!(cin>>n)) return 0;
          vector<int> a(n); for(int&x:a) cin>>x;
          int rounds = 0;
          while(true){
              rounds++;
              bool any = false;
              for(int i=0;i+1<n;i++)
                  if(a[i]>a[i+1]){ swap(a[i],a[i+1]); any=true; }
              if(!any) break;
          }
          cout << rounds << "\n";
      }
      ```
      *Complexity: O(n²·r) worst case — in the worst case (`r ≈ n`) this is
      O(n³), too slow for `n = 2000` on big inputs. Correct, but wasteful.*

      **② Optimization — O(n²) via the left-move formula.** Instead of
      simulating, directly compute `rounds = 1 + max_i (#{j<i : a[j]>a[i]})`.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(nullptr);
          int n; if(!(cin>>n)) return 0;
          vector<int> a(n); for(int&x:a) cin>>x;
          int mx = 0;
          for(int i=0;i<n;i++){
              int c = 0;
              for(int j=0;j<i;j++) if(a[j] > a[i]) c++;
              mx = max(mx, c);
          }
          cout << mx + 1 << "\n";
      }
      ```
      *Complexity: O(n²) time, O(1) extra space — instant for `n ≤ 2000`,
      and the formula works for *all* inputs, not just sorted ones.*

      **④ Alternative — think in inversions.** The per-element count
      `#{j<i : a[j]>a[i]}` is the number of *inversions* (i,j) with
      `j<i` *ending at* `i`. The answer is `1 + max over inversion-terminators
      i`. This is the same O(n²) cost as ② but framed as an inversion problem —
      the viewpoint that generalises to the O(n log n) Fenwick-tree solution in
      *Bubble Sort Rounds II*. It's not faster here, just a cleaner mental model.

      ## Code logic

      `solve(n, a)` — O(n²). Key lines:

      1. **Outer loop over `i`** fixes the element that is "settling left".
      2. **Inner loop `j < i`** counts how many strictly-greater values
         `a[j] > a[i]` already sit before it — each one forces one round of
         leftward travel.
      3. **`mx = max(mx, c)`** takes the bottleneck element: the one that must
         cross the most larger values.
      4. **`cout << mx + 1`** adds the final "no-swap" confirmation round.

      ## Walkthrough

      **Input:** `n = 3`, `a = [3, 1, 2]`.

      Count greater-before for each element:

      - `i=0` `3`: nothing before → `c=0`.
      - `i=1` `1`: `{3}` → `c=1`.
      - `i=2` `2`: `{3}` (1 and 3 are before it, only 3 is greater) → `c=1`.

      Max = `1`, so **rounds = 1 + 1 = 2**. ✓

      Cross-check by actually simulating:

      - **Round 1:** swaps `(3,1)→(1,3)` then `(3,2)→(2,3)`. Array becomes
        `[1,2,3]`. One swap happened.
      - **Round 2:** `[1,2,3]` — no swaps. Done.

      Total **2 rounds**, matching the sample output.
