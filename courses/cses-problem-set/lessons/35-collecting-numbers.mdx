      # Collecting Numbers

      **The technique: an inverse-index array that counts "breaks" between
      consecutive values.** The array is a permutation of `1..n`: each value
      appears exactly once. To collect `1, 2, ..., n` in order, in each round we
      sweep the array left-to-right and grab as many *consecutive-ordered*
      numbers as possible.

      The decisive observation: if value `v` sits **after** value `v−1` in the
      array, then both can be collected in the **same** round (we pick `v−1`,
      keep sweeping right, and reach `v` later). But if value `v` sits **before**
      value `v−1` (`pos[v] < pos[v−1]`), we *cannot* collect `v` in the round
      that collected `v−1` — we already passed it — so value `v` **forces a new
      round**. Hence:

      ```
      rounds = 1 + (# of v in 2..n such that pos[v] < pos[v-1])
      ```

      **When you reach for it:** any problem where you track the relative order
      of consecutive items in a permutation. Building the inverse map
      `pos[value] = index` converts "where does value X appear?" into an O(1)
      array lookup, and a comparison of consecutive values' positions becomes a
      one-line check.

      **Worked mini-example.** `[4, 2, 1, 5, 3]`. Inverse: `pos[1]=3, pos[2]=2,
      pos[3]=5, pos[4]=1, pos[5]=4`.

      | pair | pos[v] <? pos[v−1] | new round? |
      |------|--------------------|------------|
      | 2 vs 1 | 2 < 3 ✓ | yes |
      | 3 vs 2 | 5 < 2? no | — |
      | 4 vs 3 | 1 < 5 ✓ | yes |
      | 5 vs 4 | 4 < 1? no | — |

      `rounds = 1 + 2 = 3`. (Round 1: `1`; Round 2: `2,3`; Round 3: `4,5`.) ✓

      **Complexity.** One pass to build `pos`, one pass to count → **O(n)** time,
      **O(n)** space. This is optimal — you must read every element.

      :::tip
      **Interview tip:** the "permutation + inverse index" pattern is extremely
      common — swap-in-a-permutation questions, "how many passes to sort/collect"
      problems, and CSES's own Collecting Numbers II (with updates). The reflex
      to train: when asked "how many rounds/passes to collect 1..n", *do not
      simulate the rounds* — build `pos[value]` and count how many consecutive
      pairs are out of order (`pos[i+1] < pos[i]`). Interviewers often add a
      follow-up where swaps happen dynamically, which is exactly Collecting
      Numbers II.
      :::

      # Question — Collecting Numbers

      You are given an array that contains each number between `1` and `n`
      **exactly once** (a permutation). Your task is to collect the numbers from
      `1` to `n` in increasing order. On each round, you go through the array
      from left to right and collect as many numbers as possible. What is the
      total number of rounds?

      **Constraints:**
      - `1 ≤ n ≤ 2·10^5`

      **Input:** the first line has an integer `n` (array size). The next line
      has `n` integers — a permutation of `1..n`.

      **Output:** one integer — the number of rounds.

      Sample input:

      ```
      5
      4 2 1 5 3
      ```

      Sample output:

      ```
      3
      ```

      (Round 1 collects `1`, round 2 collects `2, 3`, round 3 collects `4, 5`.)

      ### Solution — progressive tiers

      **① Brute force — simulate the rounds, O(n · R) worst-case O(n²)**
      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      int main() {
          ios::sync_with_stdio(false);
          cin.tie(nullptr);
          int n; cin >> n;
          vector<int> a(n);
          for (int i = 0; i < n; ++i) cin >> a[i];

          vector<char> collected(n + 1, 0);
          int next = 1, rounds = 0;
          while (next <= n) {                 // one pass per round
              ++rounds;
              for (int i = 0; i < n && next <= n; ++i)
                  if (a[i] == next) {         // we may take it when we pass it
                      collected[a[i]] = 1;
                      ++next;
                  }
          }
          cout << rounds << "\n";
          return 0;
      }
      ```
      O(n · R) — up to O(n²) when the array is decreasing (`n, n−1, ..., 1`
      needs `n` rounds). Correct but too slow for `n = 2·10^5`.

      **② Optimization — inverse index + count breaks, O(n)** (the chosen solution)
      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      int main() {
          ios::sync_with_stdio(false);
          cin.tie(nullptr);
          int n; cin >> n;
          vector<int> pos(n + 1);              // pos[value] = its index (1-based)
          for (int i = 1; i <= n; ++i) {
              int v; cin >> v;
              pos[v] = i;                      // inverse mapping
          }

          int rounds = 1;
          for (int v = 2; v <= n; ++v)
              if (pos[v] < pos[v - 1]) ++rounds;   // v appears before v-1
          cout << rounds << "\n";
          return 0;
      }
      ```
      O(n) time, O(n) space. A single pass to build the map and a single pass to
      count. Optimal.

      **③ No further optimization — already linear**
      ```cpp
      // The answer is a single formula over adjacent inverse positions. There
      // is no meaningful faster tier: reading n values is Omega(n), and the
      // count over v = 2..n is also Omega(n). O(n) is the lower bound.
      ```
      Nothing to improve — both construction and counting are minimal.

      **④ Alternative — rolling "round assignment" DP, O(n)**
      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      int main() {
          ios::sync_with_stdio(false);
          cin.tie(nullptr);
          int n; cin >> n;
          vector<int> pos(n + 1);
          for (int i = 1; i <= n; ++i) { int v; cin >> v; pos[v] = i; }

          int f = 1;                       // rounds up to and including value 1
          for (int v = 2; v <= n; ++v)
              f = f + (pos[v] < pos[v - 1] ? 1 : 0);   // new round iff break
          cout << f << "\n";
          return 0;
      }
      ```
      O(n) time, O(n) space. The same computation restated as a recurrence
      `f[v] = f[v-1] + [pos[v] < pos[v-1]]` over the value order — makes the
      incremental structure explicit, useful framing before the update variant
      (Collecting Numbers II).

      # Code-logic

      The chosen tier is **② inverse-index counting**. The two lines that matter:

      - `pos[v] = i;` (in the read loop) — this is the *inverse* index: instead
        of asking "what is at position `i`" we record "value `v` is at position
        `i`". Array indexing is then enough to jump straight to where any value
        lives.
      - `if (pos[v] < pos[v - 1]) ++rounds;` — the crux. Value `v` can be
        collected in the same round as `v−1` exactly when `v` appears *after*
        `v−1` in the array. If `v` appears *before*, then by the time the round
        reaches `v`'s position it has already passed it, so `v` needs a fresh
        round. Every value that needs a fresh round adds exactly one, and add
        the initial `1` for the very first value.

      Compare with the brute-force tier: the simulation actually re-scans the
      array per round; this counted version derives the answer from positions
      alone, never simulating.

      # Walkthrough

      **Input:**
      ```
      5
      4 2 1 5 3
      ```

      Build the inverse map: `pos[1]=3, pos[2]=2, pos[3]=5, pos[4]=1, pos[5]=4`.

      | v | pos[v−1] | pos[v] | pos[v] < pos[v−1]? | rounds |
      |---|----------|--------|--------------------|--------|
      | 1 | — | 3 | — | 1 (start) |
      | 2 | 3 | 2 | yes | 2 |
      | 3 | 2 | 5 | no | 2 |
      | 4 | 5 | 1 | yes | 3 |
      | 5 | 1 | 4 | no | 3 |

      Result: **3** ✓. Simulation of the actual rounds:

      - Round 1: sweep → collect `1` (only number we may take yet).
      - Round 2: sweep → collect `2` at index 2, then `3` at index 5.
      - Round 3: sweep → collect `4` at index 1, then `5` at index 4.

      **Edge cases:**
      - Already sorted: `5 / 1 2 3 4 5` → all `pos[v] > pos[v−1]`, rounds = 1.
      - Reverse sorted: `4 / 4 3 2 1` → `pos[1]=4,pos[2]=3,pos[3]=2,pos[4]=1`;
        every pair is a break → rounds = 4.
      - `n = 1`: `1 / 1` → rounds = 1.
