      # Sliding Window Advertisement — the shortest span covering every ad type

      A campaign runs `m` different ad types. The daily log is a sequence of
      `n` ads, each of type `1..m`. We want the **shortest contiguous run of
      days (a window) that contains at least one ad of every type**. If several
      shortest windows tie, we report the earliest one.

      This is the classic **minimum-window substring** problem ("find the
      shortest substring containing all letters of a required set") in sliding
      form, solved with the **two-pointer / sliding-window** technique.

      ## The two-pointer idea

      Run a right pointer `r` that keeps adding ads, and a left pointer `l`
      that shrinks the window as far as it safely can:

      1. Expand `r` until the window `[l, r]` has **all** `m` types
         (`covered == m`).
      2. While the window still covers all `m` types and the leftmost ad
         `a[l]` occurs more than once, **shrink** `l` (drop `a[l]`).
      3. Record the current window `[l, r]` — for this fixed right end this is
         the shortest window covering everything.
      4. Advance `r` and repeat.

      Because `l` and `r` each only ever move right, the whole thing is a
      single pass: `O(n)`.

      ## Tracking "covered"

      Keep `cnt[x]` = number of times ad type `x` appears in the window, and a
      counter `covered` = how many of the `m` types have `cnt > 0`. Adding a
      type whose count was `0` increments `covered`; removal is the exact
      opposite. The window "covers all ads" iff `covered == m`.

      :::tip
      **Interview tip:** "shortest/longest window satisfying a covering
      condition" is the textbook trigger for the shrinkable two-pointer
      (a.k.a. sliding-window / *minimum window substring*). The condition here
      — "all `m` types present" — is monotone under expansion, which is
      exactly what makes the two-pointer provably optimal: greedily expanding
      then shrinking never skips the true minimum.
      :::

      # The Problem

      A company displays `m` different types of advertisements. The
      advertisement log over `n` days lists, for each day, the *type* of ad
      shown that day (an integer from `1` to `m`).

      Find the **shortest contiguous span of days** (a window `[l, r]` of the
      sequence) that contains **at least one ad of every type**. If there are
      several shortest spans, print the **earliest** one (smallest `l`). If no
      contiguous span contains all `m` types, print `-1`.

      ## Input

      The first input line has two integers `n` and `m`. The next line has `n`
      integers `a_1, a_2, …, a_n` (the ad type of each day).

      **Constraints:** `1 <= m <= n <= 2*10^5`, `1 <= a_i <= m`

      ## Output

      If a valid span exists: print its **length** on the first line, and its
      **start and end positions** (0-indexed or 1-indexed as stated) on the
      second. Otherwise print `-1`.

      ## Sample

      **Input:**
      ```
      7 3
      1 2 1 3 2 1 3
      ```
      **Output:**
      ```
      3
      2 4
      ```
      (Positions are **1-indexed** here; "earliest" means smallest start day.)
      The shortest covering spans have length `3`; several exist — `[1,3,2]` at
      days `2–4`, `[3,2,1]` at days `4–6`, `[2,1,3]` at days `5–7`. The
      leftmost one (days `2–4`) is printed. No length-2 window contains all
      three types.

      ### Solution — progressive tiers

      **① Brute force — O(n²)**

      For every start `l`, extend `r` until all `m` types are covered; keep the
      shortest found. Correct, quadratic.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(0);
          int n,m; cin>>n>>m; vector<int> a(n); for(auto&x:a) cin>>x;
          int best=INT_MAX, bestL=-1;
          for(int l=0; l<n; l++){
              vector<int> seen(m+1,0); int covered=0;
              for(int r=l; r<n; r++){
                  if(seen[a[r]]++==0) covered++;
                  if(covered==m){ if(r-l+1<best){ best=r-l+1; bestL=l; } break; }
              }
          }
          if(bestL==-1) cout<<"-1\n";
          else cout<<best<<"\n"<<bestL+1<<" "<<bestL+best<<"\n";
          return 0;
      }
      ```

      *`O(n²)` — too slow for `n = 2*10^5`.*

      **② Optimization — two pointers, O(n) (optimal)**

      Expand `r` until covered, then shrink `l` while still covered. Reporting
      the leftmost shortest is handled because we only update `best`/`bestL`
      when a strictly shorter length is found (the earliest tie is kept). This
      is the tier we compile and verify.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;
      int main(){
          ios::sync_with_stdio(false); cin.tie(0);
          int n,m; cin>>n>>m; vector<int> a(n); for(auto&x:a) cin>>x;
          vector<int> cnt(m+1,0);
          int covered=0, best=INT_MAX, bestL=-1, l=0;
          for(int r=0;r<n;r++){
              if(cnt[a[r]]++==0) covered++;
              while(covered==m && cnt[a[l]]>1){ cnt[a[l]]--; l++; }   // shrink while removable
              if(covered==m && r-l+1<best){ best=r-l+1; bestL=l; }
          }
          if(bestL==-1) cout<<"-1\n";
          else cout<<best<<"\n"<<bestL+1<<" "<<bestL+best<<"\n";
          return 0;
      }
      ```

      *`O(n)` time, `O(m)` space. Each `l` and `r` advances at most `n` times.*

      **③ Note** — no genuinely different algorithm beats O(n): the covering
      condition is monotone under expansion (a bigger window cannot lose a type
      it already contains), and monotonicity of the condition is precisely what
      makes the two-pointer exhaustive. A binary search on the answer length
      plus an O(n) check gives O(n log n) and is a nice backup idea, but the
      direct two-pointer is the intended solution; we skip a fourth tier.
  - type: markdown
    content: |
      # Code logic

      - **`cnt[a[l]]>1` is the shrink guard.** We may drop `a[l]` only if it
        appears more than once; otherwise dropping it would break the
        `covered==m` invariant. So `while (covered==m && cnt[a[l]]>1)` shaves
        left as far as possible without losing a type.
      - **Earliest-tie handling.** `best`/`bestL` update only when
        `r-l+1 < best` (strictly less), so of equal-length windows the first
        (smallest `l`) survives.
      - **Positions are 1-indexed when printed.** Internally everything is
        0-indexed; the output adds `+1`. A shortest span of length `best`
        starting at 0-indexed `bestL` runs to `bestL + best - 1`
        (1-indexed: `bestL+1` to `bestL+best`).
      - **Impossible case.** If no window ever reaches `covered==m`, `bestL`
        stays `-1` and we print `-1`.
