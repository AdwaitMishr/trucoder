      # Concert Tickets

      **The technique: a balanced multiset with `upper_bound`/`lower_bound`.**
      There are `n` tickets (each with a price) and `m` customers who arrive
      one after another. A customer announces the maximum price they will pay
      and receives the ticket with the *highest* price that does not exceed
      that cap; the ticket is then removed (it cannot be sold twice). If no
      ticket is cheap enough, the customer gets nothing (`-1`).

      **When you reach for it:** "repeatedly query for the largest element ≤ K
      **and delete it**" — a form of dynamic predecessor search. The challenge
      is that removal changes the data, so a static sorted array is not enough:
      deleting from a vector costs O(n) per removal. The right tool is a
      **balanced binary search tree** that supports find **and** delete in
      **O(log n)** each.

      **Why a `std::multiset`?** C++ gives us `std::multiset`, a balanced BST
      (typically a red-black tree) that:
      - `upper_bound(K)` returns the first iterator with value `> K`. Its
        **predecessor** (one step before) is the largest stored value `≤ K` —
        exactly the ticket we want.
      - `erase(it)` deletes that single element in O(log n).
      - Duplicates are allowed (two tickets at the same price), which is why we
        use `multiset` (element keys may repeat) rather than `set`.

      **Worked mini-example.** Tickets `[5, 3, 7, 8, 5]`. Customers pay caps
      `[4, 8, 3]`.
      - multiset = `{3, 5, 5, 7, 8}`. Cap `4`: `upper_bound(4)` → first `>4` is
        `5` (begin); predecessor is `3`. Sell `3`. Multiset `{5, 5, 7, 8}`.
      - Cap `8`: `upper_bound(8)` = `end`; predecessor is `8`. Sell `8`.
        Multiset `{5, 5, 7}`.
      - Cap `3`: `upper_bound(3)` = first `>3` is `5` which **is** the begin
        iterator → no cheaper ticket. Print `-1`.
      Answer: `[3, 8, -1]`. ✓

      **Complexity.** Each customer does one O(log n) search and one O(log n)
      deletion → **O((n + m) log n)** time, O(n) space.

      :::tip
      **Interview tip:** this is the classic "largest element ≤ K with
      deletions" pattern (a.k.a. predecessor queries). The subtle point to
      verbalize: `upper_bound(K)` finds the first value **strictly above** K,
      so "one step back" is the largest value **≤ K**; and when that
      `upper_bound` lands on `begin()`, no ticket qualifies → `-1`. Also note
      `std::lower_bound` is the **≥** variant — you want `upper_bound` here so
      a ticket priced exactly at the cap is still sold. Interviewers love
      asking why a sorted *vector* plus binary search is too slow (the O(n)
      vector erase) and why a balanced BST fixes it.
      :::

      # Question — Concert Tickets

      There are `n` concert tickets available, each with a certain price. Then,
      `m` customers arrive, one after another. Each customer announces the
      maximum price they are willing to pay for a ticket, and after this, they
      will get a ticket with the nearest possible price such that it does not
      exceed the maximum price.

      **Constraints:** `1 ≤ n, m ≤ 2·10^5`, `1 ≤ h_i, t_i ≤ 10^9`.

      **Input:** The first input line contains integers `n` and `m`: the number
      of tickets and the number of customers. The next line contains `n`
      integers `h_1, ..., h_n`: the price of each ticket. The last line contains
      `m` integers `t_1, ..., t_m`: the maximum price for each customer in the
      order they arrive.

      **Output:** Print, for each customer, the price that they will pay for
      their ticket. After this, the ticket cannot be purchased again. If a
      customer cannot get any ticket, print `-1`.

      Sample input:

      ```
      5 3
      5 3 7 8 5
      4 8 3
      ```

      Sample output:

      ```
      3
      8
      -1
      ```

      ### Solution — progressive tiers

      **① Brute force — O(n·m)**

      Sort the tickets, then for each customer scan the whole array for the
      largest unused ticket priced ≤ cap.

      ```cpp
      #include <bits/stdc++.h>
      using namespace std;

      vector<long long> solve(vector<long long> h, const vector<long long>& t) {
          sort(h.begin(), h.end());
          int n = (int)h.size();
          vector<bool> used(n, false);
          vector<long long> res;
          for (long long maxp : t) {
              long long best = -1, bestIdx = -1;
              for (int j = 0; j < n; ++j) {
                  if (!used[j] && h[j] <= maxp && h[j] > best) {
                      best = h[j]; bestIdx = j;
                  }
              }
              if (bestIdx >= 0) used[bestIdx] = true;
              res.push_back(best);
          }
          return res;
      }
      ```

      **O(n·m)** time — ~4·10^10 steps for `n = m = 2·10^5`. Way too slow.

      **② Multiset + upper_bound — O((n + m) log n) (the solution)**

      Load prices into a multiset; each customer finds its ticket with
      `upper_bound` and erases it.

      ```cpp
      vector<long long> solve(vector<long long> h, const vector<long long>& t) {
          multiset<long long> tickets(h.begin(), h.end());
          vector<long long> res;
          res.reserve(t.size());
          for (long long maxp : t) {
              auto it = tickets.upper_bound(maxp);   // first ticket with price > maxp
              if (it == tickets.begin()) {           // no ticket with price <= maxp
                  res.push_back(-1);
              } else {
                  --it;                              // largest ticket with price <= maxp
                  res.push_back(*it);
                  tickets.erase(it);                 // remove the sold ticket
              }
          }
          return res;
      }
      ```

      **O((n + m) log n)** time, O(n) space. This is the CSES submission.

      **③ Further optimization — none (O(log n) per customer is optimal)**

      Each customer fundamentally needs a predecessor query *plus* a deletion
      in a changing set; both are Ω(log n) for a comparison-based structure,
      and we have exactly that. No meaningful improvement exists. Skip.

      **④ Alternative algorithm — coordinate compression + Fenwick tree
      (O((n + m) log n))**

      Same asymptotic speed, driven by a different data structure. Compress the
      distinct prices to ranks `1..m`; a Fenwick (binary indexed) tree stores
      the count of available tickets per rank. For each customer:
      find how many available tickets have price `≤ cap` (a prefix sum), then
      "find by order" index of the last available one and decrement its count.

      ```cpp
      struct Fenwick {
          int n; vector<int> bit;
          Fenwick(int n) : n(n), bit(n + 1, 0) {}
          void add(int i, int d) { for (; i <= n; i += i & -i) bit[i] += d; }
          int sum(int i) { int s = 0; for (; i > 0; i -= i & -i) s += bit[i]; return s; }
          int find_by_order(int k) { // smallest idx with prefix sum >= k
              int idx = 0, step = 1;
              while ((step << 1) <= n) step <<= 1;
              for (; step > 0; step >>= 1) {
                  int nx = idx + step;
                  if (nx <= n && bit[nx] < k) { idx = nx; k -= bit[nx]; }
              }
              return idx + 1;
          }
      };

      vector<long long> solve(vector<long long> h, const vector<long long>& t) {
          sort(h.begin(), h.end());
          vector<long long> prices = h;
          prices.erase(unique(prices.begin(), prices.end()), prices.end());
          int m = (int)prices.size();
          Fenwick fw(m);
          for (long long pr : h) {
              int idx = int(lower_bound(prices.begin(), prices.end(), pr) - prices.begin()) + 1;
              fw.add(idx, 1);
          }
          vector<long long> res;
          for (long long maxp : t) {
              int r = int(upper_bound(prices.begin(), prices.end(), maxp) - prices.begin());
              if (r == 0) { res.push_back(-1); continue; }
              int total = fw.sum(r);
              if (total == 0) { res.push_back(-1); continue; }
              int idx = fw.find_by_order(total);   // last available price among ranks 1..r
              res.push_back(prices[idx - 1]);
              fw.add(idx, -1);
          }
          return res;
      }
      ```

      **O((n + m) log n)** time, O(n) space. A great bridge into Fenwick/order
      statistics for harder problems, though a bit more code than the
      multiset.

      # Code-logic

      The multiset tier is short; the meaning of each line matters.

      - **Build.** `multiset<long long> tickets(h.begin(), h.end());` inserts
        all ticket prices into a balanced BST. Duplicates are kept (two tickets
        priced `5`).
      - **`upper_bound(maxp)` vs `lower_bound(maxp)`.** `upper_bound` returns
        the first value **strictly greater** than `maxp`; `lower_bound` returns
        the first value **`>= maxp`**. We need the largest price **`≤ maxp`**,
        so we step back from `upper_bound`. Using `upper_bound` also correctly
        sells a ticket priced *exactly* at the cap (its predecessor).
      - **The `it == tickets.begin()` guard.** If `upper_bound(maxp)` already
        points at the first element, every ticket is priced above `maxp` — no
        affordable ticket exists. Print `-1`. Crucially we do **not** `--it`
        here, or we would dereference `begin()-1` (undefined behaviour).
      - **`--it` then `erase(it)`.** One step back is the largest remaining
        price `≤ maxp`. We erase exactly that one iterator value, keeping the
        other copies of the same price intact (that's the multiset behaviour).

      The Fenwick tier reuses the same idea differently: ranks replace raw
      prices, counts replace the tree, `prefix_sum(r)` = how many tickets are
      available at price `≤ cap`, and `find_by_order(total)` pins the last
      available rank inside that prefix.

      # Walkthrough

      **Input:**

      ```
      5 3
      5 3 7 8 5
      4 8 3
      ```

      Expected output:

      ```
      3
      8
      -1
      ```

      Multiset starts as `{3, 5, 5, 7, 8}`.

      | customer | cap | upper_bound(cap) | action | sold | multiset after |
      |----------|-----|------------------|--------|------|----------------|
      | 1 | 4 | first `>4` = `5` (not begin) | `--it` = `3` | 3 | `{5, 5, 7, 8}` |
      | 2 | 8 | `end` (not begin) | `--it` = `8` | 8 | `{5, 5, 7}` |
      | 3 | 3 | first `>3` = `5` **which is begin** | print `-1` | -1 | `{5, 5, 7}` |

      Printed sequence: **`3`, `8`, `-1`** — exactly matching the sample. ✓

      Note for customer 3: the only affordable price `3` was already sold to
      customer 1, and the next cheapest ticket is `5`, which exceeds the cap
      `3`. Since `upper_bound(3)` points at begin, we output `-1` without ever
      dereferencing an invalid iterator.

The dynamic, deletable structure is what makes each customer O(log n).
