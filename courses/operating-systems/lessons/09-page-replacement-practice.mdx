      ### Page replacement — the three algorithms in one table

      When no frame is free, the OS evicts a **victim page** (writing it back
      first if dirty). Know the eviction rule and the classic numbers.

      | Algorithm | Evicts… | Classic string (7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1, 3 frames) | Belady's anomaly? |
      |---|---|---|---|
      | FIFO | the **oldest loaded** page | 15 faults | **yes** (non-stack algorithm) |
      | LRU | the **least-recently-used** page | 12 faults | no (stack algorithm) |
      | OPTIMAL | the page whose **next use is farthest** in the future | 9 faults | no |

      **Belady's anomaly in miniature** — string `1,2,3,4,1,2,5,1,2,3,4,5`:
      FIFO with 3 frames faults **9** times but with 4 frames faults **10** —
      *more* frames, *more* faults. LRU and OPTIMAL never do this: they are
      **stack algorithms** (the set of pages in k frames is always a subset of
      the set in k+1 frames).

      ### TLB — the translation cache

      - **TLB (translation lookaside buffer)** — a small, fast hardware cache
        of recent page-table entries: maps **page number → frame number**.
      - **TLB hit** — the translation is in the cache: address resolution in
        one cycle, no memory access for the page-table walk.
      - **TLB miss** — the translation is *not cached*: the hardware walks the
        page table (possibly multi-level) to find the frame. That is **not** a
        page fault — only if the PTE says the page is not resident do we fault.
      - **No dirty bit needed in the TLB?** The TLB caches *translations*; the
        **dirty bit lives in the page-table entry in memory** and is consulted
        at eviction time to decide write-back. A TLB entry is just a cached
        copy — if it's evicted, the mapping is re-read from the PTE anyway.

      **Use case:** on a context switch the TLB is flushed (or tagged), which
      is why thread-per-request servers with huge thread counts pay TLB-miss
      costs — and why pools (lesson 8) win.

      :::tip **Interview question: TLB hit vs miss vs page fault — three different things**
      "A TLB hit serves the page→frame mapping from the cache without touching
      memory. A TLB miss means the mapping isn't cached, so the hardware walks
      the page table — normal, and the entry is then cached. A page fault is
      different: the *page itself* isn't in physical memory, so the OS must
      swap it in from disk, which costs milliseconds — orders of magnitude
      more than a TLB miss."
      :::

    hints:
      - "Count a fault every time the referenced page is not resident — same counter as the FIFO exercise; only the eviction rule changes."
      - "LRU evicts the page whose most recent use is the oldest. Keep resident pages in recency order: every reference moves that page to the back (most recent)."
      - "Python: if page in memory: memory.remove(page); memory.append(page). else: faults += 1; if len(memory) == frames: memory.pop(0); memory.append(page)."
    solution: |
      def solve(reference: list[int], frames: int) -> int:
          memory = []  # recency order: front = least recently used
          faults = 0
          for page in reference:
              if page in memory:
                  memory.remove(page)  # re-referenced: move to most-recent end
                  memory.append(page)
              else:
                  faults += 1
                  if len(memory) == frames:
                      memory.pop(0)  # evict least recently used
                  memory.append(page)
          return faults
