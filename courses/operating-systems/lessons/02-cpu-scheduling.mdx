      ### CPU scheduling — the basics

      The scheduler picks the next process from the **ready queue** whenever the CPU is free. Key metrics:
      - **Turnaround time** = completion − arrival.
      - **Waiting time** = turnaround − burst (time spent only in the ready queue).
      - **Response time** = first response − arrival.

      ### FCFS — First Come First Served

      - Non-preemptive; the ready queue is a plain FIFO queue.
      - Simple and starvation-free, but suffers the **convoy effect**: one long CPU-bound process arrives first, and every short I/O-bound process waits behind it — the CPU stays busy while I/O devices sit idle.

      :::example
      Convoy effect: P1 (burst 10) arrives before P2 and P3 (burst 1 each). P2 and P3 sit in the queue for 10+ units even though they are tiny.
      :::

      ### SJF — Shortest Job First (non-preemptive)

      - Run the ready process with the **smallest burst** to completion.
      - When **all processes arrive at time 0**, SJF provably **minimizes average waiting time**: swapping a longer job ahead of a shorter one can never reduce the total waiting.

      ### SRTF — Shortest Remaining Time First (preemptive SJF)

      - On every arrival, preempt the current process if the newcomer has less **remaining** time.
      - Even better average waiting than SJF, but it needs to know burst lengths and can **starve** long processes.

      **Use case:** burst lengths are unknown in practice, so SJF/SRTF are benchmarks, not real schedulers — Linux CFS approximates 'shortest virtual run time first' with aging to stay fair.

      def solve(arrivals, bursts):
          n = len(arrivals)
          done = [False] * n
          time = 0
          total = 0
          completed = 0
          while completed < n:
              best = -1
              for i in range(n):
                  if not done[i] and arrivals[i] <= time:
                      if best == -1 or bursts[i] < bursts[best]:
                          best = i
              if best == -1:
                  time = min(arrivals[i] for i in range(n) if not done[i])
                  continue
              total += time - arrivals[best]
              time += bursts[best]
              done[best] = True
              completed += 1
          return total

      ### Round Robin (RR)

      - Preemptive, time-sliced: every process gets the CPU for at most one **quantum (q)**; on expiry it is preempted and re-queued at the tail.
      - Fair and starvation-free with good **response time** — the classic time-sharing algorithm.
      - Trade-off: small quantum → better response but more context switches (overhead); large quantum → fewer switches but response degrades. If q ≥ longest burst, RR degenerates to FCFS.

      **Use case:** interactive OSes (Linux, Windows, macOS) give the foreground a small time slice so typing and clicks always feel instant.

      ### Priority scheduling

      - Run the ready process with the **highest priority** (preemptive or non-preemptive variant).
      - Major flaw: **starvation** — low-priority processes may wait forever while higher-priority ones keep arriving.
      - Fix: **aging** — a waiting process's priority increases over time, so it eventually reaches the front of the queue.

      **Use case:** aging is exactly how real kernels keep interactive tasks responsive while long batch jobs still finish eventually.

      ### Multilevel Queue & Multilevel Feedback Queue (MLFQ)

      - **Multilevel Queue:** processes are partitioned into fixed classes (system, interactive, batch), each with its own queue and policy. Rigid — a process never changes class.
      - **MLFQ:** several priority queues — **RR in the top queues, FCFS at the bottom**. New processes enter the top queue; a process that exhausts its quantum is **demoted** one level. I/O-bound interactive jobs stay near the top; CPU hogs sink to the bottom. Aging prevents starvation.

      **Use case:** classic Unix schedulers (e.g. BSD) use MLFQ — interactive processes keep the top queue, long computations sink and run last.
