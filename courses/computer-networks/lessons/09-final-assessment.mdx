  - type: mcq
    prompt: "A router forwards packets based on IP addresses. At which OSI layer does it operate?"
    options: ["Physical (1)", "Data Link (2)", "Network (3)", "Transport (4)"]
    answer: 2
    explanation: "Routers make forwarding decisions on IP (logical) addresses → layer 3 (network). Switches use MAC addresses (layer 2), hubs just repeat bits (layer 1)."
  - type: mcq
    prompt: "During encapsulation, an HTTP request becomes a TCP segment, then an IP packet, then an Ethernet frame. Which layer adds the TCP header?"
    options: ["Application", "Transport", "Network", "Data Link"]
    answer: 1
    explanation: "Each layer adds its own header: transport adds the TCP header (segment), network adds the IP header (packet), data link adds the MAC header (frame). The application layer produces the original message."
  - type: mscq
    prompt: "Which statements about the OSI/TCP-IP models are true?"
    options: ["The TCP/IP application layer folds OSI layers 5–7 into one", "Switches forward frames using MAC addresses (layer 2)", "The PDU produced at the network layer is called a packet", "Hubs make forwarding decisions on IP addresses (layer 3)"]
    answer: [0, 1, 2]
    explanation: "TCP/IP merges OSI 5+6+7 into its application layer; switches are layer-2 (frames/MAC); the network layer produces packets. Hubs are layer 1 — they repeat bits and make no IP decisions, so option 3 is false."
  - type: mcq
    prompt: "How many Hamming check bits are needed to correct a single-bit error in 11 data bits?"
    options: ["3", "4", "5", "6"]
    answer: 1
    explanation: "Need 2^r ≥ n + r + 1 with n = 11. r = 3: 2^3 = 8 ≥ 11 + 3 + 1 = 15? No. r = 4: 2^4 = 16 ≥ 11 + 4 + 1 = 16? Yes (equal counts). → 4 check bits, codeword = 15 bits."
  - type: mcq
    prompt: "A 2 Mbps link transmits 2000-bit frames with a one-way propagation delay of 40 ms. What is the stop-and-wait utilization?"
    options: ["≈ 1.2%", "≈ 2.5%", "≈ 50%", "≈ 12%"]
    answer: 0
    explanation: "Tt = L/B = 2000 / 2,000,000 = 1 ms. U = Tt / (Tt + 2Tp) = 1 / (1 + 2×40) = 1/81 ≈ 0.0123 ≈ 1.2%. The link idles ~99% of the time — why stop-and-wait is only used on short, slow links."
  - type: mcq
    prompt: "Why does WiFi (CSMA/CA) avoid collisions instead of detecting them like Ethernet (CSMA/CD)?"
    options: ["A radio transceiver cannot listen while transmitting, so collisions are undetectable", "CSMA/CA is faster than CSMA/CD", "WiFi uses fiber, where collisions never happen", "Wired Ethernet cannot detect collisions either"]
    answer: 0
    explanation: "A radio cannot hear incoming signals while it is transmitting (its own signal drowns them out), so collision *detection* is impossible. WiFi therefore *avoids* collisions: listen-before-talk, RTS/CTS, random backoff. Ethernet senses voltage on the wire and can detect collisions."
  - type: mcq

  - type: mcq
    prompt: "OSPF is a link-state protocol using Dijkstra. RIP is a distance-vector protocol (Bellman-Ford) that suffers from…"
    options: ["count-to-infinity — slow convergence", "SYN flooding", "head-of-line blocking", "DNS amplification"]
    answer: 0
    explanation: "Distance-vector routers only know neighbours' distances, so a route failure propagates slowly and hop counts can increment toward infinity. Link-state (OSPF) floods the topology and converges fast. The other options are attack/transport concepts, not routing-protocol problems."
  - type: mcq
    prompt: "In the TCP 3-way handshake, the client sends SYN with seq = x. What does the server's SYN-ACK carry?"
    options: ["ack = x + 1 (the client's ISN plus one)", "ack = x (the client's ISN unchanged)", "ack = y + 1", "ack = 0"]
    answer: 0
    explanation: "The ACK field confirms the next byte expected: since the SYN consumes one sequence number, the server acknowledges with x + 1. The handshake: SYN(seq=x) → SYN-ACK(seq=y, ack=x+1) → ACK(ack=y+1)."
  - type: mcq
    prompt: "A TCP connection has a window of 64 KB and an RTT of 50 ms. What is the approximate maximum throughput?"
    options: ["≈ 10.5 Mbps", "≈ 5.24 Mbps", "≈ 21 Mbps", "≈ 1.05 Mbps"]
    answer: 0
    explanation: "Throughput = window / RTT. 64 KB = 65536 bytes × 8 = 524288 bits. 524288 bits / 0.05 s = 10,485,760 bps ≈ 10.5 Mbps. The ×8 bytes → bits conversion is the classic trap."
  - type: mcq

    explanation: "cwnd doubles every RTT: start 1 → RTT1: 2 → RTT2: 4 → RTT3: 8 → RTT4: 16 MSS. Slow start grows exponentially (1, 2, 4, 8, 16…) until ssthresh, then AIMD switches to linear growth."
  - type: mcq

      - **Recite the layers cold:** the 7 OSI layers, a one-line job for each, and the
        PDU at every layer (segment → packet → frame → bits).
      - **Numericals you must redo in 60 seconds:** Hamming check bits (2^r ≥ n+r+1),

      - **Protocol one-liners:** UDP 8-byte header vs TCP 20-byte; ports HTTP 80 /

      - **Security in one breath:** asymmetric key exchange → symmetric session key →
        certificates via CAs → TLS → defense against MITM; parameterized queries against
        SQLi; TLS 1.3 = 1-RTT handshake, 0-RTT resumption, mandatory ECDHE (forward
        secrecy).
      - **Newer topics:** ping proves L3 reachability only; traceroute maps hops via TTL
