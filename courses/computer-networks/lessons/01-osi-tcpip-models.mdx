      Networking is organized into **layers**. Each layer talks to its peer on the other
      machine and provides services to the layer above it. Two models matter:

      - **OSI (7 layers)** — a reference model; describes *what* each layer does.
      - **TCP/IP (4 layers)** — the model the real internet runs on; describes *how*.

      ## The 7 OSI layers (top → bottom)

      | Layer | Name | One-line job |
      |-------|------|--------------|
      | 7 | Application | User-facing protocols: HTTP, DNS, SMTP. |
      | 6 | Presentation | Encoding, encryption, compression (mostly absorbed into 7 today). |
      | 5 | Session | Establishes/manages dialogs between applications. |
      | 4 | Transport | End-to-end delivery: TCP (reliable) / UDP (fast). |
      | 3 | Network | Logical addressing (IP) + routing between networks. |
      | 2 | Data Link | Framing, MAC addressing, error control on one link. |
      | 1 | Physical | Bits on the wire: voltage, light, radio. |

      **Mnemonic** (top→bottom): *Please Do Not Throw Sausage Pizza Away* — or the
      reverse (bottom→top): *All People Seem To Need Data Processing*.

      ## TCP/IP 4-layer model vs OSI

      - **Application** ≈ OSI 5 + 6 + 7 (HTTP, DNS, SMTP, FTP, SSH).
      - **Transport** = OSI 4 (TCP, UDP — ports live here).
      - **Internet** = OSI 3 (IP, ICMP, ARP-adjacent).
      - **Link / Network Access** = OSI 1 + 2 (Ethernet, WiFi, framing).

      TCP/IP won because it was implemented first and shipped with the internet; OSI
      stayed mostly a paper standard.

      ## Encapsulation & decapsulation

      Each layer **adds a header** to the data from the layer above (encapsulation);
      the receiver **strips headers in reverse order** (decapsulation). The data unit
      gets a new name at each layer — the **PDU**:

      - Transport → **segment** (TCP) / **datagram** (UDP)
      - Network → **packet**
      - Data Link → **frame**
      - Physical → **bits**

      **Use case:** every packet on the wire is the result of encapsulation — your
      HTTP request becomes a segment, then a packet, then a frame, then bits; the
      server reverses the process.

      :::tip
      **Interview question:** Which device works at which layer — hub, switch, router?
      — A **hub** repeats bits: layer 1 (physical). A **switch** forwards **frames** by
      MAC address: layer 2 (data link). A **router** forwards **packets** by IP address:
      layer 3 (network). This is the single most-asked "device" question in CN interviews.
      :::

      :::tip
      **Interview question:** Why does TCP/IP matter more than OSI in practice?
      — OSI is a *reference* model used for teaching and reasoning about layers; TCP/IP
      is the *actual protocol suite* of the internet (HTTP over TCP over IP over
      Ethernet). Say: "OSI explains the layers, TCP/IP is what the internet speaks."
      :::
